# Workflow Action G3.1：协议一致性与静态引用安全

## 范围

G3.1 新增 `MyAvaloniaManagement.PluginSdk.Workflow 1.0.0`，提升 Core/UI SDK 到 `3.2.0`，但 Host 产品
继续为 `3.0.0`。原始候选范围不修改或发布 Build、Templates、Host 产品包和四个业务插件；SDK 发布后，
操作者另行明确扩大范围并发布 Templates `1.2.0`，详见
[Templates 1.2.0 发布补充记录](g3.1-template-1.2-publication.md)。外部 Workflow Studio 提升到 `1.1.0`，
manifest SDK 区间为 `[3.2.0, 4.0.0)`。

本阶段不使用 AIFLOW，不配置或运行 Windows CI、Windows Smoke、Host Release Acceptance 与 Host 产品
发布门禁。

## 共享协议与 Host

Workflow SDK 只公开 Schema Profile、结构化 Schema/实例校验、保守可赋值、静态/运行时共享路径解析与
Catalog 双 revision；不包含 Definition、Runner 或 UI 模型。字符串长度按 Unicode Rune，integer 限制为
Int64，number 必须能表示为 decimal。新增公共类型和安全算法使用中文 XML 注释，并启用 CS1591 与
PublicApiAnalyzers 基线门禁。

Host 的 Descriptor 注册、输入输出校验和目录 revision 已改用共享实现，原始异常不越过既有稳定失败码。
目录同时提供 ContractRevision 与 PresentationRevision；运行快照与授权指纹只依赖 ContractRevision。
Workflow 程序集加入默认 ALC 共享根，插件 ZIP 不携带该 DLL。

## 外部 Studio 协议

Studio v2 严格根字段为 schemaVersion、contractRevision、presentationRevision、summary 与 steps。v1、未知
字段、重复字段和混合版本直接拒绝。Contract 规范化忽略 description 并处理语义无序集合；Presentation
只跟踪 Action 名称、说明与 Schema description。

静态引用要求每个对象段 required，数组段为非负整数且由 minItems 保证；来源 Schema 全部合法值必须能
赋给目标 Argument Schema。Secret 用当前会话真实字符串验证。ForEach 来源必须是保证存在的有界数组，
其后续输出形状为 Action 输出数组。运行时引用失败转换为 WorkflowRunFailure，不伪造 invocation entry。

`MainDocument` 只承担 Document 生命周期、可观察状态、命令转发和结果映射；目录/编辑/Codec/验证由
WorkflowEditorCoordinator 负责，Secret/运行/取消/关闭清理由 WorkflowRunSession 负责。

## 验证与发布边界

平台专项覆盖 Rune、decimal、enum/范围/对象/数组可赋值、optional、数组 segment、双 revision 顺序无关性、
Host 双 revision 和默认 ALC。完整专项测试必须包含 SDK、Host Unit、Headless UI 与 Plugin 回归且无跳过。
Workflow SDK 与 Studio 行/分支覆盖率不低于 85%/75%，协议关键类行覆盖率不低于 90%。

发布顺序固定为 Core 3.2.0、UI 3.2.0、Workflow 1.0.0 与对应符号包，且只能上传门禁验证的同一批字节。
聊天中出现过的凭据视为暴露并禁止使用；必须换用短期最小范围 Token，通过临时环境传递并在完成后撤销。
预检发现版本已存在或任一上传失败时立即停止后续上传，不覆盖或重打同版本。发布后以全新 NuGet 缓存和
纯公开源重复 locked restore、Release build/test/package。
