# 工具中心使用说明

V7 将全部 Tool 的发现和显隐操作集中到 **工具 → 工具中心…**。欢迎页的“工具中心”按钮打开同一窗口。
窗口可以缩放，保持打开时仍能使用主工作区；重复打开会激活现有窗口，Esc 关闭。

## 找到与使用工具

- 左侧提供全部工具、常用工具、最近使用、已显示、已隐藏，以及用途分类。
- 搜索支持名称、用途说明、分类和稳定 ID；来源当前显示插件 ID，内建工具显示“内置”。
- 输入搜索词会查询全部已登记工具，右侧标题明确搜索范围；来源筛选继续生效，标题显示当前来源；“清除来源”只解除来源限制。
- 清空搜索恢复之前的导航选择；主动切换导航会清空搜索。
- 单击一行只选择；点击“显示”恢复工具，点击“定位”激活已有工具并展开自动收起区域。双击或在列表行按 Enter 执行主操作。
- 每行保留星标、显示／定位和“⋯”更多操作。更多菜单的“隐藏工具”移除该工具入口。
- 底部“整理工具 → 隐藏所有工具（整个工作区）”作用于全工作区，不受搜索、来源或分类限制。
- 工具标题栏 × 的提示和工具关闭菜单均为“隐藏工具”；页面标签 × 仍关闭页面。

隐藏不会销毁工具模型，也不会停止下载等后台任务。重新显示会复用同一实例与页面。
“自动收起”表示工具仍在 Dock 边缘可访问，属于“已显示”；“已隐藏”表示边缘入口也已移除。
插件暂不可用或页面创建失败时显示原因，并禁用打开；已有实例仍可以隐藏。

## 常用与最近

星标加入或移出常用，与工具当前是否显示无关。收藏不会自动打开工具，隐藏也不会取消收藏。
已收藏项的“⋯”菜单提供“常用上移”“常用下移”。
最近使用只记录成功的显示或定位，保留最近 20 个不同工具；浏览、搜索、收藏和隐藏不会新增最近记录。

卸载插件后，常用和最近中的历史项保留原名称并标为“插件缺失”；重新安装相同 Tool ID 后恢复关联。
不同 ID 的同名工具不会混为一项。

## 用途分类

预置资源导航、系统诊断、其他工具。外部工具默认在其他工具，不从插件名称推测分类。
通过“整理工具 → 管理用途分类…”可以新建、重命名或删除自定义分类；名称为 1–60 字符，不能与已有分类重名。
使用该工具行的“⋯ → 设置分类”选择分类。删除自定义分类后，关联工具回到其他工具，显隐状态保持。

## 启动与兼容

首次启动没有布局时，所有 Tool 默认隐藏。有效的已有布局继续恢复，旧布局之外新增的工具保持隐藏。
旧侧边“工具管理”和“插件状态”已移除，不再占用 Dock 标签；旧布局中的这两项会定向迁移，其余有效布局保留。
插件状态改从 **工具 → 插件状态…** 打开独立窗口，详见[插件状态使用说明](./plugin-status.md)。
这两个退役项的收藏、最近使用、分类分配与历史名称会定向清理，其他缺失插件的偏好保留。
所有 Tool 都能隐藏，包括旧 SDK 声明 `ToolCloseBehavior.Prevent` 的插件。此举只改变当前 Host 的显示政策，
没有删除 SDK 枚举、改变插件加载协议或卸载插件。

“文件 → 功能中心…”打开功能选择窗口。命令面板 `Ctrl+Shift+P` 可直接显示／定位工具，
并支持打开功能的新标签、切换已有页面与执行上下文命令，见[工作区搜索](./workbench-search.md)。

## 偏好与布局文件

默认数据根为 `%LOCALAPPDATA%/MyAvaloniaManagement/v2`；设置 `MYAVALONIA_DATA_DIRECTORY` 时使用该完整目录。

| 文件 | 保存内容 |
| --- | --- |
| `tool-center-v1.json` | 常用顺序、最近访问、自定义分类、工具分类关联、历史名称 |
| `layout-v2.json` | 停靠位置、比例、显隐、自动收起和活动工具 |
| `layout-v2.json.<GUID>.pre-tool-retirement.bak` | 内置 Tool 退役迁移前的原始布局，首次写回前保留 |

偏好文件损坏时保留 `.invalid.bak` 并使用默认设置；未知版本保留原文件，只在内存中接受本次修改。
写入失败会在窗口显示提示，当前修改仍可使用，但重启可能丢失。收藏文件不保存插件业务数据。
