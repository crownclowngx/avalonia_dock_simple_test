# V15 启动引导与进度契约

> 用途：说明已接入的启动行为、进度含义及线程和所有权边界。核对日期：2026-09-21。
> 实现与测试来源见[开发记录](../archive/records/host-v15/development-acceptance.md)和[专用验证](../maintenance/host-v15-startup-verification.md)。当前 Host 人工验收已[确认通过](../archive/records/host/manual-acceptance-20260921.md)，实际交付见[本机部署](../maintenance/local-deployment.md)。

## 用户可见行为

普通 Host 先显示约 520 × 380 DIP 的启动窗口，再执行插件组合。窗口包含原生矢量羽毛、当前阶段、插件标识、本阶段计数和最近三项状态。全局主题完成装配前，首屏跟随系统浅深主题；正式工作台沿用原有保存的主题设置。

羽毛以 2.4 秒为周期轻微浮动，位移不超过 3 DIP，摆动不超过正负 2 度。Windows 使用系统客户区动画偏好；环境变量 `MYAVALONIA_REDUCED_MOTION=1` 可明确关闭羽毛动画。进度信息不会因关闭动画而消失。成功不等待动画播完，取消或失败立即停止羽毛动画。

已知总数时，进度条表达本阶段已处理数，不表达成功插件数或剩余时间；失败也计为已处理，并明确标出失败。未知总数及空阶段不计算百分比。禁用插件不进入 DLL 加载，只显示跳过；没有生命周期声明的插件没有虚构的初始化步骤。

当前清单没有显示名称字段，因此使用稳定 PluginId，清单读取前使用目录名。长标识省略并提供完整提示。启动窗口只展示最近三项，失败摘要保留；完整诊断仍归日志和插件看板。可隔离的插件异常不会阻止其他插件启动，进入主窗口后显示诊断摘要及“查看插件看板”按钮。

## 唯一启动链

`Program` 首先识别 V14 重启助手。助手正常等待时不初始化本启动窗口；新 Host 按普通启动路径显示羽毛。普通启动的唯一路径为：轻量 App → Splash 首帧调度 → StartupCoordinator → StartupWorker / HostRuntime.CreateAsync → UI 线程 AttachWorkbench → 正式主窗口交接。

App 在启动时只加载 Fluent 基础主题和最小错误展示颜色。V19 将工作台命令目录改为纯描述，Runtime 在后台组合时完成最终身份合并校验。回到 UI 线程后，原 App 实例安装 App.axaml、ViewLocator 和容器唯一回收器；随后创建并校验显式 Host Handler 绑定、Workspace 和桌面 Shell。执行绑定仍早于主窗口显示，失败仍走启动失败和同一 Runtime 回滚；读取元数据不再连带创建工作区。

只建立一次 Avalonia Application 与桌面消息循环。启动阶段使用显式关闭，成功显示正式窗口后关闭 Splash 并恢复既有关闭模式。窗口显示后启动时序写出 `firstFrameMs` 和 `readyMs` 诊断值，起点为进程启动时间；它们仅用于观测，不构成启动成功证明或最低等待时长。

## 线程与资源边界

- 非 UI 启动使用专属后台线程；Windows 最初保持 STA，以保留旧入口模块构造和 Configure 的线程公寓特性。该线程没有 COM 消息泵，不能解释为对任意原生插件的兼容保证。
- 生命周期异步挂起后的执行仍遵守原有 `ConfigureAwait(false)`；插件顺序不变，不并发初始化。同步慢调用不占用 UI 线程，但协作取消不能强制中断不观察令牌的代码。
- 控件、工作区、主题和绑定在 UI 线程装配；该阶段同步构建仍可能造成短暂动画停顿，原生复杂插件的实际耗时需独立观察。
- 加载器依赖 `IStartupProgressSink`，不引用启动控件。缓冲拥有单调序号、最近三项和去重失败数；UI 每 80 毫秒拉取快照，不在加载线程运行 UI 观察者。
- 进度仅为观察，不改变插件可用性、超时或故障处置。成功、取消和失败后关闭缓冲，晚到消息不能访问已关闭窗口。
- Runtime 工厂交付前失败，使用 `InitializeAsync` 与原关闭链回滚；交付后取消仍将 Runtime 留给进程入口。Program 消费同一幂等关闭结果，保留 `ResourcesRetained`、Failures、日志释放和重启许可规则。

## 取消与失败

启动窗口关闭或系统关闭请求会提交一次协作取消，并显示“正在停止启动”。关闭被接受后不再交接主窗口；已经启动的任务须交还资源所有权。普通用户取消以非成功启动退出，不启动重启助手，不触发重试循环。

致命异常在同一个 Application 中显示最小 StartupFailureWindow，不再次启动 Avalonia App。原始阶段诊断优先，未知异常才补宿主启动兜底码。最小错误展示自身失败时结束桌面循环，由 Program 完成最终收尾。Avalonia 无法建立时保留进程级错误输出，不声称已经显示了错误窗口。

生命周期默认初始化 30 秒、关闭 10 秒、取消宽限 2 秒继续由既有协调器管理。超时不代表插件代码已经停止；仍在使用的 Provider 沿用保留机制。同步回调尚未返回 Task 时，异步等待期限无法强制中断它。

运行时、单文件解包及平台初始化发生在首屏之前，本功能不能覆盖这部分等待。SDK、manifest、用户数据格式和业务插件无需为进度显示升级；V15 不改变安装目录、发布资格或实际部署状态。
