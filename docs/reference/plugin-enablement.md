# 插件启用与禁用契约

> 状态：V13 已实现，重启 Host 生效。核对日期：2026-09-21。开发结果见[开发记录](../archive/records/host-v13/development-acceptance.md)及其 JSON 证据；Host 人工验收已由所有者[确认通过](../archive/records/host/manual-acceptance-20260921.md)，外部专有业务由对应仓库记录。

## 用户行为

在 **工具 → 插件看板… → 选择插件 → 概览 → 下次启动启用** 设置。点击成功即保存，无额外保存按钮。完整退出并重新启动 Host 才应用。运行中的文档、工具、工作流和生命周期继续遵循原协议；取消退出不会提前释放插件。

V14 提供看板“重启并应用更改…”和文件菜单“重新启动 Host…”，自动执行真实进程重启。它们共享一次请求，应用全部已保存设置。设置服务先冻结新写入/重读、等待已接受操作完成，再准备关闭；失败或取消恢复操作能力，已提交文件不回滚。冻结拒绝写入使用 `PLUGIN_ENABLEMENT_RESTART_PENDING`。详情见[自动重启契约](host-restart.md)，不改变本节的启动快照和加载规则。

| 本次启动设置 | 已保存的下次设置 | 展示 |
| --- | --- | --- |
| 启用 | 启用 | 显示真实加载/初始化结果，无待重启标记 |
| 启用 | 禁用 | 待禁用，重启后生效 |
| 禁用 | 禁用 | 已禁用、未加载，无待重启标记 |
| 禁用 | 启用 | 已禁用、待启用，重启后尝试加载 |

运行失败与禁用是不同事实。启用不保证兼容或初始化成功；配置未知不冒充用户禁用。正常禁用不计异常，清单或配置错误仍显示。已禁用项保留在列表，支持已禁用、待重启筛选和搜索。

## 配置与提交

使用 HostDataRootPolicy 选定的数据根：默认 `%LOCALAPPDATA%/MyAvaloniaManagement/v2`；`MYAVALONIA_DATA_DIRECTORY` 为完整覆盖根，不追加代际目录。文件为 `plugin-enablement-v1.json`：

```json
{
  "schemaVersion": 1,
  "disabledPluginIds": ["myavalonia.plugin.example"]
}
```

只保存禁用身份。新身份默认启用；按 SDK PluginId 精确规则比较、去重、排序。插件升级、目录改名不改变选择；暂时未安装的禁用身份仍保留。严格拒绝重复字段、未知字段、非法 ID、未知 schema、超过 1 MiB 或 10000 项的输入。

保存由服务串行执行：持有 `.lock` 独占文件句柄，重新读取并比较 SHA-256 修订，写入同目录临时文件并 Flush，再原子移动/替换主文件；替换时 `.bak` 保留上一版。成功提交后才发布内存意图，提交点之后不再执行会把成功误报为失败的文件操作。持锁失败或写失败返回受控错误；临时文件删除失败只记固定诊断，不覆盖原结果。锁文件残留不代表仍被占用。

锁保护遵循本协议的 Host 实例；外部编辑会在提交前修订核对时被发现，不承诺与不遵循锁协议的任意编辑器构成跨进程事务。冲突时保留旧选择，用户点击“重新读取设置”后针对最新意图再次操作。普通刷新只读内存，不自动读取外部修改。

## 错误与恢复

| 情况 | 处理 |
| --- | --- |
| 主文件和备份都不存在 | 首次默认全启用，读取不创建配置 |
| 主文件无效或缺失，有有效备份 | 按备份决定本次加载；明确恢复提示，配置只读，原件保留 |
| 无可靠配置或读取失败 | 本次不加载插件；Host 管理窗口仍可用，禁止开关写入 |
| 主文件为未知 schema | 保留文件，不使用旧备份，也不重写未来格式 |
| 保存失败或冲突 | 开关恢复到已确认的意图，明确提示未保存；本次运行集合不变 |

恢复时先退出使用该数据根的所有 Host，保存主文件和备份原件，再按用户确认的选择修复 schema 1 文件，重新启动并核对。删除主文件和备份会恢复默认全启用，不能当作自动修复。界面不提供通用编辑器或一键重置。

## 启动与职责边界

HostRuntime 读取配置并注入发现和意图服务。发现先读取全部清单并检查重复 PluginId；身份歧义仍终止启动，包括被禁用身份。随后在 SDK/文件布局预检、ALC 和 DLL 加载之前过滤禁用项；因此禁用项没有模块构造、Configure、Provider、贡献或生命周期回调。损坏清单保留原诊断，不通过目录名制造可操作身份。

发现缓存按规范化插件根和数据根区分，保存同一进程的第一份启动快照；设置摘要不作缓存键。运行中保存、重读或重开窗口均不会调用发现。不可变候选记录只持有目录和清单，使未加载项仍可展示。

存储负责文件；PluginEnablementService 负责已保存意图；发现负责启动事实；PluginStatusQuery 只组合 Registry、可用性、诊断、候选及意图；ViewModel 通过窄端口组织交互。没有通用插件状态机或热加载框架。窗口关闭不取消已接受的设置保存，迟到回调不再访问已释放窗口；文件检查任务仍遵循原取消协议。

## 与 ZIP 安装的关系

V23 [安装会话](plugin-installation.md)在插件发现前应用或恢复文件，不修改启用设置。禁用插件可更新，其安装结果只标记文件已就位、尚未运行验证；启用配置不可读时不能把未加载误记为正常禁用确认。不同数据根共享同一安装根的文件租约，各自启用选择保持独立。

## 关联数据与兼容

禁用后贡献从下一次启动的 Document/Tool/Command/Placement/Icon/Workflow Action 目录中消失。工作流引用返回既有 `WORKFLOW_ACTION_NOT_FOUND`，不删定义、不自动启用。原有缺失工具布局、显示意图、收藏和最近记录保留；重新启用沿用原恢复逻辑。Document 不新增跨启动自动恢复功能，用户业务文件不删除。

未加载候选的“检查安装产物”只读磁盘与 PE，明确显示“本次未加载”；历史报告不能覆盖禁用事实，也不能表示当前插件已运行。SDK public API、manifest V2、Document V2、Layout V3 和包版本均不因 V13 改变。V13 是改造序号，不是发布版本。

验证矩阵与重跑命令见[专用开发验证](../maintenance/host-v13-plugin-enablement-verification.md)。本轮仅使用本地开发测试和 verify，不使用 AIFLOW、Windows CI 或发布门禁。
