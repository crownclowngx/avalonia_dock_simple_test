# Host 自动重启契约

> 状态：V14 实现已接入；最终开发判定与产物身份见 [JSON 证据](../archive/records/host-v14/final-development-evidence.json)。日期：2026-09-19。V14 是改造序号，不改变产品、SDK 或持久化 schema 版本。

## 用户行为

**文件 → 重新启动 Host…** 可在没有插件设置变化时使用，也可在命令面板搜索。插件看板存在已保存的待重启设置时显示 **重启并应用更改…**；它应用全部已保存设置，搜索、筛选与选中项不缩小范围。两个入口共用一次请求；没有新增快捷键。

接受请求后显示“正在准备重启…”，暂缓新的插件设置写入及重读，等待此前已接受的操作完成，再复用整窗关闭协议：处理所有窗口中的文档保存/放弃/取消、排空命令、复查修订并保存最终布局。文档确认沿用正常用户交互，不强制超时通过。设置冻结在服务层执行，看板关闭不会取消已接受的文件提交。

任一保存或布局失败、用户取消、助手准备失败、最终原生 Closing 拒绝，均撤销准备和助手连接，恢复原工作区及设置入口。已经成功保存的文件不会回滚。最终主窗口关闭以后不承诺恢复原实例。

新 Host 是独立进程，重新读取有效启动设置，沿用工具布局、显隐、收藏和偏好的既有恢复规则。上次打开的 Document 不自动重开；启动仍会创建默认欢迎页。业务文件不删除，后台任务按原生命周期收尾，不承诺跨进程续跑。无重启请求的普通退出不创建助手。

## 职责与所有权

| 对象 | 职责与所有者 |
| --- | --- |
| `IHostRestartActions` / `HostRestartCoordinator` | UI 线程的单次请求、忙碌与失败状态；主菜单和看板只获得此窄端口 |
| `IPluginEnablementRestartBarrier` | 设置服务拥有准入与排空；取消释放冻结许可，最终关闭后保持冻结直至进程退出 |
| `MainWindow` / 现有工作区与布局对象 | 拥有原生关闭、文档许可和最终布局；用关闭代次阻止已撤销请求的迟到继续执行 |
| `HostLaunchSpecification` | 不可变启动描述；集中处理 apphost 与 dotnet DLL，无进程所有权 |
| `RestartHandoffSession` | Program 独占并以借用实例注入 DI；寿命长于 Runtime，不捕获 View 或已释放 Provider |
| `RestartHelperRunner` | 验证本次旧进程与会话，等待退出，至多启动一次；等待/启动副作用通过窄委托验证 |
| `HostRuntime.Shutdown` / `Program.Run` | 复用既有资源释放顺序，检查结构化结果和诊断关闭，确定最终许可及退出码 |

Workbench 重启 Handler 只在 UI Dispatcher 的 Background 优先级安排请求并返回；自身命令租约先结束，关闭准备才进入命令排空，避免等待自己。沿用普通类、少量窄接口和明确所有权，不引入状态机库或通用 IPC 框架。

## 一次性交接

正常启动与内部 `--host-restart-helper-v1` 模式在 Program 最前方分流；未知助手版本不能回退成普通 Host。助手的成功路径不创建 HostRuntime、插件、布局锁、正常日志或 Avalonia 主应用。

1. 旧 Host 验证启动描述，冻结设置，完成文档与布局准备。
2. 每次请求创建当前用户限定的双向命名管道和随机 GUID 身份；助手在 Ready 前取得旧进程系统句柄并核对 PID、启动时间，拒绝自身或不匹配身份。
3. 固定 32 字节身份验证后交换单字节 Ready；它只证明助手已准备好。
4. 最终关窗否决以关闭通道表示 Abort，没有磁盘重启意图。重启后的普通启动也不会扫描任何历史指令。
5. 主窗口及浮窗关闭、桌面循环返回后，Program 调用既有 Shutdown。仅正常返回、`ResourcesRetained == false`、`Failures.Count == 0` 且诊断释放没有新增错误，才发送 CleanExit；否则发送 Failed。
6. 助手确认最终结果。旧进程继续退出，不等待新 Host；助手同时取得 CleanExit 和所持有旧进程的实际退出码 0 后，才创建一次新进程。

消息值为 Ready=1、CleanExit=2、Failed=3。身份与消息固定长度，不解析任意 JSON/命令。身份采用固定时间比较。设置排空、连接/Ready、最终结果确认分别最多 15 秒；助手 Ready 后等待最终许可和实际退出共最多 90 秒。测试用取消令牌及明确完成信号验证超时语义，不以固定 sleep 推断退出。新进程创建成功不等同于初始化成功，初始化仍走原启动链。

## 启动形式与环境

apphost 使用当前 `Environment.ProcessPath`；`dotnet Host.dll` 保留 dotnet 可执行路径及实际入口 DLL。单文件按可执行路径处理，不依赖 `Assembly.Location`；真实单文件样本尚未验证。`dotnet run` 只按最终进程形态重建，不重新执行构建命令。

保留工作目录、逐项复制的原始用户参数、有效数据根，以 `ProcessStartInfo.ArgumentList` 启动，`UseShellExecute=false`；中文、空格、引号和 shell 元字符不参与命令拼接。显式设置 `MYAVALONIA_DATA_DIRECTORY`，其余环境继承，清除以 `MYAVALONIA_` 开头且含 `TEST` 或 `PROBE` 的一次性测试变量。助手参数只进入助手，不传给普通后继 Host。启动信息验证先检查可执行文件、入口 DLL 和目录存在性；操作系统执行权限或随后文件变化仍由真实创建失败路径处理。

不支持任意目标程序、在线更新、安装文件替换、进程内重新创建 App/Runtime 或崩溃守护。插件/设置被其他实例更改时，新 Host 读取实际启动时的有效磁盘状态，本协议不是跨进程配置事务。

## 失败与诊断

| 阶段 | 结果 |
| --- | --- |
| 启动描述、设置、文档、布局或助手 Ready 失败 | 原窗口保持打开，中文提示；取消后可再次操作 |
| 无最终许可就退出、断开连接或被强杀 | 不创建后继进程，助手结束本次等待 |
| 已关窗后资源保留、清理失败或退出码非零 | 不创建后继进程，不能重建原会话 |
| 最终许可后进程迟迟不退出、协议错误或新进程创建失败 | 助手显示独立中文错误，不强杀旧进程、不自动重试 |
| 新 Host 初始化失败 | 使用既有启动失败界面，无再次重启循环 |

助手错误界面只在失败时初始化最小 Avalonia 应用；错误窗口可由用户关闭，不承担自动重试。诊断写入数据根 `diagnostics/restart-<随机编号>.log`，仅固定错误码与异常类型，不写会话令牌、用户参数或异常正文。无法写日志时仍尝试显示错误界面。原 Host 的具体资源清理原因保留在既有诊断中。

操作步骤见[重启指南](../quick-start/restart-host.md)，测试层级、桌面与单文件边界见[专用验证](../maintenance/host-v14-automatic-restart-verification.md)。
