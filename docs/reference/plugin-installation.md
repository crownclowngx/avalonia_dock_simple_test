## 包协议与检查级别

直接消费现有 Plugin.Build 1.1.3 / 3.4.1 的输出：ZIP 内只有 `Controls/<PluginFolder>/` 一个载荷，根目录包含严格 schema 2 的 `plugin.manifest.json`、入口 DLL 和同名 `.deps.json`。插件身份来自清单，不从 ZIP 名称推测。PDB 和 `plugin.build.json` 对安装可选；正式打包仍执行原 Build 规则。

相邻同名 `.manifest.json` 自动参与检查，用户也可另选配套清单。有清单时要求 schema 2 的全部既有字段，ID、版本、入口、SDK、目录一致，`runtimeIdentifier=win-x64`、`targetFramework=net10.0`；ZIP 长度/SHA256、完整文件集合及每份长度/SHA256 均须相符。`archive.file` 只记录原发布名，因此改名 ZIP 可显式配对原清单。

没有清单时显示“基础检查通过；未进行发布摘要对照，也未提供独立 RID 声明”。清单损坏、不匹配、路径被目录占用或不可读都会拒绝，不自动降低检查级别。用户可明确点击“仅 ZIP 重新检查”生成新的预览。摘要一致不是作者签名，不能据此推定来源可信或业务兼容。

预检不创建 ALC、不调用入口构造、Configure 或生命周期。检查 SDK 范围、入口托管程序集及版本、deps 基本结构、全部 DLL 的 PE 架构和 RuntimeProfile 禁带资产，保留私有图标精确例外。明确异平台原生资产拒绝，静态检查不保证所有私有依赖都能解析；真实加载结果由启动链判断。

| 限制 | 值与处理 |
| --- | --- |
| ZIP / 解包字节 | 2 GiB / 4 GiB；流式统计实际解压量 |
| 条目 / 载荷层级 | 20000（含目录）/ 32 |
| 运行清单 / 配套清单 / deps | 64 KiB / 16 MiB / 16 MiB |
| 路径 | 安全单段不超过 180 字符，规范相对路径不超过 2048 字符 |
| 不允许 | 根外路径、绝对路径、ADS、设备名、尾点/空格、重复路径、文件目录冲突、链接、嵌套或多份运行清单、多插件包 |

输入先复制到专属暂存根，后续操作使用快照。提交及应用重新校验载荷和 ZIP 摘要；原用户文件后续改动不改变已检查候选。所有写入路径和祖先重复检查 reparse point。该边界保护安装器处理不可信包；它不是抵御同权限恶意进程持续替换路径的操作系统沙箱。

## 决策与数据边界

按 PluginId 盘点全部现有插件目录，包含禁用及加载失败项。ID 相同始终更新原目录；新 ID 遇到目录占用、重复 ID、坏清单或登记与磁盘不一致时拒绝。版本按数字比较。

| 候选 | 行为 |
| --- | --- |
| 未安装 / 版本更高 | 安装 / 更新，预览后确认 |
| 同版同摘要 | 已安装相同内容，不产生待办 |
| 同版不同摘要 / 更低版本 | 重装 / 降级，需要额外勾选明确确认 |
| 恢复上一版本 | 验证登记引用的备份身份、完整摘要及 SDK，生成预览并要求明确确认 |

首次更新人工部署目录会保留完整旧目录；原 ZIP 摘要未知时不伪造。旧目录附加文件随备份保存，不混入新目录。启用偏好、布局、报告和数据根不被安装器修改。插件自行写在载荷目录里的数据不会自动迁移；其改动会触发基线冲突。业务数据库迁移与文件恢复是独立责任。

看板原列表显示本次运行事实；安装面板显示磁盘基线、候选和待应用版本。安装成功不覆盖插件可用性或兼容报告结论。只有启用且成功注册、生命周期就绪的插件才记录 `startupConfirmed`；禁用插件记为 `installedDisabled`，没有执行代码。

## 存储、租约与恢复

```text
Host/
├─ Controls/<PluginFolder>/
└─ .plugin-management/
   ├─ installed-v1.json             安装登记与上一版引用
   ├─ operation-v1.json             最近操作，至多一个未完成
   ├─ runtime.lock                 进程寿命共享使用 / 启动前独占修改
   ├─ operations.lock              短时元数据串行锁
   ├─ staging/<operationId>/        package.zip、可选清单、payload 或 failed-payload
   └─ backups/<operationId>/        完整旧目录
```

备份直接按全局唯一操作 ID 存储，身份和旧登记保存在日志中；不再重复一层 PluginId。非 `Controls` 的自定义发现根在管理根名称后附路径摘要；管理根不属于插件发现范围。不同数据根不能绕过同一插件根的租约，大小写同一路径共享归属，文件系统链接不接受。

登记最多 4 MiB / 1000 项，日志最多 1 MiB。严格拒绝缺失、未知或重复字段、未来 schema、无效版本及路径。写入采用同目录临时文件、Flush 和原子替换，保留 `.previous`。主文件缺失但历史文件存在时不默认为空。多份文件不是一个原子事务，最终日志才是成功提交标志。

锁顺序固定为 runtime → operations；当前会话仅准备待办，可单独取得 operations，不等待 runtime。所有 V23 Windows Host 在发现前持有共享运行租约，交由 ProcessExit 释放，即使 Runtime 已释放也继续保护原生线程或延迟加载。不会在活跃会话里把共享锁升级为独占锁。

安装根首次使用需要创建管理目录及租约文件。已建立的只读锁文件可通过读权限取得共享租约；无法建立可靠租约则停止该根加载，不隐式提权或换根。旧 Host 不参与此协议，首次切换前须退出旧实例。外部占用或改动导致受控失败，不强杀其他程序。

| 持久阶段 | 后续行为 |
| --- | --- |
| Staged | 当前文件不变；可取消，下次独占启动复核后应用 |
| Applying | 已先写恢复意图，旧目录移到备份，再把完整候选移到目标；普通取消不再介入 |
| AwaitingStartup | 目录就位；日志记录 PID + 进程启动时间，只有该进程可试运行 |
| Committed | 主窗口已交接，目标运行或禁用事实确认，先写登记再写最终成功日志 |
| RecoveryRequired | 新版未确认；当前进程只记录，下次独占启动恢复 |
| RolledBack / Cancelled | 已恢复安装前文件与登记 / 已取消且未应用；不再次自动执行 |

其他实例占用时不应用 Staged，保留待办并允许旧版运行；试启动/恢复期间其他实例不能加载未确认版本。独占转共享后重新读取日志，不能依据竞争前快照执行插件。

目录移动或日志提交中断时，结合前后摘要、备份和旧登记恢复。新装失败撤除本次载荷，旧版更新失败恢复原完整目录；失败载荷保留在自身暂存根。未知内容或损坏备份不覆盖，保留现场并由现有启动失败界面提供诊断。已加载插件失败或进程中断后不会在同进程换回 DLL，也不循环重启。

“取消待应用安装”先写 Cancelled 再删除自有暂存；清理失败仍保持已取消。未提交预览在下次检查或 Host 收尾时清理；关闭看板不取消服务已接受的提交。V23 保守保留已完成操作的 ZIP、失败现场和历史备份，暂未自动裁剪。磁盘维护必须在所有 Host 退出后进行，不能删除当前登记引用的备份、未完成操作或租约文件来强行解锁。

## 启动与朴素职责划分

`Program` 在发现之前创建 `PluginInstallationSession` 并完成应用或恢复。原 `HostRuntime`、生命周期和主窗口负责真实启动；窗口交接后确认安装。重启准备同时冻结设置与安装准入，取消后恢复；普通退出后手动启动也会应用待办。助手只等待退出和启动继任者，仍不接收安装命令。

| 实现 | 责任与依赖 |
| --- | --- |
| `PluginPackageInspector` / `PluginPayloadValidator` / `PluginReleaseManifest` | 快照、受限解包、无执行校验；复用原清单、兼容性和指纹规则 |
| `PluginInstallPlanner` | 纯身份、版本和目标规则，不依赖 UI 或 IO |
| `PluginInstallationStore` / `IPluginInstallFileCommit` | 严格记录和实际提交；窄端口供真实文件步骤故障注入 |
| `PluginInstallationService` | 用例、后台任务、预览和提交所有权；复用既有准入/排空机制 |
| `PluginInstallApplier` / `PluginInstallationSession` / `PluginInstallationLease` | 文件替换与幂等恢复、进程入口接线、租约 |
| View / ViewModel | 平台文件选择、展示与意图；仅使用窄安装操作和重启端口 |

SRP 划开变化原因，DIP/ISP 位于真实 IO 和 UI 边界，普通纯规则不为形式统一增加接口；测试端口保持真实提交语义。未来下载可产生本地 ZIP 复用该入口，当前不建来源策略、状态机框架、事件总线或第二套容器。关键所有权、取消和恢复代码有中文设计注释。
