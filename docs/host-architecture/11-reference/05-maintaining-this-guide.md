[返回文档总览](../README.md)

## 文档定位

本组文档是 Host 当前实现的学习与源码导读，按全景、模块、机制、代码四层组织。现有 docs/reference 仍是协议和外部行为的权威说明；旧 Host 架构原文保留固定路径，供应用帮助与既有链接使用。

与[全仓文档规则](../../maintenance/documentation.md)一致：实现、自动验证、人工验收、部署和公开发布分别记录。发现文档与源码不一致时，以源码、测试和现行契约交叉核对，不从旧计划推断实现。

## 建设顺序与阅读顺序

| 阶段 | 产物 | 完成标准 |
| --- | --- | --- |
| 1 | 全景、核心概念、模块地图和源码地图 | 不读具体类即可解释 Host 职责 |
| 2 | 运行时、插件和 Workspace | 说明声明如何变成可用实例 |
| 3 | Document 与 Dock/Layout | 说明创建、提交、关闭、释放及回滚 |
| 4 | Command、Workflow、Presentation、支撑能力 | 说明交互入口与跨边界治理 |
| 5 | 八个跨模块场景、术语和索引 | 可从用户动作一路找到关键方法 |
| 6 | 链接、图示、嵌入与回归检查 | 文档可导航且帮助资源可读取 |

模块正文已经按此顺序展开；这张表用于解释组织和后续扩展原则，不将文档建设阶段等同于产品开发版本。

## 单篇文章的写作要求

先说场景和概念，再画局部结构或时序，最后解释关键方法、状态和失败分支。详细程度以读者能够定位代码并判断修改影响为目标。无需给每个简单属性单独建文档，也不要大段复制实现让两份代码同时维护。

源码片段标明是原文还是简化伪代码。本文现有短片段来自对应方法，链接到文件并以方法名导航，避免固定行号漂移。代码改动后同步复核片段。

## 图的约定

结构图表达职责或依赖，时序图表达一次操作，状态图表达阶段转换，所有权图表达创建与释放。图注说明省略范围，箭头标明用途。全景图不堆内部类，局部图不引入与当前机制无关的框。

Mermaid 保留在 Markdown 源内，名称与正文一致。改图后进行实际语法和渲染检查，类图里的结果消费箭头不要被解释为不存在的构造依赖。

## 导航和帮助

每篇保留返回模块和总览链接；模块 README 列出全部机制页；跨模块流程链接回权威机制。新增文件在总目录加入入口，使用仓库相对链接。

Host 工程会嵌入本组 Markdown。修改后构建并检查资源文本与渲染，保持八个固定帮助章节及旧架构原文路径。源码链接服务仓库阅读，安装版帮助不随文档附带全部 C# 源码。

链接校验区分两类：根 docs、Host 内部 docs 与根 README 的链接需验证帮助解析；SDK 包、Packaging、patches 的 README 和代码链接需验证仓库文件存在，并明确其仓库阅读边界。

## 变更后怎么验证

检查新增与修改 Markdown 的文件链接、锚点和代码围栏；核对图示可解析及可渲染；检查 git diff --check；按影响运行帮助内容与窗口回归。不要为文档变化修改业务逻辑、版本号或发布基线。

带日期的执行证据放在 docs/archive/records/documentation，避免在日常导航里固化某次测试数量或产物身份。源码与测试链接是验证入口，不是测试执行声明。
