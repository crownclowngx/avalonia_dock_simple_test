## 1. 问题与目标

用户反馈两个连续工作场景中的问题：

1. 将 Document 浮动后，关闭最后一个文档，原位置留下黑框或空窗口。
2. 在浮动窗口按 `Ctrl+Shift+P` 并选择功能创建入口，新文档仍进入主窗口。

浮动窗口已经承载用户当前工作，命令面板也在该窗口显示，因此新文档应落在发起操作的工作台窗口，并进一步定位到该窗口的活动文档分组。关闭最后一项可见业务内容后，浮窗应完成原生窗口和 Dock 模型的收尾；若用户取消关闭，则保留原来的内容和窗口。

两个问题分别涉及关闭生命周期和新建位置解析，应分开设计、分阶段验证，共享既有工作区所有权与窗口上下文。

### 1.1 首要约束

- **SOLID 是首要规定。** 按单一变化原因分配职责，显式传递本次操作的目标；新增边界必须有实际职责或副作用隔离依据。
- 设计模式朴素使用，优先复用既有适配器、关闭协调器、作用域许可和普通不可变记录，不建立通用窗口管理框架、事件总线、策略注册平台、状态机库或第二套 DI 容器。
- 核心代码使用详细中文注释，解释设计思路、事件顺序、UI 线程要求、目标有效期、取消与回滚、资源所有权，而不是逐句翻译代码。
- 单元、插件集成、Headless UI、既有回归和本地开发门禁必须齐全；黑框和焦点的原生桌面体验单独验收。
- 实施时同步现行文档和本专项文档，结果与证据分别记载，不把计划改写成未经验证的完成记录。
- **不使用 AIFLOW**，不读取或维护其上下文、任务记录和候选更新。
- **不使用 Windows CI 或发布门禁。** V16 开发阶段不执行 `seal`、发布 Smoke、发布覆盖率或重复性门禁；发布阶段再按当次发布要求执行，不删除、绕过或降低既有条件。
- 安装目录部署、包发布、版本升级和 CI 配置修改均不属于本方案交付；实施阶段只运行本地开发验证。

## 3. 目标交互规则

### 3.1 新建文档的位置

| 场景 | V16 目标行为 |
| --- | --- |
| 主窗口命令面板中选择功能创建入口 | 加入主窗口的活动文档组，不固定回最初的中心组 |
| 文档浮窗命令面板中选择功能创建入口 | 加入该浮窗的活动文档组 |
| 同窗口存在多个文档分组 | 优先使用执行动作前的活动文档组；面板搜索框的焦点不覆盖这一选择 |
| 焦点在同一窗口的 Tool 上 | 使用该窗口最近活动且仍有效的文档组；没有有效记录时按稳定布局顺序选取可接收文档的组 |
| 来源是纯工具浮窗，没有文档组 | 回退到主窗口的活动或默认文档组，不自动为工具浮窗插入新的文档区 |
| 保存对话框、功能中心、帮助等辅助 TopLevel | 不成为文档插入容器；本次来源只能是已登记的工作台窗口 |
| 选择搜索结果中的已打开页面 | 定位原页面并激活实际承载窗口，不创建副本、不迁移页面 |
| 选择 Tool 或普通 Command 搜索结果 | 沿用各自已有用例，不因新建位置规则而搬动工具或改写命令目标 |

“当前窗口”指本次操作的发起工作台窗口，不是异步完成时碰巧处于活动状态的窗口。选择文档组也只查询该窗口局部树，不能把其他浮窗中的全局活动文档当成来源窗口的活动组。

纯工具浮窗回退主窗口是本方案的明确产品取舍：本次只解决已有文档工作区的就地新建。若以后需要把工具浮窗扩展成文档工作区，应另行定义布局插入规则。

### 3.2 关闭行为

| 场景 | V16 目标行为 |
| --- | --- |
| 关闭纯文档浮窗的最后一个 Document | 先确认与排空，获准后关闭原生窗口、移除窗口模型，并释放该文档 |
| 文档组为空，但同浮窗另有文档组或 Tool | 只清理允许折叠的空组，保留承载其他内容的窗口 |
| 主窗口关闭最后一个 Document | 保留主窗口和主文档骨架，仍可继续新建 |
| 未保存文档选择取消、保存失败或保存后仍有修改 | 保留原文档、View、Scope、窗口及可用命令状态 |
| 原生 Closing 或 Dock 关闭能力拒绝 | 不先拆内容、不留下失去模型引用的原生空壳 |
| 直接关闭包含多文档或混合内容的浮窗 | 沿用既有整窗范围确认；Document 最终释放，Tool 仅隐藏并保留实例及恢复依据 |
| 拖回、合并或重置布局导致原浮窗为空 | 沿用布局转移协议，不把转移误判为关闭文档；补关联回归 |

最后一项以浮窗完整可见业务内容为依据，统计 `Document` 和 `Tool`，不能只判断当前分组的标签数。分隔条和布局容器不是业务内容；隐藏工具按现有恢复记录处理，不要求保留一个可见空窗。

## 4. SOLID 与最小职责设计

| 原则 | 本次落实方式 |
| --- | --- |
| S：单一职责 | 视图提供输入来源；窗口上下文维护窗口身份；目标解析负责选组；Workspace 发布并拥有文档；关闭协调器准备许可；Factory 适配 Dock 协议 |
| O：开闭原则 | 使用明确的 Host 内部新建目标与现有用例扩展点；不按插件名称、文档类型或视图类型增加分支，不建立不必要的通用插件扩展协议 |
| L：里氏替换 | Factory override 保留关闭能力、可取消事件、基类事件顺序及所有权契约；不能因转入整窗关闭就跳过文档拒绝或 Tool 隐藏规则 |
| I：接口隔离 | 只暴露捕获目标、校验目标、提交发布所需的窄能力；普通记录或方法足够时不强制一类一接口，不暴露整个窗口注册表或服务容器 |
| D：依赖倒置 | 用例接收内部目标数据及必要的窄协作者，不查全局活动 Window、不在领域/SDK 中依赖 Avalonia 控件；调度与原生事件留在展示/适配边界 |

实际职责分配如下；目标解析由具体 `DocumentCreationTargetResolver` 实现，不额外建立单实现接口：

| 对象或边界 | 负责 | 不负责 |
| --- | --- | --- |
| `WorkbenchWindowInteraction` / `CommandPaletteView` | 保留面板来源窗口及打开前的分组线索，执行新建时捕获一次目标 | 创建文档 Scope、遍历整个工作区决定业务寿命 |
| `WorkbenchWindowContext` | 验证工作台窗口身份，提供来源窗口或明确 Owner | 把所有对话框和业务命令的目标统一改成一个全局可变字段 |
| 内部 `DocumentCreationTarget` 及窄解析逻辑 | 表达来源窗口身份与候选文档组，按确定规则捕获及发布前重验 | 持久化窗口引用、拥有窗口或文档、创建第二套布局树 |
| `DocumentPersistenceCoordinator` | 透传本次目标，保留串行门、初始化错误和结果语义 | 从 Avalonia 焦点重推目标、自行修改 Dock 集合 |
| `WorkspaceSession` | 校验仍可接受创建，选定最终组，提交并回滚文档，发布实际结果 | 承担原生按钮事件、确认框绘制、窗口 Close 重入管理 |
| `HostDockFactory` / `HostFloatingWindow` | 识别最后文档入口，适配原生关闭和 Dock 清理，约束重入与重复事件 | 拥有或提前 Dispose 插件文档、吞掉可取消关闭 |
| 既有关闭协调器 | 确认、保存、命令排空、一次性许可、范围变化和迟到完成防护 | 再建一套保存服务或把取消后的窗口强制销毁 |

窗口引用如确需用于内部适配，只能由本次短期请求借用；Workspace 接收的目标不应是 Avalonia `TopLevel` 本身。优先使用现有运行时模型身份，不为本次需求引入持久化窗口 ID 格式。窗口/组记录在移除、关闭或 Runtime 结束时撤销，不能形成长期持有已释放对象的新缓存。

## 5. 最后一个 Document 的关闭顺序

1. 在 Document 尚附着于布局时，识别其是否为该浮窗最后一项可见业务内容，检查关闭能力和 `CanCloseLastDockable` 等框架约束；主窗口和仍有其他内容的浮窗沿原路径处理。
2. 对需要连同外壳关闭的情况，先进入已有原生窗口关闭协议，让既有协调器完成保存选择及命令排空；首次同步否决只表示等待，不得提前调用 `RemoveDockable`、解除窗口引用或释放文档。
3. 确认期间复用原有内容集合校验。窗口已移除、内容变化、应用关闭冲突或旧请求迟到时撤销本轮许可，不盲目关闭新内容。
4. 重试进入最终可取消关闭时，文档能力和 Dock 可取消事件必须在内容拆除前得到有效判定。需要跨阶段保留许可时，只保存本轮、一次性的信息，不能永久跳过后续关闭检查。
5. 只有原生关闭获准后才按框架协议清理内容、注销 HostWindow 和 DockWindow，并交由 Session 释放 Document。原生最终清理期间设置明确的重入边界，避免再次把同一个文档转接成新的窗口关闭请求。
6. 取消、异常和成功路径均撤销未消费许可与等待状态；关闭观察者、布局保存或迟到任务不能让已关闭文档被再次释放，也不能让保留文档永久处于 closing 状态。

不能简单把 `TryCloseLastToolWindow` 的类型判断扩大为 `ITool or IDocument` 就视为修复完成：Tool 隐藏与 Document 释放不同，文档关闭许可可能已被单页流程持有，若再无条件申请整窗范围许可会互相拒绝。实施时必须验证已在途的单页关闭、范围确认和原生最终清理三种路径能正确接续。

若 P0 证实某个真实 Document 关闭按钮同次点击同时请求窗口关闭和执行文档命令，只对已由关闭协议接管的该次事件去重；不能预先禁用所有 Document 关闭按钮或全局吞掉 Click。保留键盘和辅助功能的按钮执行语义。

关闭取消以“不进行关闭性拆除”为约束；等待期间用户主动进行的其他有效操作不应被静默回滚。范围变化必须使旧许可失效，而不是把整个工作区强行恢复到旧快照。

## 6. 新建目标的捕获、传递与提交

### 6.1 捕获时机与调用链

面板显示前记录来源工作台窗口及当时活动文档组，避免布局或搜索框焦点通知覆盖来源；用户执行功能创建动作时把该不可变目标复制给本次调用，再进入串行门和插件初始化，发布前统一重验。标签选择和组内焦点事件共同更新最近组，因此点击另一组已选中的页面也被正确记录。

目标沿 `CommandPaletteView / WorkbenchWindowInteraction → WorkspacePaletteActions → DocumentPersistenceCoordinator → WorkspaceSession` 显式传递。不要将目标放入共享 Command 实例的可变字段，否则主窗与浮窗共用投影时可能相互覆盖。已有 `UseOwner` 继续解决保存/确认对话框归属，不能单独替代文档目标参数。

操作在 A 窗口发起后，即使排队或初始化期间激活 B 窗口，结果仍优先进入 A 的原目标组。组跟随文档拖动到其他窗口时，不能只因引用仍存在就追随到新窗口；必须同时验证组归属与来源窗口身份。

### 6.2 发布前的确定性回退

在 UI 线程提交前按以下顺序重验：

1. 原目标组仍附着于来源窗口、具备文档接收能力且不处于关闭中，则使用原组。
2. 原组失效但来源窗口仍有效，则使用该窗口最近活动的有效文档组；再按稳定布局顺序寻找其他有效组。
3. 来源窗口失效、正在关闭或没有可接收文档的组，则使用主窗口有效的活动文档组，再回退到主默认文档组。
4. 应用已进入关闭/重启准备、Session 不再接受创建或没有安全目标时，拒绝发布并按现有所有权释放未发布候选；不能复活旧窗口或在退出中补建新窗口。

所有回退均排除其他无关浮窗，不能因为 B 窗口最近被激活就把 A 的请求重定向到 B。若回退成功，通过实际选中的新标签表现结果；若无法发布，则让原面板显示本次失败，不伪装成创建成功。

### 6.3 原子发布与焦点

- `PublishDocument` 按选定目标执行一次插入、激活与通知，失败时撤销该目标上的部分写入；重复发布检测覆盖整个工作区，不能只查最初主文档组。
- 保留“初始化成功后才可见”的语义，失败候选的 View、Scope、持久化状态和页面登记仅清理一次。不要先发布到主窗口再 Move 到浮窗，以免闪现、错误通知和中间状态落盘。
- 结果应能确定实际发布的页面及其承载组；面板结束后的焦点恢复基于本次结果，不借用可能已被其他操作改变的全局活动 Document。
- 新页在目标组内选中。延迟焦点回调重查页面、窗口与会话是否仍有效；用户已经切换到其他窗口时，不由旧回调把输入焦点抢回。目标失效后不得聚焦已释放 View。

### 6.4 其他创建与打开入口

本轮必须修复 Ctrl+Shift+P 的功能创建入口，并核对共用发布链的所有调用者：

| 入口 | V16 范围 |
| --- | --- |
| 命令面板“打开新标签” | 显式使用本次来源窗口与文档组，属于本轮新增行为 |
| 插件目录、欢迎页、功能中心 | 本轮保留既有默认落点，不顺带重构辅助窗口 Owner；调用共用新接口时必须明确采用既有默认策略并补回归 |
| 打开文件、恢复文件、启动创建 | 保留各自既有目标与去重规则；无显式来源时不得暗中读取最近活动浮窗 |
| 已打开页面定位、保存、Tool、普通命令 | 保留现有身份与执行语义，不适用功能新建规则 |

统一更多入口的“就地新建”可以后续扩展同一窄目标参数，但不是本次修复的隐含工作。此范围避免把命令面板修复扩大成全部窗口服务改造。

## 7. 兼容、注释与数据边界

不更改 Plugin SDK public API、插件注册协议、manifest、Document 文件格式、Layout V3 或 NuGet 依赖版本。文档仍由原 WorkspaceSession 唯一拥有，不为每个浮窗建立独立 Runtime、Provider、文档服务或工作区。

纯文档浮窗仍只存在于本次运行，重启不自动重开 Document；布局保存继续只表达工具空间安排。混合浮窗关闭、隐藏工具恢复、布局重置与跨窗转移必须保留原模型/View/Scope 规则。不为解决可见黑框修改背景颜色、隐藏整个应用或引入周期扫描空窗口。

优先在 Host 适配层解决宿主确认与 Dock 同步协议的衔接。若正式回归证明必须修改固定 Dock 补丁，先补充本方案的证据和影响范围，再遵守现有补丁重建与摘要校验流程；不能修改全局 NuGet 缓存或静默替换 DLL。

实现中的中文注释至少覆盖：

1. 为什么最后文档必须在拆除布局前请求关闭窗口，以及取消后保留哪些对象。
2. 首次否决、异步确认、一次性许可、重试和最终清理的先后关系，如何避免递归和重复事件。
3. 为什么窗口 Owner、全局活动文档和本次插入目标不能混用。
4. 为什么在串行门前捕获目标、在发布前重验，以及每一级回退的产品理由。
5. 文档、View、Scope、窗口注册及借用目标各自由谁拥有、何时撤销。
6. 发布失败和迟到完成如何释放候选、恢复状态，以及哪些调用必须在 UI 线程执行。

对有不变量的核心入口使用中文 XML 注释；复杂时序使用中文行内说明设计原因。注释随实现更新，避免保留已经失效的假设或测试承诺。
