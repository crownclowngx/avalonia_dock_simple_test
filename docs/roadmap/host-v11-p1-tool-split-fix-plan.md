# V11-P1：Tool 上下分割崩溃修复计划

> 范围：V11 源码补丁和开发验收。分支：`codex/host-v11-floating-layout`。基线：`0525321`。用户已确认保留 Tool 到主窗口文档区域的全宽上下停靠。本轮不部署安装目录。

## 目标和边界

修复 Tool 上下分割中的过期插入索引，同时保留局部布局、分隔条、比例及原模型和 View。Tool → Tool 与浮窗内部采用 Dock 局部分割；Tool → 主窗口 DocumentDock（含文档子组）保留全宽停靠；主窗口外侧全局停靠与 Document 分割保持既有语义。

不升级 Dock、Plugin SDK 或 Layout V3，不重置用户布局，不使用 AIFLOW、Windows CI、seal 或正式发布门禁。真实桌面验收与 Headless 分开记录。

## 职责和 SOLID

- Factory 适配基类分割顺序，通过内部 `OnDockSplitCompleted(IDock originalTarget, IDockable insertedDock, DockOperation operation)` 回调携带明确目标，不按插件 ID 判断。
- Session 拥有工作区及业务实例，按当前主树的对象引用确认主窗口目标；Coordinator 处理工具全宽兼容策略及临时容器替换。通用 OnDockableDocked 只维护通知，不再猜测分割目标。
- 保留基类事件、初始化、取消及释放协议；接口只扩展已有内部边界，不增加通用管理器、服务定位器或事件总线。
- 保存组件继续只负责捕获、校验和 I/O，不获得停靠策略职责。纯判断依赖传入布局事实。

上述分别落实 SRP、OCP、LSP、ISP 与 DIP。中文注释解释目标分类、框架清理副作用、UI 线程与原实例所有权。

## 替换与保存

临时容器仅在仍挂接、仅剩一个有效子节点且不是固定骨架时整理。保存比例和 Active/Default 引用；先取出子节点，再重新定位临时容器，先插入替代节点，最后移除旧容器。通过 Factory 协议操作，不截断索引、不吞异常、不绕过框架批量重写集合。

前置条件不满足时保留基类的有效分割并记录诊断，不将既有恢复检查点扩展成整个拖放事务。DockService 先移动再分割，保留现有批量变更和 UI 延后捕获，验证临时脱离状态不会进入布局文件。V3 继续仅恢复工具，文档不跨启动重开。

## 测试和实施顺序

1. 将原复现转为正式失败测试：上下方向、首中尾、嵌套布局、父分割方向、全宽停靠临时容器替换。
2. 接入内部完成回调和目标分类，修正替换顺序；追加无效目标、固定骨架和诊断测试。
3. 通过真实 DockService/DockManager 覆盖同组拆分、跨组/整组移动、浮窗内分割及拖回主窗口；补原实例、分隔条、比例、Active/Default 和重复挂接断言。
4. 验证 V3 恢复后再次分割、隐藏显示和捕获—写入—恢复；保留 Document、全宽、全屏及关闭取消回归。
5. 同步总计划、当前 V3 契约、使用指南与 Host 设计文档，修正文档中的旧 V2 及全部上下停靠均全宽的表述。文档定稿后执行完整本地 verify；最终证据写入非嵌入 JSON。
