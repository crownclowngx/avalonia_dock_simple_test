## 1. 目标与取舍

本轮把现有兼容规则、产物验收和插件状态展示连接起来，让 Host 维护者能够直接回答：

1. 当前运行的是哪一份 Host，每个插件来自哪一份产物？
2. 插件声明支持什么 SDK，实际用什么依赖编译，当前由 Host 提供什么运行时？
3. 哪些检查已经执行，哪些尚未执行，已有报告是否仍适用于当前产物？
4. Host 升级后哪些插件可以继续使用，哪些需要补充验证或处理实际冲突？

主要衡量成本是长期决策成本。允许 AI 承担较多实现工作，但实现必须减少人工对照、跨仓同步和规则解释，不能增加无实际需要的公开 API、包版本组合或通用框架。

最终使用入口为 **工具 → 插件看板…**。扩展现有插件状态独立窗口，提供概览、兼容矩阵、详情与诊断；底层报告同时供本地验收工具和 Host 使用。

### 1.1 开发完成定义

- 共享运行时、插件引用和打包限制具有唯一规则来源，差异可解释、可验证。
- 新产物携带可读取的构建信息；旧产物无需重编译，缺失信息以未知显示。
- 验收报告绑定具体插件产物和具体 Host 构建，分项说明覆盖范围。
- Host 看板复用既有运行事实，能够区分当前状态、验证结果和证据适用性。
- 完整本地 `verify`、新增工具自测、规则与报告测试、真实包测试、Headless UI 测试通过。
- 当前指南、专项契约、专项验证说明和 V10 开发记录同步完成。
- 未执行的真实 Windows 输入、原生视频及外部业务验收明确保留为待验收；开发完成不等于发布资格。

### 1.2 本轮保留的边界

| 项目 | 决定及原因 |
| --- | --- |

### 2.2 必须纠正的语义

1. **禁止携带不等于 Host 保证提供。** Build 的 `Microsoft.Extensions.*` 限制比运行时具体闭包更宽；Build 禁带 Newtonsoft.Json，而 Host 边界测试要求不直接引用它。不能把禁带名单直接当成共享名单。
2. **允许共享加载不等于允许插件直接引用。** Dock 可保留当前加载策略，同时保持插件代码边界。
3. **SDK 版本不等于 Host 产品版本。** 当前 Host 产品为 3.0.0，自有包为 3.4.1；看板必须另有构建身份。
4. **manifest 区间不等于已验证范围。** 在某一构建通过不能显示为该版本及以后全部通过。
5. **加载通过不等于业务通过。** ALC、视图、Workspace、原生播放和业务流程需要独立证据。
6. **Unshipped 不等于从未公开。** 部分增量签名已经公开；本轮不能通过清空文件消除这个事实。
7. **历史验收记录不等于可用夹具。** V9 部分生成物已经清理；只有哈希、没有原文件时，不能宣称已重新验证旧二进制。

## 3. SOLID 与实现约束

SOLID 优先于接口数量、模式数量和目录整齐度。每个新增边界必须有明确的职责、消费者和可验证行为。

| 原则 | 落地要求 | 验证方式 |
| --- | --- | --- |
| SRP 单一职责 | 规则解释、元数据读取、指纹计算、报告校验、匹配判断、界面投影各有明确变化原因；窗口不承担加载或验收 | 纯函数测试、I/O 边界测试，以及打开窗口不激活插件的集成检查 |
| OCP 开闭原则 | 新插件依据贡献和产物信息自动进入看板；新增普通依赖通过描述归类 | 不允许按业务插件名称编写分支；规则数据变化无需修改窗口 |
| LSP 里氏替换 | 有无新元数据、加载成功或失败的候选都可形成有效只读快照；未知信息不伪装成功 | 旧包、坏清单、无 PluginId 和缺报告夹具 |
| ISP 接口隔离 | 界面只获得查询、导入与导出所需能力；报告读取接口不拥有启动插件的权限 | 检查构造依赖和调用链；不注入整个容器或通用服务定位器 |
| DIP 依赖倒置 | 匹配与状态计算依赖明确的数据输入；文件、时钟、调度和 UI 适配在组合根注入 | 可用内存数据验证判断；基础设施失败不能改变判断规则 |

### 3.1 朴素设计

- 沿用 MVVM、构造器注入、不可变查询快照和现有 Host Adapter。
- 有限状态使用枚举、记录类型和明确分支；默认采用小型具体类或纯函数。
- 仅在确有替换、I/O 或平台边界时引入窄接口，不为每个类创建同名接口。
- 规则源使用有限字段的数据描述，禁止引入可执行脚本、通用表达式语言或规则引擎。
- 验收工具复用生产组合与既有测试夹具，不复制一份 Host 行为实现。
- 不引入 MediatR、CQRS 基础设施、事件总线、通用任务平台、在线服务或数据库。
- 不按目录白名单机械搬动 Dock 代码；Layout、Workspace 内部的合理依赖允许保留。
- 公共 SDK 不承担看板 DTO、验收内部接口或 Host 诊断实现。

### 3.2 中文注释

新增及实质修改的核心类型、跨层方法、状态判断和异常处理使用中文注释。复杂处使用 XML `<summary>`、`<remarks>`，必要时给出输入与输出示例。

注释必须说明：

1. 设计目的、对象所有权，以及为何采用当前职责划分。
2. 数据事实来源、缺失值语义和不能推导的结论。
3. 指纹覆盖范围、版本区别、报告何时适用或失效。
4. 异步取消、窗口关闭、刷新覆盖、迟到结果和异常后的状态保留。
5. 兼容例外的来源与保留原因；注释关联测试或契约，而不是只写“兼容处理”。

不逐行复述赋值或循环；重点解释“为什么”和“边界是什么”。代码变化后同步修正中文注释，不能保留与新行为矛盾的旧说明。

## 4. 规则与数据设计

### 4.1 唯一运行时规则源

规则至少分三个维度，不压成单一 shared/private 标记：

| 维度 | 含义 | 例子 |
| --- | --- | --- |
| 运行时提供方 | Host 共享、插件私有、.NET 运行时 | SDK 由 Host 提供；Icons 默认属于插件私有资产 |
| 引用边界 | 插件可引用、Host 内部、历史限制 | Dock 保持 Host 内部使用 |
| 打包约束 | 禁止携带、按私有声明携带、另有原因的禁带 | 历史 Newtonsoft 限制单独说明，不伪装为 Host 提供 |

实施采用主仓受版本控制的描述文件；Host 和 Build 使用构建时生成或校验过的投影。Build 包必须包含所需规则与工具，外部消费者不依赖主仓路径。Host 启动不读取用户可随意编辑的外部策略文件来改变程序集共享。

第一轮迁移以现有行为为基线，不顺带扩大或缩小共享闭包。规则源记录显式根、引用限制、打包模式和例外原因；传递闭包按实际 Host 构建计算，作为输出证据，不手工维护每个传递 DLL。

检测以下情况：规则冲突、Host 共享文件误入插件包、私有资产误共享、被声明为 Host 提供但候选产物缺失、构建规则与运行时投影不一致。BCL 的运行时加载规则单独处理，不把所有 System.* 文件当成普通插件资产。

已发布旧版 Build 的内容不可改变。新 Build 输出与旧 Build 产物都由候选 Host 验收，不能假设规则源统一后所有历史工具链同步获得新规则。

### 4.2 版本与身份

| 信息 | 事实来源 | 使用规则 |
| --- | --- | --- |
| 插件业务版本和 SDK 区间 | 原始 plugin.manifest.json | 保留原值，不因验证失败修改下限 |
| 编译 NuGet 依赖 | Build 生成的构建信息、可用的依赖还原描述 | 区分声明版本和实际解析版本；缺失时不猜测 |
| 程序集引用身份 | 只读程序集元数据 | 单独标注 AssemblyVersion，不等同于 NuGet 包版本 |
| 插件产物身份 | 规范化文件清单及内容指纹 | 相同业务版本的不同文件必须区分 |
| Host 产品与源码信息 | 构建生成信息 | commit 仅辅助定位；脏工作树不能只以 HEAD 代表内容 |
| Host 运行时身份 | 候选产物及实际提供的共享程序集身份、内容摘要 | 相同产品版本、不同运行时不得复用通过结论 |
| 规则版本 | 规范化规则描述摘要 | 判断规则变化需要重新验证，不沿用旧结论 |

构建信息优先通过新增可选旁路文件提供，不扩展严格 manifest schema 2。文件名称及字段在 G1 固定；旧 Host 是否忽略该文件、旧打包流程是否容纳新增资产，必须有实际消费测试，不凭假设保证兼容。

指纹按相对路径、文件长度和内容 SHA-256 计算，路径分隔符、排序及大小写规则必须固定；包含入口、manifest、deps、私有托管与原生资产。规范化清单防止大小写或路径碰撞。

运行日志、业务数据、验收报告、临时缓存不进入插件代码产物指纹。新元数据属于产物内容，但自身不包含依赖自身内容的最终摘要；完整产物摘要由外置验收报告持有，避免循环哈希。

构建元数据不注入当前时间、随机 ID、个人绝对路径等导致相同输入不同输出的字段；验收时间属于报告。对目录输入，验收前后核对指纹；发生变化即标记输入变化，不能给出稳定通过结论。

### 4.3 验收报告与兼容矩阵

报告至少包含 schemaVersion、报告身份、插件身份和产物摘要、Host 构建与运行时摘要、规则摘要、操作系统与架构、验收层级、分项结果、执行时间和证据引用。

| 层级 | 覆盖范围 | 不可据此声称 |
| --- | --- | --- |
| 静态 | 清单、文件、依赖、禁带项、直接引用边界 | 已加载或已运行 |
| 加载与组合 | ALC、DI、贡献注册、声明视图 | Workspace 和业务流程通过 |
| Workspace | 文档创建关闭、Scope、视图转移、工具显隐 | 原生播放、数据库或网络任务通过 |
| 业务与真机 | 显式列出的场景和环境 | 未执行插件、场景或平台也通过 |

分项结果使用通过、失败、未执行、输入缺失、执行中断等明确状态；证据适用性独立表示匹配、不匹配、无法确定或报告无效。当前会话可用性由原 Host 状态提供，不被报告覆盖。

矩阵的行绑定插件产物，列绑定 Host 构建；同一插件不同产物使用分组或展开项。单元格显示验证层级和结果，不能只用一个绿勾覆盖全部含义。没有报告不是失败，SDK 区间内也不是已验证。

同一身份和层级出现多个结果时保留历史，明确最新有效执行；存在相互矛盾或中断后的不确定结果时展示提示，不挑选任意一次成功掩盖后续失败。

报告只能携带数据。来源可显示为“随产物交付”或“用户导入”，但这不代表经过签名认证；内容哈希也不证明报告来源可信。导入不得执行报告中的命令、加载附件 DLL 或自动访问其中的网络地址。

## 5. Host 看板方案

### 5.1 入口与窗口

- 菜单改为 **工具 → 插件看板…**，沿用 `myavalonia.host.command.plugin-status.open` 命令身份。
- 命令面板继续可通过“插件状态”和“插件看板”找到同一入口；不增加新的默认快捷键。
- 扩展当前 PluginStatus 窗口及查询实现，内部类型按职责需要调整，不为名称统一大面积改名。
- 使用主窗口 Owner 的单实例非模态窗口；重复打开恢复并激活，Esc 关闭。
- 取消主窗口关闭不销毁看板；主窗口真正关闭时释放窗口及其后台读取任务。
- 没有插件、没有活动文档、所有工具隐藏时仍可打开；不把可打开条件绑定到某个插件生命周期。

### 5.2 窗口内容

| 区域 | 内容与行为 |
| --- | --- |
| 环境摘要 | Host 产品版本和构建标识；SDK、Avalonia、Dock 的实际运行版本；当前会话时间 |
| 概览 | 插件名称 / ID、业务版本、编译 SDK、声明区间、当前运行状态、当前环境验证情况 |
| 兼容矩阵 | 当前 Host 列优先；历史构建按需展开；支持按插件和验证结果筛选 |
| 详情与诊断 | 构建依赖、程序集引用、指纹、报告来源、执行时间、层级与场景、贡献及原有诊断 |
| 操作 | 搜索、筛选、刷新状态、显式检查安装产物、导入报告、复制摘要和显式导出 |

概览优先回答“现在是什么状态、证据到哪一层、下一步做什么”。技术哈希、路径和详细程序集清单进入详情。颜色配合文字，不能只靠红绿区分。

提示采用固定规则：例如“已有匹配验证”“尚未验证 Workspace”“报告对应其他产物”“依赖检查失败，请查看详情”。仅因包版本较旧或没有报告，不提示必须升级。

### 5.3 数据来源与刷新

数据流保持简单：

```text
现有 Registry / Availability / Diagnostics ── 当前会话快照 ──┐
安装产物元数据与后台指纹检查 ─────────────── 产物快照 ──────┼─ 匹配与只读投影 ─ ViewModel ─ 窗口
随包报告 / 显式导入 ── 校验与本地保存 ───── 报告快照 ──────┘
```

复用现有运行事实，不建立第二套生命周期状态。记录当前会话已加载的程序集身份；磁盘文件变化不能替换当前会话身份，展示“安装内容已变化，当前会话仍为原加载结果”，按既有流程重启后再判断。

打开、激活和“刷新状态”读取快照，不重复发现或加载插件。首次必要的元数据读取和“检查安装产物”异步执行；大文件哈希不在 UI 线程，不在每次激活时重算。文件时间和大小只能帮助失效判断，不能替代内容匹配证据。

窗口关闭取消自身读取与计算；迟到结果不得写回已释放窗口或覆盖更新的刷新结果。刷新失败保留上一次成功快照，明确最后更新时间和失败状态。

报告保存沿用 HostDataRootPolicy，使用独立子目录，不混入布局、插件安装文件或 SDK API 基线。实现格式版本、重复导入、冲突、原子写入和损坏文件处理；旧报告作为历史保留，可按需查看，失效不自动删除。

报告导入与文件校验设定合理大小、条目数量和路径范围限制。复制及导出沿用诊断脱敏规则，不包含凭据、账号信息或非必要个人路径。

### 7.2 本轮使用的门禁

主仓根目录执行的现有完整开发入口：

```powershell
dotnet run --project tools/MyAvaloniaManagement.Gate -- verify
```

它负责 locked restore、Release 零警告构建、SDK / Host Unit / Plugin / Headless UI / MyPlugTest 测试、契约检查、打包及真实 ZIP 验收。新增本仓可重现测试需进入相应测试工程和执行集合，不只保留为人工可选脚本。

修改 Gate 后独立运行工具自测，避免工具运行时重建自身：

```powershell
dotnet test tools/MyAvaloniaManagement.Gate.Tests -c Release -m:1 -warnaserror
```

定位现有测试工程时可使用以下专项命令；它们不替代最终完整 verify：

```powershell
dotnet test Host/MyAvaloniaManagement.PluginSdk.Tests -c Release -m:1 -warnaserror
dotnet test Host/MyAvaloniaManagement.Tests -c Release -m:1 -warnaserror
dotnet test Host/MyAvaloniaManagement.PluginTests -c Release -m:1 -warnaserror --filter 'Category!=PackageAcceptance'
dotnet test Host/MyAvaloniaManagement.UiTests -c Release -m:1 -warnaserror
```

开发门禁不得通过跳过测试、放宽断言、取消警告错误、降低已有阈值或删除 API 基线获得通过。测试结果记录通过 / 失败 / 跳过数及实际输入，缺报告、零测试和需要执行却未执行均不能记为成功。

真实 ZIP 的 PackageAcceptance 保持由 Gate 提供输入并校验结果数量。外部兼容入口是另一个显式开发验证入口，不恢复旧外部仓库 scope，不让默认 verify 依赖十一插件源码、个人安装目录或外网账号。

本轮不采集或调整发布专用覆盖率阈值，也不以发布 coverage / Windows Smoke 阶段作为开发完成前提。新增工具的实际命令在实现后写入专项维护指南；不得在本计划中虚构已经可执行的参数。

### 7.3 真机与业务检查

Headless 测试不能证明真实鼠标、DPI、原生视频、数据库迁移、账号登录或下载任务通过。可进行普通本地人工观察并记录，但不启动 Windows CI 或发布 Smoke。缺少环境时列为待验收，沿用[现有待办](README.md)相应条目；正式发布时再完成当次要求的业务、真机和发布门禁。

| API 分类是否解除发布阻塞 | 本轮仅提供证据和开发验证，不宣告 seal 条件已经满足 |

### 9.2 需要停下该项并报告的情况

- 统一规则要求改变历史共享或禁带语义：先列清受影响依赖、旧产物和候选行为，不悄悄扩大范围。
- 旁路元数据必须破坏 manifest 或旧 Host 消费：先调整为兼容方案，不能用强制重打所有插件规避。
- 无法唯一匹配实际运行 Host 与报告：显示无法确定，继续提供现有诊断，不能降级为只比较版本字符串。
- 原始旧产物缺失：对应重放验收待补，不伪造历史 DLL 或沿用旧测试数量。
- 新公共包、SDK 契约或跨仓批量改造成为必要：单独给出事实和范围变化，不能由内部实现顺带引入。
