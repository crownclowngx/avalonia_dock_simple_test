# V23：本地 ZIP 插件安装与更新专用开发验证

> 用途：验证 [V23 方案](host-v23-local-zip-installation-plan.md)的旧包兼容、安装检查、文件事务、进程占用、重启和恢复。
> 状态：待实施的验证计划，不代表测试已编写或运行；当前任务仅交付文档。日期：2026-09-24。
> 当前入口：[主仓开发验证](../maintenance/verification.md)。V22 在线插件源继续暂停，本矩阵不包含远程源、网络下载或托管验证。

## 1. 首要规定与验证边界

1. SOLID 优先，设计模式朴素使用；生产、测试和工具关键代码均使用详细中文注释，解释资源所有权、锁顺序、取消、提交点和恢复思路。
2. 不使用 AIFLOW、Windows CI 或发布门禁。仅本机单元测试、文件/进程专项、Headless UI、必要的 Gate 工具自测与开发 `verify`；不执行 seal、发布 Smoke、发布覆盖率/重复性，不部署或上传。
3. 每个矩阵编号建立“真实测试全名与参数 → 关键断言 → TRX/文件证据”的映射。缺输入、零发现、跳过、失败、超时、不完整报告均不能写为通过。
4. 普通纯逻辑用单元测试；文件提交和恢复必须使用隔离真实目录；锁竞争和进程退出必须使用受控真实子进程；UI 用 Headless 验证交互状态。不能用模拟文件系统代替实际重命名/占用语义，也不为纯逻辑启动完整 Host。
5. 故障注入覆盖每个持久化/文件变更边界，断言目录、登记和日志三者的最终事实；不测试私有方法调用次数来代替可观察行为。
6. 进程等待使用明确就绪/阶段信号与有界取消，禁止固定 sleep、重复点击和自动重跑掩盖失败。测试只清理自己拥有的进程和经过绝对路径核对的目录。

## 5. T：安装事务、登记与崩溃恢复

| 编号 | 场景 | 必需断言 |
| --- | --- | --- |
| T01 | 预览与提交 | 用户确认前无待应用意图，Staged 前所有快照完整；活动目录不变 |
| T02 | 单操作限制 | 两个确认者不能各自成功覆盖待办；第二者得到明确忙碌/修订冲突 |
| T03 | 取消 | Staged 取消先持久化；清理失败不复活；Applying 不接受普通取消 |
| T04 | 原目录变化 | 提交前和应用前均复核完整基线；有改动则拒绝且不自动更新基线继续覆盖 |
| T05 | 整目录更新 | 旧版特有 DLL 不残留新目录，兄弟插件完整不变；备份包含全部旧文件 |
| T06 | 旧目录移走前后中断 | 每个日志提交/目录移动前后注入失败；新进程恢复到可解释完整状态 |
| T07 | 新目录就位/登记更新时中断 | 日志与磁盘共同恢复，不能因为新 DLL 存在或登记已写就判定成功 |
| T08 | 没有旧版的新装失败 | 撤除本操作候选、保留失败证据，其他插件与用户数据不变 |
| T09 | 启用插件确认 | 实际贡献和生命周期 Ready、主窗口交接满足后才 Committed；全局启动失败不假报成功 |
| T10 | 禁用插件确认 | 只记录安装成功且未运行验证，不调用其入口/生命周期 |
| T11 | 已加载后初始化失败/崩溃 | 当前进程不替换文件；下一次独占启动恢复原版；不循环启动失败候选 |
| T12 | 主动恢复上一版本 | 备份身份/摘要/SDK复核；用同一事务恢复，保留当前失败载荷及原启用选择 |
| T13 | 无备份/备份损坏 | 明确无法恢复，不删除现有载荷、不从其他目录猜备份 |
| T14 | 日志/登记损坏 | 大小、重复字段、未知 schema、伪造路径等失败保留原件，不能重置成空状态继续安装 |
| T15 | 恢复幂等性 | 对每种半完成磁盘状态重复启动恢复，最终内容一致；不发生二次删除、丢失备份或重复应用 |
| T16 | 保留和清理 | 候选未确认不得清理旧版；只清理归属明确的多余备份，故障证据先归档 |

T06/T07 必须覆盖写意图失败、旧目录移动成功但记录失败、新目录移动失败、新目录成功但记录失败、登记成功但最终 Committed 失败。测试保存各阶段目录摘要和日志状态，故障覆盖表不能只写“测试了回滚”。文件替换可恢复不等于业务数据库事务回滚。

## 6. L/R：租约、进程和重启

| 编号 | 场景 | 必需断言 |
| --- | --- | --- |
| L01 | 两个 Host 使用同根 | 多个共享使用租约共存；任一个仍活跃时不能取得文件变更租约 |
| L02 | 同根不同数据根/不同发现根 | 前者共享事务与锁，后者互不占用；路径大小写/别名不能绕过归属检查 |
| L03 | 锁顺序与并发提交 | runtime→operations 顺序固定，无持有 operations 等待 runtime；竞争失败受控 |
| L04 | 进程终止与残留锁文件 | OS 租约释放后可恢复；锁文件仍存在不等于忙碌，不用删锁文件解锁 |
| L05 | 独占转共享的竞争窗口 | 共享取得后重新检查日志/磁盘；另一进程胜出不得加载旧快照 |
| L06 | 试启动所有者 | PID 和启动时间匹配才允许试运行；另一实例不能加载未确认载荷或提前提交成功 |
| L07 | 无权限与外部占用 | 安装不可写不隐式提权/换目录；租约无法可靠建立则阻断加载，文件被非协作进程占用时不强杀 |
| L08 | 进程与资源寿命 | 看板关闭、Runtime 释放或资源保留不提前释放运行保护；最终退出后其他进程才修改 |
| R01 | 自动重启正常链 | 原文档许可、布局保存、资源排空和 CleanExit 保持；新进程在发现前应用一次 |
| R02 | 取消/保存失败/关窗否决 | 原会话继续，当前文件不变，Staged 意图保留，安装准入恢复 |
| R03 | 异常退出/资源清理失败 | 不启动继任者；下次手动启动按真实日志恢复，不伪造已应用 |
| R04 | 普通退出后手动启动 | 不创建重启助手；下一次启动应用已确认的待办 |
| R05 | 启动形式及助手边界 | apphost/dotnet、中文/空格路径保持；助手不创建安装器/Runtime、不接收任意文件命令 |
| R06 | 故障后恢复运行 | 使用真实旧新程序集确认运行版本变化，不只检查 JSON；无同进程重载和重启循环 |

上述为本机专属进程开发测试，不是 Windows CI 或发布 Smoke。只读安装/旧 Host 不参与新租约的兼容边界需要文档与人工观察记录，不能通过一个模拟锁声称覆盖所有外部程序。

## 8. 执行顺序与命令

### 8.1 本次仅文档

运行 `git diff --check`，检查变更 Markdown 的本仓链接/锚点与 JSON 围栏，核对新增方案没有冒充已实施契约。Markdown 会嵌入 Host，因此重新构建并执行现有帮助专项：

```powershell
dotnet test Host/MyAvaloniaManagement.Tests -c Release -m:1 -warnaserror --filter FullyQualifiedName~HelpContentTests --logger 'trx;LogFileName=v23-docs-help.trx' --results-directory artifacts/host-v23/docs-help
```

另用本次构建出的 Host 程序集只读核对两个新增 Markdown 资源确实存在、内容与源文件一致，使用已有帮助渲染器验证输出。无需为了简单文档新增永久测试框架，也不能仅凭既有 HelpContentTests 声称它逐个读取了 V23 新文件。

依赖或本机补丁缺失时记录实际失败，不把未执行写成通过。本次不执行尚未实现的安装矩阵或完整发布流程。

### 8.2 后续实施

每阶段先构建真实变更输入，再运行本阶段专项。过滤器使用实现后真实测试全名，不使用计划编号或不存在的类名。常规 Plugin 测试排除现有独立包验收：

```powershell
dotnet test Host/MyAvaloniaManagement.PluginTests -c Release -m:1 -warnaserror --filter 'Category!=PackageAcceptance'
```

新安装用例不标为 `Category=PackageAcceptance`。该分类现有“恰好一项”约束保持，由 Gate 准备 `MYAVALONIA_MY_PLUG_TEST_PACKAGE_ROOT` 后执行；真实安装矩阵使用普通 Plugin 测试或独立清晰分类，避免破坏现有计数。

如修改 Gate 编排，先单独运行工具自测，不与 Gate 自身并发重建：

```powershell
dotnet test tools/MyAvaloniaManagement.Gate.Tests -c Release -m:1 -warnaserror
```

完整实施及专项通过后，在仓库根目录运行现有本机开发门禁：

```powershell
dotnet run --project tools/MyAvaloniaManagement.Gate -- verify
```

默认 verify 保持只依赖主仓；不为 V23 强制还原/构建 12 个外部插件，也不接入 Windows CI、seal、发布 Smoke、发布覆盖率/重复性。按 G0–G5 的影响范围修复和复测，失败记录保留，不无理由重复整套运行。
