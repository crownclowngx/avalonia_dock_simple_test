## 1. 目标与首要规定

本轮判断标准是：哪些复杂度来自用户需求、资源寿命和框架协议，哪些复杂度由代码组织额外制造。目标是让同一业务规则只有一个维护位置，每次失败都有明确回滚责任，读取事实不必构建无关运行对象。文件数量、类长度、方法长度和注释行数不作为完成指标。

实施必须满足以下规定：

1. **SOLID 是首要规定。** 每项方案先解释职责、依赖和所有权，再讨论代码搬移；不能以减少行数为由破坏取消、提交或释放边界。
2. **设计模式朴素使用。** 优先普通方法、现有具体协作者、少量不可变记录及局部租约；新增类型必须消除一个可说明的重复规则或清理义务。不得建立通用状态机、策略注册框架、事件总线、反射分发、通用事务管线或第二服务容器。
3. 新增或实质修改的核心类型、方法和关键分支使用**详细中文注释**，说明职责、输入输出、状态与资源归属、时序及设计理由；不逐行翻译代码。
4. 单元测试、必要的 Plugin/Headless UI 回归、架构边界检查与本地开发门禁必须齐全。要求逐项落到真实断言，不能以“已有某测试类”代替覆盖证明。
5. 实施同步更新当前契约、架构、设计取舍、导航及本轮专用验证；方案、实现、自动验证、实机体验、部署和发布分别记录。
6. **不使用 AIFLOW**，不读取或维护其上下文、任务记录及更新候选。
7. **不使用 Windows CI 与发布门禁。** 开发阶段仅执行本机专项和既有 `verify`；不执行 `seal`、发布 Windows Smoke、发布覆盖率或发布重复性门禁，不修改 CI、不部署安装目录、不上传包或创建发布标签。发布阶段再按当次要求执行发布验证，现有政策和阈值保持。

本次请求交付 Markdown 方案、专用验证规范和导航更新。下述实施阶段用于后续代码工作，不把文档任务扩展成未经要求的代码改造。

## 2. 真实复杂度与组织复杂度

| 对象 | 应保留的真实约束 | 本轮要减少的组织负担 |
| --- | --- | --- |
| 文档关闭 | 同步 Dock 否决与异步确认衔接；保存修订；命令排空；原生取消；许可不能跨范围复用 | 单页、整窗分别实现同一决策规则，旧入口与专属状态继续存活 |
| 文档创建及恢复 | 初始化与 View 准备完成后才能发布；失败释放；恢复原件保护 | 多个方法分别约定 pending 清空和回收，方法之间出现无局部回滚保护的间隙 |
| 命令目录 | Host/Plugin 身份冲突校验；当前目标和运行期可用性复查 | 纯描述与 Handler 实例耦合，使目录校验依赖 Workspace 和 UI 服务解析 |
| 创建入口和页面查询 | 身份、插件可用性、关闭状态及 V18 目标一致性必须实时判断 | 元数据读取经过 Session 转调；单项布尔判断构建全部分类或页面展示数据 |
| 工具显示与隐藏 | 单例复用；定位和显隐意图不同；浮窗关闭可取消；一次提交通知 | 多套近似入口重复校验、恢复和解释 bool/结果语义 |

继续保留每插件私有 Provider、每 Document Scope、Tool singleton、原子文件提交、严格 JSON、Layout V3 与 V2 只读迁移，以及取消后等待实际任务结束的关闭门。Workflow 运行治理、诊断策略、框架补丁和窗口服务体系不纳入全面重写。

## 4. SOLID 的落实与审查

| 原则 | 本轮具体要求 | 拒绝的做法 |
| --- | --- | --- |
| SRP 单一职责 | 关闭决策、Dock 协议、发布回滚、目录事实和 Handler 执行各有明确职责；Session 继续拥有工作区 | 将 Session 拆成多个同时修改同一集合的管理器；把校验、执行和释放塞进万能 Helper |
| OCP 开闭原则 | 使用已有强类型身份、描述和目标范围表达变化；Host 固定 Handler 映射集中显式维护 | 按插件名称/ID 增加特判，或为未来假设引入规则引擎和反射扫描 |
| LSP 里氏替换 | 保持返回、异常、取消、通知、原生否决和释放协议；确认的缺陷以独立行为变更记录 | 将取消当完成、将保存警告当磁盘失败，或让相同入口悄悄改换目标 |
| ISP 接口隔离 | 复用已有窄端口；仅真实跨模块、替换或测试隔离需要时增加接口 | 一类一接口、依赖包、包含全部操作的上下文接口 |
| DIP 依赖倒置 | DI 解析留在组合根；目录不依赖运行对象；消费者依赖所需事实与用例 | 把 IServiceProvider、任意服务名或根容器闭包传入目录/业务类 |

新增协作者的判断不是“看起来更分层”，而是能否指出被删除的重复状态、分支、依赖或清理义务。如果只是把原实现转调出去，且读者需要更多跳转，应缩小或取消该提取。

## 5. P0：基线、行为复现与方案校准

1. 记录当前源码与工作树，运行一次完整本地 `verify`，建立真实基线。已有失败单独记录和处理，不删除断言或降阈值。
2. 逐项核对 P1–P5 的生产调用方、测试入口、事件和资源释放者，形成专用验证矩阵到真实方法的映射。
3. 先用可控 Task 复现两项风险：干净单页在命令排空期间出现修改；备份初始化成功后恢复确认抛异常。前者检查关闭许可和重试，后者检查未发布对象、View、Scope 和登记残留。
4. 对已存在的范围关闭回归作对照；确认缺陷的测试应在旧实现失败、最小修复后通过。等价重构保护测试则应在调整前后都通过，二者证据分开。
5. 核对保存警告和关闭判断的现行差异：主文件已提交、AcceptChanges 异常、备份失败、明确新增修订分别建例。磁盘保存成功与是否可以关闭分开表达，不为统一流程把这些状态混为一个成功标志。发现契约/实现冲突时在缺陷条目说明裁决依据与影响，不暗中改变全体入口。

P0 不要求预先创建所有未来测试文件或架构接口，也不把正常的多个关闭阶段简单压成一个 bool。

## 6. P1：关闭规则统一与旧链清理

### 6.1 设计思路

单页、整窗和应用退出都需要回答相同问题：哪些修改获得了保存或放弃许可，目标是否完成在途命令，结束时是否仍有未获许可的待保存内容。窗口范围、同步回调和关闭重入是不同协议，应继续由各自适配层处理。

在现有 DocumentCloseCoordinator 内先提取最小共享决策步骤，不要求新增协调器类型。将结果表达为明确的允许/拒绝和已授权放弃的目标集合；只有需要区分额外状态时才增加小型记录。复用现有 DocumentCloseApproval，不创建通用关闭事务。

### 6.2 处理顺序

1. 将“确认与保存”和“排空后的最终检查”收口；确认过放弃修改的目标按精确身份保留，许可不扩大到其他文档或后来新增的范围。
2. 单页保留同步无等待快速路径；需要等待时先否决，再按原协议重试。不得强制所有干净页面异步重入。
3. 保留 V16 单页等待期间变成浮窗最后一页时的精确许可接续，不能直接用公共范围入口替换单页入口而引入自拒绝或扩大授权。
4. 原生关闭被拒绝、目标改变或发生异常时，撤销许可与临时命令关闭门；最终 Document ClosingToken 与 Scope 释放仍只发生在真正关闭阶段。
5. 将旧 VM/Session/Coordinator ConfirmWindowCloseAsync 和 HasDirtyDocuments 链上的有效测试迁到现行准备关闭入口；确认没有生产调用后删除旧入口及仅服务于它的状态。每个删除测试都要能找到保留下来的行为断言。

### 6.3 完成标准

同一保存及最终复查规则只有一个实现。未获放弃许可的新增修改阻止关闭；取消、警告、原生否决和单页转整窗的精确范围均有测试。关闭门、Scope 所有权与同步快速路径保持，旧链不因测试引用而继续保留。

## 7. P2：待发布文档的完整回滚区间

### 7.1 设计思路

Session 已经是工作区资源所有者，本轮不改变这一点。需要收敛的是调用链对“创建成功但尚未发布”的回滚责任：从获得候选到成功发布之间，无论遇到等待、拒绝、异常还是目标失效，都要回到同一个 ReleaseDocument 入口。

先为恢复确认补上完整 try/finally，完成最小修复。再评估是否以一个局部待发布句柄承载回滚动作：未成功转交时 Dispose 回滚，成功发布后解除；它不创建 Scope、不持有 Provider、不替代 Session 的进程退出兜底。若直接 try/finally 已清楚覆盖全部路径，不为形式增加类型。

### 7.2 实施边界

- 覆盖新建、主文件打开、备份初始化、确认等待、恢复登记、Dock 插入及部分插入失败；不能只包住 PublishDocument 调用。
- 发布到原请求目标，保留 V16 来源窗口/分组复查与 V18 精确创建意图，不在主窗口先发布再搬运。
- 明确回滚异常与原始异常的政策：原失败保留，清理失败按现有诊断/聚合机制记录；重构不得无意改变异常优先级。
- 恢复拒绝、确认异常和发布失败均不修改损坏原件或备份；成功恢复继续要求另存，保持 RequiresSave、路径查重和修订语义。
- 在途文档操作仍由 DocumentOperationGate 排空；不能让局部回滚句柄与关闭流程竞争释放正在初始化的对象。

### 7.3 完成标准

确认异常不残留未发布文档、路径/恢复登记或额外事件订阅；每个失败阶段最终释放一次，成功发布对象继续存活。无需由多个方法约定“调用下一层后谁把 pending 清空”。

## 8. P3：命令事实与 Handler 绑定分离

### 8.1 目标依赖

```text
Host 描述 + PluginRegistry → WorkbenchCommandCatalog（纯描述与身份）
组合根 → 固定 Host Handler 映射 → 状态查询 / Executor
状态查询 + 当前 Context + 目标约束 → 本次可执行判断
Executor → 原 Handler 或原 Document Target
```

Host 命令目录只保存 ID、Descriptor 及现有路由需要的纯值事实。状态查询与 Executor 借用同一份明确 Handler 映射，目录不保存实例、Provider 或延迟解析 Provider 的委托。继续复用 IHostWorkbenchCommandHandler，不建立第二执行器。

### 8.2 实施要求

1. Host 元数据独立于 Handler 构造；合并目录完成身份冲突校验时，Workspace、窗口、插件 View/模型和 Document Scope 创建计数为零。
2. Handler 在现有 UI 组合边界明确绑定；检查注册身份与 Handler 一一匹配、无缺失/重复，错误必须早于正式工作台交付。
3. 先证明目录确为无 UI 依赖，再调整 HostRuntime 的校验时机。发生失败时仍走现有组合回滚，保留原稳定诊断、冲突顺序和资源登记语义。
4. Handler 的 CanExecute 和实际执行保持原逻辑；命令完成通知、租约释放、全局排空、插件目标校验顺序保持。
5. V18 的 ExpectedTarget（PageId/Revision）必须穿透原执行链；普通菜单/快捷键仍按其原当前目标语义工作，不能把 Palette 捕获的目标保存在共享 Handler 中。

### 8.3 完成标准

可独立构造、合并和校验目录，不需要建立工作区或窗口。Handler 创建仍在明确时机；注册绑定错误在交付前失败；菜单、快捷键、Palette 执行与关闭回滚没有行为回退。

## 9. P4：元数据查询直达与单项实时判断

DocumentCreationMenuQuery 直接消费 WorkspaceCatalog 与现有可用性事实，删除仅转发元数据的 Session 方法；只有真实工作区状态仍通过 Session 查询。

为功能身份有效性和页面可激活性提供窄查询：功能按 DocumentTypeId 与 CreationIntentId 检查原声明；页面按 PageId 检查拥有、已发布、实际挂接、关闭与插件可用性。复用已有集合和判断，不能把完整 ReadDirectory/GetOpenPages 包装到新方法中假装完成。

需要完整列表时继续使用现有短命 WorkspaceLayoutQuerySnapshot。窄查询不新增跨事件缓存、后台索引、失效协议或第二份文档目录；不承诺未测量的复杂度等级或耗时改善。

执行前复查、等待后复查和 V18 目标约束仍保留。分类路径解析与受控诊断留在展示目录构建边界；查询调整后核对首次诊断时机和同类去重，不让业务存在性判断反复触发展示副作用。

完成标准：单项判断无需构建完整分类树或全部页面展示记录，返回值与现行身份/可用性规则一致；重复读取不创建插件对象、不改变布局或发布事件。

## 10. P5：工具入口与提交步骤收敛

保留两个明确意图：OpenTool 负责显示、展开或定位原实例，SetToolVisibility 负责请求可见性。HideAll 保留独立批量结果，部分成功不能变成全有或全无事务。

在现有 Session/ToolDockCoordinator 内共享必要的查找、恢复和隐藏步骤。业务入口统一返回 ToolOperationResult；只服务内部协议的 bool 可以保留，但名字和调用范围必须明确，不能让调用方猜测 false 是已满足、拒绝还是失败。被删或收窄入口的测试改测对应业务行为。

必须保留自动收起预览、最小化浮窗恢复、原位置回停、CanClose 和原生取消、同实例 View/模型、成功访问记录及焦点交还。仅定位已有工具也可能需要记录访问和改变焦点，不能因为可见状态不变就跳过整个 OpenTool。

布局批次仍由既有机制控制，成功提交才通知；HideAll 汇总一次最终通知并保留逐项结果。不得通过新增通用操作枚举和大型 switch 把所有工作区动作塞入同一方法。

完成标准：对外用例边界清楚，同一恢复/隐藏规则不重复维护；各入口结果、事件次数、访问记录和取消后的实例身份均有回归证明。

| 关闭公共步骤 | 为何确认后还要排空和复查；精确放弃许可的范围；同步快速路径与重入的原因 |
| 待发布回滚 | 回滚区间从哪里开始、何时结束；成功转交条件；异常与关闭同时发生时谁最终释放 |
| 命令绑定 | 为何目录不能持有 Handler；何时创建 Handler；为何绑定必须在交付前完整校验 |
| 窄查询 | 返回的是当次事实；为何展示快照不能授权执行；哪些身份和关闭状态需要重查 |
| 工具提交 | 定位与显隐的差异；已满足结果如何处理；原生否决与通知的提交点 |

注释与实现同次审查，过期注释同步删除或修正。详细设计集中保留在本文及 Host 设计文档，代码中不粘贴阶段日志、测试数量和历史讨论。
