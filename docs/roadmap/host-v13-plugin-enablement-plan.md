## 1. 目标与实施边界

用户在现有“插件看板”中设置某个插件下次启动是否启用。设置成功后立即持久化，当前会话继续使用启动时的插件集合；完整退出并重新启动 Host 后，才按新设置决定是否加载。

必须实现：

- 新安装且未配置的插件默认启用；按稳定 PluginId 保存选择，版本更新及部署目录改名不重置选择。
- 禁用插件在下次启动时不加载入口 DLL、不创建插件加载上下文、不构造模块或私有 Provider、不执行 Configure 和生命周期。
- 禁用插件仍显示在看板中，可以重新启用；启用表示下一次尝试正常加载，不承诺兼容预检或初始化一定成功。
- 分别显示当前运行状态、下次启动设置和待重启提示；用户改回本次启动的设置后取消待重启提示。
- 插件开关不删除部署文件、业务数据、文档文件或布局及收藏偏好。Host 自带管理入口保持可用。

本轮涉及 Host 内部设置、发现、看板、诊断与测试。Plugin SDK、业务插件接口和清单格式保持兼容，已有插件无需为开关功能重新编译。第一版由用户手动重启 Host，不增加自动重启、安装更新、热启停、依赖级联禁用或新的插件管理框架。

不使用 AIFLOW，不读取或维护 `.aiflow` 流程上下文。不运行 Windows CI、`seal`、发布 Windows Smoke、发布覆盖率或发布重复性门禁；这些保留到实际发布阶段。本轮开发只用本地专项测试和现有 `verify`，不上传包、不发布、不部署安装目录，也不修改发布门禁政策。

## 2. 首要规定：SOLID 与朴素设计

SOLID 是设计、实施和审查的首要规定。每个新增组件都应解释：为什么独立变化、谁调用、谁拥有状态、有什么副作用、如何验证。以职责清楚和影响范围可控衡量设计，不以接口、模式或文件数量衡量。

| 原则 | V13 具体约束 |
| --- | --- |
| SRP | 设置存储只负责校验及持久化；开关服务拥有已保存意图；发现负责启动过滤；查询组合事实；ViewModel 组织交互。UI 不直接写 JSON，存储不调用加载器 |
| OCP | 所有插件走同一 PluginId 规则，不为示例或业务插件写特判。新增展示状态只调整对应投影，不改生命周期执行器 |
| LSP | 原有查询仍无副作用；启用插件沿用预检、失败隔离与退出协议。新增实现和测试替身保持相同成功、失败与取消语义 |
| ISP | 保留只读 IPluginStatusQuery；新增窄开关操作端口，不把写配置塞进查询接口。仅在真实替换及跨职责边界使用接口 |
| DIP | ViewModel 依赖窄查询与操作端口；发现接收冻结的启动配置。HostRuntime 负责组合，不通过全局服务定位器或任意 IServiceProvider 解析设置 |

使用普通 sealed 类、不可变记录、显式方法调用和现有 MVVM 命令即可。复用现有发现、Registry、生命周期与诊断机制，不引入通用中介者、事件总线、策略注册系统、泛型事务框架或自建插件状态机。

### 2.1 中文注释与设计思路

新增及实质修改的核心类型、方法、重要分支使用详细中文注释：

1. 类型 XML 注释说明用途、状态所有者、输入输出、依赖方向和不承担的职责。
2. 方法说明前置条件、线程及取消约束、持久化提交点、失败时保留什么；不能只逐句翻译代码。
3. 明确解释为什么在 DLL 加载前过滤、为什么保留未加载清单、为什么不能用 IsAvailable 推断禁用。
4. 对启动快照、进程缓存、保存失败、跨实例冲突和迟到 UI 回调写出设计思路，并链接或对应到行为测试。
5. 注释随代码和测试同步更新，不能保留“看板绝不修改设置”等已失效说明，也不能把规划写成现有能力。

## 4. 行为契约与状态所有权

### 4.1 三类事实分别拥有

| 事实 | 权威所有者 | 可变时机 |
| --- | --- | --- |
| 本次启动采用的启用策略及候选处理结果 | PluginDiscoverySnapshot 中的冻结数据 | 仅本次启动发现时形成 |
| 当前加载、初始化和可用性 | 原 Registry、PluginAvailabilityReadModel 及诊断 | 沿用现有运行及关闭流程 |
| 下一次启动的用户选择 | 开关服务中最后成功持久化的设置快照 | 保存成功后更新；失败不提交 |

待重启由启动策略与已保存意图比较得到。加载失败、初始化失败、退出中的插件都不因此被标为“用户禁用”。查询及 UI 不建立第二套运行状态。

| 本次启动设置 | 已保存的下次设置 | 展示与行为 |
| --- | --- | --- |
| 启用 | 启用 | 显示真实运行状态，无待重启标记；失败时仍允许设置禁用 |
| 启用 | 禁用 | “待禁用，重启后生效”；当前页面、后台服务和贡献继续按既有规则运行 |
| 禁用 | 禁用 | “已禁用，未加载”；属于正常用户选择，不计入异常数量 |
| 禁用 | 启用 | “待启用，重启后尝试加载”；当前会话仍不创建插件对象 |
| 读取配置失败而未采用有效策略 | 未知 | 显示配置错误与“本次未加载”；不伪装成用户禁用，也不计算正常待重启状态 |

### 4.2 身份与启动顺序

启动顺序固定为：读取设置 → 扫描及严格解析 manifest → 检查全局重复 PluginId → 保存候选身份 → 过滤禁用项 → 对启用项执行原兼容/目录/程序集/类型预检 → 原 Catalog、Provider、Registry 和生命周期流程。

- 保留现有重复 PluginId 致命歧义规则，包括处于禁用列表的重复身份。插件开关不承担修复重复安装的职责。
- 已验证 manifest 的候选即使 DLL 缺失、SDK 不兼容、注册或初始化失败，仍有可靠身份，可以设置下次禁用。
- 无法通过清单读取取得可靠 PluginId 的候选继续显示原诊断，禁用开关不可操作；不按目录名猜身份。
- 禁用项不执行 SDK 兼容评估或 DLL 预检；看板可展示清单声明范围，但不能声称“已兼容”或“已验证”。
- 所有贡献类别都通过“未进入原注册流程”自然缺席，包含 Document、Tool、Command、Placement、Icon 和 Workflow Action；不在每个菜单或创建入口追加零散禁用判断。

### 4.3 启动缓存与运行中修改

现有 RootSnapshots 只按插件根缓存，需要显式纳入所用 Host 数据根，防止不同数据配置误共用开关结果。建议以规范化的“插件根＋数据根”作为进程内发现键，缓存首份启动快照；配置内容或修改时间不进入缓存键。

同一键重复发现返回本次实际启动事实，不重新读取开关、不生成另一套插件加载上下文。运行中保存、刷新看板、重开窗口和检查产物均不得调用 Discover 或清理加载缓存。看板使用缓存快照携带的真实启动策略，不把后来读取的文件冒充启动事实。

测试使用独立数据根和插件目录验证隔离；真正的“重启生效”还必须用新进程证明，不能清空静态缓存后将同进程测试称为重启。

## 5. 最小内部设计与持久化

候选名称用于说明职责，不构成公共 API；实施时只增加有真实职责的类型。

| 组件 | 职责及依赖 |
| --- | --- |
| PluginEnablementSettings / 启动策略记录 | schema、禁用 ID 集合及明确的读取状态；集合防御性复制，不包含插件实例 |
| PluginEnablementSettingsStore | 严格读取、原子保存、有效备份及写冲突检查；只使用文件系统和配置数据 |
| PluginEnablementService 与窄操作端口 | 接受某个 PluginId 的下一次启用意图；保存成功后发布新设置快照，返回可展示结果 |
| 发现候选记录 | 已验证 manifest、规范目录、启动处理结果；不通过伪造 Assembly 或错误诊断表示禁用 |
| 扩展 PluginStatusQuery / PluginStatusItem | 合并候选、原运行事实和已保存意图，去重并生成筛选、统计、待重启状态 |

### 5.1 存储位置与格式

新文件为 Host 数据根下的 `plugin-enablement-v1.json`，默认位置为 `%LocalAppData%/MyAvaloniaManagement/v2/`；环境变量覆盖时直接使用既定完整数据根。示例仅展示规划格式：

```json
{
  "schemaVersion": 1,
  "disabledPluginIds": [
    "myavalonia.plugin.my-plug-test"
  ]
}
```

使用 SDK 已有 PluginId 规则，采用精确身份比较。保存时去重并排序；严格拒绝非法身份、重复 JSON 字段、不支持的 schema 和结构损坏，限制文件大小及集合规模。尚未安装或暂时移走的插件 ID 继续保留；启用某项只移除该 ID，不能重建为“当前可见插件列表”。

配置作用域跟随 Host 数据根；共享数据根的多个安装实例共享用户意图。需要独立选择的开发/测试实例使用已有环境变量隔离，不新增第二套配置层级。

### 5.2 保存与失败规则

1. 新文件和备份都不存在时视为首次使用，默认全部启用。仅备份存在时按恢复路径处理，不误判首次使用。
2. 写入采用同目录临时文件、flush、原子替换及上一有效备份；成功替换是持久化提交点，只有提交成功才更新已保存意图。
3. 写入及清理失败返回受控诊断；未提交时保留旧文件、旧快照和原开关位置。提交后清理失败单独提示，不把已提交结果误报为未保存。
4. 同进程写入串行化；跨进程使用短时文件锁，并在锁内核对读取时的文件修订身份。发现外部修改时拒绝覆盖，提示重新读取后再设置，不做通用设置合并框架。
5. 主文件损坏时保留原件；若存在有效备份，可按备份作为本次启动策略并明确告知，但在修复前禁止覆盖原件。未知未来 schema 不回退旧格式备份，更不能覆盖。
6. 无可靠配置可用或权限阻止读取时，Host 继续提供管理界面，本次暂停全部插件加载，展示配置错误并禁用设置写入。不得回退成全部启用；维护者按专用指南修复文件后重启。
7. 保存期间禁用重复操作，防止过期异步结果覆盖新选择。窗口关闭不损坏已提交设置；窗口释放后的结果不得访问控件。无需文件监控或后台轮询。

读取状态、备份恢复和用户禁用必须是不同事实。诊断使用固定中文文案和错误码，沿用已有脱敏机制，不复制个人路径、原始异常或任意插件文本到导出摘要。

## 6. 看板与关联行为

- 在现有“概览”中增加“下次启动启用”开关，旁边显示当前运行状态和保存反馈；成功后提示“重启 Host 后生效”。
- 增加“已禁用”和“待重启”筛选。前者依据本次启动确实因用户设置跳过加载，后者依据有效启动策略与已保存意图的差异；两者允许重叠。
- 已发现数量包含禁用候选；禁用本身不增加异常数。异常仍依据独立诊断和运行失败判定，不能因为禁用而隐藏真实配置或产物错误。
- 刷新、关闭重开、重新激活、搜索和筛选保留已保存选择与稳定选中项。无法识别身份、配置只读、Host 退出中或保存中时，按钮禁用并说明原因。
- 复制诊断及导出摘要分别写出当前运行状态、下次设置及待重启情况，不能让读者把“待禁用”误解为当前已停止。
- 未加载候选的产物检查复用 PluginArtifactReader，只读取文件及 PE 元数据。展示“已检查磁盘产物，本次未加载”，不使用现有“已核对当前会话加载程序集”的文案；导入历史报告不能覆盖禁用事实。
- 重启后禁用插件的贡献不进入菜单、功能中心、工具中心的可用目录及工作流目录；已有工作流引用按现有“动作不存在/不可用”失败，不删除定义或暗中重新启用提供方。
- 保留缺失工具的布局、显示意图和收藏；重新启用后沿用现有布局恢复。Document 不因本功能跨启动自动恢复，用户文件继续保留。
- 正常退出沿用现有未保存文档确认与生命周期清理。当前会话点“禁用”不关闭文档，不停止后台任务，也不撤回贡献。
