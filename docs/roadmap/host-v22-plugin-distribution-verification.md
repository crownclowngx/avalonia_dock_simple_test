# V22：Host 插件源与安装升级专用开发验证计划

> 用途：为[V22 方案](host-v22-plugin-distribution-plan.md)提供可实施的测试矩阵、本机开发门禁和文档验收范围。
> 状态：随 V22 已暂停（尚未实施）；暂停日期：2026-09-22。以下矩阵保留供恢复后重新核对，不作为当前执行任务；用例编号不是已有测试名称，不表示已执行通过。
> 约束：SOLID 优先、模式朴素、详细中文注释；不使用 AIFLOW、Windows CI、seal、发布 Windows Smoke、发布覆盖率或发布重复性门禁。正式发布时沿用原发布要求，本计划不授予发布资格。

## 1. 测试分层与证据原则

- Host Unit：配置读写、目录解析、版本/来源决策、下载控制、ZIP 验证、日志转换与恢复判定。纯规则用数据驱动单测；文件提交必须使用真实隔离目录，不只测试 mock 调用顺序。
- Host Plugin：标准 ZIP、加载预检、禁用保留、生命周期确认、启动前事务；同根多实例、进程退出和中断恢复使用真实子进程夹具。
- Host Headless UI：插件看板、源编辑与状态投影、取消/错误/重启交互；真实桌面可用性单独人工验收。
- Gate 工具自测：仅在开发编排或证据接入发生变化时增加，保证缺输入、零发现、跳过、超时和不完整 TRX 不会被误判通过。
- 文档：JSON 示例语法/字段对齐、路径链接、嵌入帮助读取与渲染；不能把文档专项通过记作安装事务验收。

测试只操作夹具拥有的暂存安装根/数据根；不修改真实 `%LOCALAPPDATA%`、用户 `Controls`、远端目录或 Release。网络单测使用可控 HttpMessageHandler；协议集成使用本机测试服务，HTTP 例外只存在测试注入，不进入生产源配置。

并发/超时用可控制信号和时间边界，不以固定 sleep 推断成功。故障注入放在窄的文件提交/移动边界，不建立通用虚拟文件系统。子进程在 finally 中负责其自身资源，不能按进程名称批量结束真实 Host。

## 2. S：默认源与持久化

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| S01 | 首次默认初始化、默认 Gitee 文件为空 | 默认使用方案中确定的完整 Gitee Raw URL，且只初始化一次；远程内容为空不阻止订阅持久化；首次保存失败有明确反馈 |
| S02 | 编辑 URL/名称/优先级/启停后保存，重新创建服务和进程 | 与磁盘已提交内容一致，Host 升级默认值不覆盖用户值 |
| S03 | 删除默认、全部删除、显式恢复默认 | 空数组持久化且不自动补回；恢复仅在明确操作后发生 |
| S04 | 非法/重复 ID 与 URL、HTTP、凭据、fragment、字段/schema/大小边界 | 严格拒绝且原配置字节不变；URL 规范化不破坏路径和查询语义 |
| S05 | 主文件损坏/缺失、有效备份、双损坏、未来 schema、读取拒绝 | 按方案恢复或停止远程功能，不自动重置；本地管理仍可用 |
| S06 | 写入失败、替换前失败、文件锁占用、修订冲突、提交后清理失败 | 不半写、不误报提交结果；重读后可继续，备份与原件符合策略 |
| S07 | 切换/删除源时旧响应晚到；看板关闭后返回 | 旧代次不能覆盖新缓存/窗口；已接受下载仍使用固定快照 |

## 3. C：目录、聚合与候选决策

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| C01 | 单源多插件多版本、合法 `plugins: []` | 完整解析，必填与可选默认正确；无文件/加载副作用 |
| C02 | 非空非法 JSON、`{}`/`[]`/`null`、缺必填、重复/未知字段、未知 schema、超深/超大、条目超限 | 整份新响应拒绝，不当作空源，不用半份数据覆盖有效缓存 |
| C03 | 非法 PluginId/版本/区间/时间/URL/摘要/长度、源内重复 | 有可定位的受控错误；不靠文本排序或猜测纠正 |
| C04 | `1.9.0` 与 `1.10.0`、SDK 下界和上界、不同 RID | 按数字比较；下界包含、上界排除；无隐式 RID 回退 |
| C05 | 跨源同 ID、同版本同摘要；摘要/大小/SDK 冲突 | 正常去重保留来源；冲突候选不能被优先级静默覆盖 |
| C06 | 未安装与已绑定来源插件、改 URL/禁用/删除原源 | 初装跨源选择；升级保持来源身份，切换必须显式发生 |
| C07 | 撤回、跨源撤回意见不同、降级与历史版本 | 撤回影响正确；不经镜像绕过，不自动降级 |
| C08 | 单源超时/404/HTML/无权限、部分失败、全部失败 | 独立状态与过期标志，其他源继续；不影响已安装插件启动 |
| C09 | ETag/304、非空/有效空缓存、缓存缺失/损坏、URL 变化 | 304 复用对应有效快照，不因无正文清空；无有效缓存时重取；缓存按原始配置 URL 与源身份隔离 |
| C10 | 并发上限、取消、Gitee HTTPS 跨域重定向、环/超限/HTTPS 降级 | 请求有界，取消及时；允许文件分发域名重定向，临时签名地址不回写配置/来源/缓存键；晚到结果不回写 |
| C11 | 离线与过期缓存 | 可查看，禁止用未刷新的候选发起远程安装；本地安装/回滚可用 |
| C12 | 完整成功响应为 0 字节、JSON 空白、仅 UTF-8 BOM 或 BOM 加空白 | 均为有效零插件快照，显示“暂无可用插件”；不编造远程 sourceId/updatedAt；纯空白仍受大小限制 |
| C13 | 非空目录之后返回有效空正文；空正文之后填入合法目录 | 成功刷新覆盖旧候选，随后可重新发现插件；不卸载本地插件，不删除订阅或影响其他源/待应用操作 |
| C14 | `text/plain` JSON/空正文、非空登录页 HTML | 前两者按内容成功解析/归一化，不硬性要求 application/json；HTML 拒绝 |
| C15 | 404/500 空正文、超时/取消/截断、未请求的 206 | 失败或不完整响应不冒充有效空目录，保留旧缓存及错误状态 |

## 4. P：下载、ZIP 与静态验证

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| P01 | 已有标准 ZIP、带私有/原生依赖、可选 build 文件 | 沿用 `Controls/<单插件>/`；无新包格式或作者发布工具前提 |
| P02 | 截断、大小/摘要不符、错误页、取消、停滞、超时、空间不足 | 不形成 staged，活动目录不变；临时文件可追踪清理 |
| P03 | 有序镜像、网络失败换源、镜像摘要不符 | 次数有界；哈希冲突明确失败，目标版本不改变 |
| P04 | 多插件包、错误层级、额外顶层文件、缺 manifest/DLL/deps | 拒绝，不扫描猜测或执行插件 |
| P05 | 绝对/穿越/UNC/驱动器/ADS/设备名/尾点空格/重复大小写路径 | 暂存根外零写入；目标 Windows 名称语义一致 |
| P06 | symlink/reparse、恶意预置父目录、条目/解包字节超限 | 拒绝链接和逃逸；按实际流式写入限制，清理不越界 |
| P07 | 目录与 manifest 的 ID/版本/SDK 不一致、程序集版本不符 | 不能提交安装；同一兼容规则用于展示和最终验证 |
| P08 | 禁带共享程序集、损坏 PE、错误入口或依赖布局 | 沿用现有 RuntimeProfile 及预检诊断，不复制规则 |
| P09 | 本地 ZIP，无目录/无网络 | 同一路径校验；来源 local，实际哈希不冒充发行方认证 |
| P10 | 校验与应用之间候选被修改 | 应用前重算摘要并拒绝；不加载被替换载荷 |

## 5. T：磁盘事务、占用与恢复

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| T01 | 首装/升级/卸载/回滚成功 | 只改目标插件目录；状态区分运行、磁盘、待应用；其他载荷与用户数据不变 |
| T02 | 下载取消、取消 staged、窗口关闭、退出准备取消 | 取消语义与所有权正确；取消重启保留 staged，不提前移动活动文件 |
| T03 | 同根多操作竞争、同根不同数据目录/进程、不同插件根 | 未完成操作唯一；共享根共同互斥，不同根隔离 |
| T04 | runtime 读租约、独占申请失败、锁文件残留、进程崩溃 | 使用 OS 持有状态判定占用，不强杀、不超时强行替换 |
| T05 | 独占应用后取得共享租约的竞争窗口、锁顺序 | 重新读取实际状态；无死锁或旧快照加载 |
| T06 | 日志提交前后、旧目录移动前后、新目录移动前后中断 | 每个持久化边界单独注入，重启恢复旧载荷或确认有效状态，不留下半安装扫描 |
| T07 | awaitingStartup 后退出/强制终止、登记更新与 committed 之间中断 | 未确认事务恢复旧载荷和旧登记；重复恢复幂等，不将登记写入当成功确认 |
| T08 | 日志/登记/备份/候选缺失损坏或未知 schema、外部修改 | 保留现场并停止不确定的自动覆盖；恢复界面不依赖业务插件 |
| T09 | 写权限不足、跨卷不可移动、空间不足、目录占用 | 应用前尽可能失败；移动中失败有恢复路径，不提权、不换发现根 |
| T10 | 手工目录接管、旧目录名、同 ID 多目录、原无 ZIP | 明确接管、完整基线和备份；冲突不处理，未知包摘要为 null |
| T11 | 确认后备份清理失败、超过保留数、卸载恢复 | 新提交不误报失败；上一已确认备份可用，只清理自身记录的路径 |
| T12 | 安装根或 staging/backup 被替换为链接 | 操作及恢复前复查规范化路径和链接，不能越界移动/删除 |

真实文件测试断言目录内容和摘要，真实进程测试断言退出、锁释放、后继 Host 输入及结果。文件移动应使用测试拥有的真实同卷临时目录；不得只根据某个 mock 被调用就判定回滚成功。

## 6. L/U：生命周期、重启和界面

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| L01 | 新进程应用顺序 | 任何发现缓存、ALC、模块构造前完成应用或恢复 |
| L02 | 无生命周期目标、Ready、初始化失败/超时、贡献不可用 | 成功条件准确；主窗口打开或进程创建不等于目标成功 |
| L03 | 禁用插件升级、卸载后恢复、历史禁用 ID 再安装 | 保留禁用身份，installedDisabled 不伪造运行验证 |
| L04 | 试启动取消/崩溃与首次安装失败 | 未确认恢复旧载荷/未安装状态，不记录虚假的兼容失败 |
| L05 | 加载后失败、恢复上一版并重启、再次启动 | 不在运行中换 DLL；每事务最多一次试启动，不循环重试 |
| L06 | awaitingStartup 的拥有者仍存活、PID 被复用 | 第二实例不加载未确认版本；PID 与启动时间联合验证 |
| L07 | 主窗/浮窗文档保存失败或取消、布局失败、退出失败 | 保持 V14 关闭否决和资源释放规则，安装意图与运行事实不混淆 |
| U01 | 零业务插件时打开看板、源配置、本地包安装 | 基础管理和恢复入口由 Host 提供 |
| U02 | 编辑/保存/测试连接失败、重开窗口、重启持久化 | 状态明确，无虚假已保存；测试连接不保存 |
| U03 | 搜索、旧版本、冲突、来源切换、无兼容包 | 安装按钮与解释一致，展示纯文本，不执行远程正文 |
| U04 | 下载进度/取消/失败、关闭看板、晚到结果 | 服务任务和窗口生命周期分离，已释放窗口不被访问 |
| U05 | 待安装/升级/卸载/回滚、稍后重启、取消待办 | 操作指向正确版本，同一安装根第二项操作有明确提示 |
| U06 | 坏配置、不可写安装根、损坏事务、断网 | 用户可理解原因，本地状态和可用操作准确 |

人工桌面验收使用本轮开发产物与隔离数据/安装根：从无插件启动、默认 Gitee 源空内容显示、添加/修改源、安装两个连续版本、保存文档取消重启、成功重启、禁用升级、断网本地回滚、卸载和恢复。第一版默认地址为 [Gitee Raw 插件目录](https://gitee.com/crownclowngx/avalonia_dock_simple_test/raw/master/plugin-sources-v1.json)，内容由维护者自行维护；零插件只证明读取和空状态，不代表安装/升级已验收。自动化使用受控响应保证可重复，实机访问记录实际 URL、响应状态及观察到的结果，不以假响应代替可达性结论，不为测试改写该远端文件。

| 编号 | 审查 | 完成条件 |

| A02 | 朴素模式与注释 | 锁顺序、提交点、版本身份、错误恢复有详细中文设计说明；无无需求的通用扩展框架 |
| A03 | 既有契约保持 | SDK public API、manifest v2、开关与布局格式不因分发自动升级；实际变化有独立证据 |
| D01 | 协议唯一权威说明与导航 | 当前/待实施状态准确，方案、专用文档、索引互链；实施后更新用户指南和当前契约 |
| D02 | JSON 示例、链接和嵌入帮助 | 所有示例可解析，字段与实施类型一致；本仓链接/锚点、实际嵌入资源读取及渲染通过 |
| G01 | 新用例被本机默认 verify 收集 | 每个矩阵项映射实际全限定测试名或人工项；零发现、跳过、超时和缺失报告不算通过 |
| G02 | 源码/产物/证据匹配 | 记录 HEAD、工作树差异、构建输入、DLL 和 TRX 身份；新源码不得借旧 --no-build 输出通过 |

新文件与进程用例优先加入现有测试项目，随既有 verify 运行。若特殊夹具确需新增单独测试阶段，在开发 Gate 内显式登记项目、过滤器、必需输入和成功证据；只更新必要编排与工具自测，不增加发布步骤。现有 MyPlugTest `Category=PackageAcceptance` 的“恰好一项”约束保持，新安装进程测试不能误归入该专用过滤器。

## 8. 执行顺序

### 8.1 本次仅文档时

检查本次变更 Markdown 的链接/锚点、JSON 围栏以及 `git diff --check`。由于仓库 Markdown 嵌入 Host，按现有文档惯例重建并执行帮助专项：

```powershell
dotnet test Host/MyAvaloniaManagement.Tests -c Release -m:1 -warnaserror --filter FullyQualifiedName~HelpContentTests --logger 'trx;LogFileName=v22-docs-help.trx' --results-directory artifacts/host-v22/docs-help
```

若现有本机依赖或固定补丁缺失，记录真实阻塞，不把未执行记作通过。除此之外不为方案文档运行完整插件安装矩阵或发布验证。

### 8.2 后续实际实施时

先核对工作树、SDK 和补丁输入，按[主仓验证](../maintenance/verification.md)准备依赖及构建。每个阶段修改后先构建该阶段真实输入，运行对应项目专项并保存独立 TRX；测试类名以实际实现为准，不使用本计划中的编号作为过滤器。

```powershell
# 完整实现并完成专项后，运行既有本机开发门禁。
dotnet run --project tools/MyAvaloniaManagement.Gate -- verify
```

需要单跑常规 Plugin 测试时按现行规则排除 `Category=PackageAcceptance`，包验收交给 verify 准备真实输入。每条命令失败即停止并保留原始结果；修复后按影响范围重跑，不能把不同构建的报告拼成一次通过。

不运行 Windows CI、seal、发布 Smoke、发布覆盖率/重复性，不创建 Release、上传包、改远程目录、部署真实安装目录或修改发布政策。

## 9. 实施证据与交付

实际实施时建立 `docs/archive/records/host-v22/` 的开发记录、测试映射和非嵌入 JSON；当前计划不提前创建“通过”记录。映射覆盖 S/C/P/T/L/U/A/D/G 所有编号，允许一个有效测试覆盖多个断言，但必须说明对应关系。

记录源码及未提交变更身份、实际运行命令、构建配置、发现/通过/失败/跳过数量、TRX 与必要产物摘要、故障注入位置、人工已观察/未观察项和原因。目录与 ZIP 人工维护、本地开发验证、实机体验、部署和公开发布分别记账，不把一类结果扩写为其他结论。
