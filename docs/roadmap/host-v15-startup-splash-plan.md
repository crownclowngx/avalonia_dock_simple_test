# V15：启动引导与插件加载进度方案

> 用途：规定工作台启动窗口、矢量羽毛形象、插件进度反馈、启动职责调整及验收条件。
> 状态：P0–P5 实现、专项与文档已接入；最终开发判定见[开发记录及证据](../archive/records/host-v15/development-acceptance.md)，原生桌面等范围独立待验收。日期：2026-09-20。
> 调研基线：`640202e10b6a1638383b345beaf3f174f3291375`；编写前工作树干净，实施前重新核对源码和已有差异。
> V15 是 Host 改造序号，不代表产品、程序集、SDK、NuGet 或持久化格式版本升级。
> 本文保留设计依据及验收目标；现行行为见[启动契约](../reference/host-startup.md)，实际类名、差异与验证结果见开发记录。

## 1. 目标与范围

用户打开 exe 后，在插件加载开始前看到一个轻量启动窗口，知道程序已经启动；加载过程中看到当前阶段、正在处理的插件及本阶段进度；工作台准备就绪后自动进入主界面。

启动窗口使用一枚矢量羽毛作为视觉主体，以轻微浮动表达程序仍在工作。加载事实来自现有宿主流程，不使用定时器伪造插件名称、成功状态或完成百分比。

本方案覆盖正常启动及 V14 自动重启后新 Host 的启动。重启助手继续在最早入口分流，正常等待时不显示启动窗口、不加载插件。

主要改动位于 Host 内部。第一版不要求插件实现新的进度接口，不改变 manifest schema 2、Plugin SDK、插件启用设置、Document 或 Layout 格式，也不增加热加载和插件内业务步骤进度。

“尽早显示”从 Avalonia 具备窗口显示能力时开始：操作系统创建进程、运行时启动和单文件解包等更早的耗时仍在窗口可见之前，不承诺双击后零延迟出现。实施时分别记录这段耗时和插件加载耗时。


### 1.1 本次实施要求

SOLID 为首要设计约束，按单一变化原因分配职责，使用窄端口和显式依赖。设计模式朴素使用，不引入通用事件总线、状态机库或第二套容器。核心代码使用详细中文注释，说明线程、取消、提交点和资源所有权；单元、插件集成、Headless 与真实子进程测试及本地 verify 完整覆盖，并同步专用验证文档和开发记录。

不使用 AIFLOW，不读取或维护其上下文；不使用 Windows CI，不运行 seal、发布 Smoke、覆盖率或重复性门禁。发布时再执行适用发布门禁。本次不部署安装目录、不发布包。

## 2. 矢量羽毛与窗口设计

### 2.1 羽毛形象

![V15 启动羽毛设计稿](assets/host-v15-startup-feather.svg)

素材：[原创 SVG 羽毛](assets/host-v15-startup-feather.svg)。图形由羽片轮廓、羽轴和少量羽枝组成，整体从左下向右上舒展；使用青蓝渐变、透明背景，无字体、位图、外部链接或脚本依赖。该文件是静态设计稿，运行时动画由宿主实现。

| 项目 | 设计约定 |
| --- | --- |
| 矢量画布 | `160 × 160` viewBox，支持任意 DPI 缩放 |
| 窗口内尺寸 | 建议 `72–88` DIP，初版使用 `80 × 80` DIP |
| 图形结构 | 一枚羽毛；羽轴清晰，羽枝保持简洁，缩小后仍可辨认 |
| 配色 | 青蓝为主色；运行时将填充和描边映射到宿主主题，确保浅色、深色背景均清晰 |
| 加载动画 | 约 2.4 秒一轮，上下浮动不超过 3 DIP，轻微摆动不超过正负 2 度，平滑往返 |
| 完成状态 | 停止循环，羽毛归位；主窗口准备完成即切换，不等待整轮动画结束 |
| 失败状态 | 羽毛静止，显示明确错误文本，不继续表现为仍在加载 |
| 减少动画 | 尊重可取得的系统动画偏好；无法取得时采用保守动画，关闭动画后仍能完整表达进度 |

优先将 SVG 路径转换为 Avalonia 原生 `Path` 与画刷资源，在宿主内嵌使用；装配动画时只修改变换等展示属性。若现有依赖已经具备 SVG 渲染能力，可复用，但不为这一枚图形新增大型动画库、浏览器或媒体运行时。第一版无需 GIF、视频或远程图片。

### 2.2 窗口布局

建议窗口约 `520 × 380` DIP，居中显示，固定大小，有明确的关闭入口，不设置为全局置顶。使用宿主自有的轻量颜色与基础控件，避免首屏依赖 Dock、插件主题或完整工作台资源。

```text
┌─────────────────────────────────────────────┐
│                                           × │
│                 矢量羽毛                    │
│               正在启动工作台                │
│                                             │
│  正在初始化插件                             │
│  myavalonia.plugin.example                  │
│                                             │
│  ━━━━━━━━━━━━━━━━━────────────              │
│  本阶段已处理 5 / 12 项                      │
│                                             │
│  ✓ example-a · 初始化完成                   │
│  ✓ example-b · 初始化完成                   │
│  ◌ example   · 初始化中                     │
└─────────────────────────────────────────────┘
```

上述插件标识与计数仅用于布局示意。主体信息固定为“阶段 + 当前插件 + 本阶段计数”，底部保留最近 3 条状态，避免展示完整日志不断滚动。文字过长时省略，提供完整文本提示；状态使用图标和文字共同表达，不能仅靠颜色。

扫描期间总数未知，进度条使用循环模式；阶段总数确定后显示真实计数。阶段切换时同步更新标签和计数，清楚表明进度属于新的阶段，不将它表现为总启动进度倒退。快速启动直接进入主界面，不设置人为最短展示时长。

## 3. 当前启动链与改动原因

当前源码中的关键位置如下。

| 组件 | 当前事实 | V15 调整方向 |
| --- | --- | --- |
| [Program](../../Host/MyAvaloniaManagement/Program.cs) | 先 `HostRuntime.Create()`，再进入 Avalonia 桌面生命周期 | 保留助手最早分流，正常启动先建立轻量 UI，再开始受观察的启动任务 |
| [HostRuntime](../../Host/MyAvaloniaManagement/Business/Composition/HostRuntime.cs) | 同步完成插件发现、组合及生命周期初始化，随后解析 `WorkspaceSession` | 拆分非 UI 组合与工作台装配，提供可等待、可报告进度的启动边界 |
| [App](../../Host/MyAvaloniaManagement/App.axaml.cs) 与 [HostAvaloniaBuilder](../../Host/MyAvaloniaManagement/Business/Presentation/HostAvaloniaBuilder.cs) | App 构造依赖完整 Shell、ViewLocator、回收器；工厂来自 Runtime 容器 | 解除启动首屏对完整 Runtime 的依赖，在同一 Application 中延后安装工作台资源 |
| [HostDesktopShell](../../Host/MyAvaloniaManagement/Business/Presentation/HostDesktopShell.cs) | 负责主题、主窗口及窗口入口绑定 | 在组合成功后执行，参与主窗口交接；保留窗口入口先于菜单绑定的顺序 |
| [AssemblyLoaderHelper](../../Host/MyAvaloniaManagement/Business/Plugins/Discovery/AssemblyLoaderHelper.cs) | 先校验清单身份，再加载启用候选；结果为进程内缓存快照 | 在实际扫描和加载边界报告进度，不额外扫描、不清除缓存 |
| [PluginProviderOwner](../../Host/MyAvaloniaManagement/Business/Plugins/Registration/PluginProviderOwner.cs) | 逐插件构造模块、注册服务、建立私有 Provider | 报告注册开始、完成和失败，保持隔离与释放责任 |
| [PluginLifecycleCoordinator](../../Host/MyAvaloniaManagement/Business/Lifecycle/PluginLifecycleCoordinator.cs) | 按既定顺序初始化生命周期并保存结果 | 报告当前插件和初始化结果，不重排插件、不增加并发初始化 |

因此，单纯在 MainWindow 内增加遮罩不能覆盖目前最主要的等待。需要先调整启动顺序，再接入展示。此次设计涉及组合根、线程边界及退出责任，不应作为一个纯 XAML 外观改动实施。

## 4. 启动顺序与职责

### 4.1 同一个应用与消息循环

正常启动拟按以下顺序执行：

1. Program 识别助手模式；普通 Host 建立必要的诊断、重启交接对象和轻量启动协调器。
2. 在主 UI 线程初始化唯一的 Avalonia Application，只加载启动窗口所需资源。
3. 显示启动窗口，让消息循环处理首帧；通过可验证的首帧/调度边界再开始耗时任务，不能仅调用 `Show()` 后立刻同步阻塞。
4. 执行配置读取、插件扫描与预检、服务组合、Registry 提交和生命周期初始化，持续报告阶段事实。
5. 回到 UI 线程，安装完整主题、ViewLocator 和回收器等工作台资源，完成工作区与主窗口装配；相关依赖按实测线程要求安排。
6. 显示主窗口，将其设为正式 `MainWindow`，确认窗口可见并具备基础交互能力后关闭启动窗口。
7. 正常退出仍由原有 Program、Runtime 关闭链和重启交接负责。

进程中不先运行一个启动 App、再创建第二个生产 App。启动阶段可采用显式关闭模式，窗口交接完成后恢复现有关闭策略，避免关掉 Splash 导致整个进程退出。切换失败进入错误展示，不留下已显示但未准备完成的主窗口。

### 4.2 最小内部设计

以下名称用于表达职责，正式实现可按现有结构收敛，不要求每一项建立独立框架。

| 组件 | 职责与所有权 |
| --- | --- |
| `StartupCoordinator` | 拥有本次启动任务、取消请求、启动终态与窗口交接；组织现有流程，异常必须被观察 |
| `IStartupProgressSink` | 宿主内部窄端口，接收不可变进度消息；加载器只报告事实，不依赖 Avalonia 控件 |
| `StartupProgress` | 携带阶段、插件标识、处理数、阶段总数、结果和可选错误码；不持有插件实例或 Provider |
| `SplashWindow` / ViewModel | 显示羽毛、进度和近期状态，将关闭意图交给协调器；不发现插件、不构建容器 |
| 现有 Runtime 与桌面 Shell | 分别保留组合及资源释放、主题及主窗口装配责任 |

组合根显式传递依赖，不通过静态全局容器解决启动依赖问题。进度通道仅属于一次启动；启动结束后停止接收展示消息并解除订阅，防止迟到消息访问已关闭窗口。观察者故障不能使插件被误判为失败，严重展示故障也不能被吞掉后留下永久等待界面。

### 4.3 UI 线程和后台任务

文件读取、清单解析、程序集预检等不依赖 UI 的工作可放入后台执行；控件创建、资源安装和绑定更新在 UI 线程完成，通过 Dispatcher 交接。Avalonia 的基本约束见[官方线程模型](https://docs.avaloniaui.net/docs/app-development/threading)。

不能把整个 `HostRuntime.Create()` 直接包进 `Task.Run()` 就视为改造完成：现有代码在组合末尾解析 `WorkspaceSession`，插件构造、注册及生命周期回调的线程假设也必须核查，包括 STA 或原生依赖。异步方法在首次真正挂起前的同步工作同样可能阻塞 UI，必须验证实际执行位置。

UI 线程不使用 `.Wait()`、`.Result` 或 `.GetAwaiter().GetResult()` 等待启动任务。沿用插件既定执行顺序；对不得不在 UI 线程完成的资源和工作台构建拆分耗时步骤，实测其阻塞时间，而不是承诺任意插件代码都能保持动画流畅。

## 5. 真实进度与插件名称

### 5.1 展示阶段

| 阶段 | 示例文案 | 计数规则 |
| --- | --- | --- |
| 准备宿主 | 正在读取启动配置 | 循环进度，不显示假百分比 |
| 扫描插件 | 正在扫描插件目录 | 清单清点完成前总数未知；可显示当前目录 |
| 加载插件 | 正在检查并加载 `{PluginId}` | 对本阶段启用候选计数；禁用、无效清单和全局身份冲突分别处理 |
| 注册插件 | 正在注册 `{PluginId}` | 对可进入组合的模块计数；注册成功不等于最终可用 |
| 校验贡献 | 正在检查插件贡献 | Registry 冲突和可用性按现有规则提交，不伪造逐插件成功 |
| 初始化插件 | 正在初始化 `{PluginId}` | 对实际生命周期待初始化项计数；未声明生命周期的插件不虚构初始化调用 |
| 准备工作台 | 正在准备主界面 | 资源安装、工作区恢复和窗口装配使用阶段文本 |
| 交接完成 | 工作台已就绪 | 只有正式窗口就绪后才完成启动展示 |

`Completed` 表示本阶段已取得处理结果的项目数，`Total` 表示本阶段总数；失败和跳过也有明确结果，不能称为“成功加载”。只有总数已知且大于零时计算本阶段进度。零插件、全部禁用或没有生命周期项时直接前进，不显示 `0 / 0`。

默认按阶段展示，不将“所有插件注册完成”混同于“所有插件初始化成功”。最终可用数量由现有 Registry、生命周期和诊断事实共同决定；启动窗口不另建一套插件可用性判定。

### 5.2 进度事件规则

建议记录字段为 `Stage`、`PluginId`（可空）、`DisplayLabel`、`Completed`、`Total`（未知时可空）、`Outcome`、`ErrorCode`（可空）及单调序号。阶段耗时由宿主时钟测量；消息只带受控展示信息，不传完整异常、敏感配置或业务数据。

每项操作在进入前报告“开始”，退出后报告“完成/失败/跳过”。耗时项目可以显示已等待时长，不能因长时间没有新事件自行宣布超时、成功或跳到下一个插件。进度动画只表达正在工作。

界面可将密集刷新合并到约每 50–100 毫秒一次，保证失败、取消及最终状态不会丢失，也不为每个瞬时插件强制停留。消费端按序号丢弃过时展示；完整诊断仍由现有日志和插件看板承接。

### 5.3 名称来源

当前 manifest 仅提供插件标识、版本、入口与 SDK 区间，没有友好显示名称。第一版优先使用稳定 `PluginId`；尚未读到有效清单时显示目录名。只有现有可靠元数据确实提供友好名称时才使用，并保留完整标识提示。

不通过构造插件视图获得名称，也不为显示名称提前执行插件代码。SVG 羽毛属于宿主启动资源，不从插件图标包动态取得。本版无需为启动文案升级插件清单或要求业务插件重新编译。

## 6. 失败、关闭与重启边界

| 场景 | 拟实施行为 |
| --- | --- |
| 单插件加载、注册或初始化失败，现有策略允许隔离 | 显示失败结果并继续；进入主界面后保留可见摘要和插件看板入口，不把短暂红字作为唯一反馈 |
| 致命诊断要求终止启动 | 停止加载展示，复用现有启动失败信息和日志定位能力，不创建工作台 |
| 已启动 Avalonia 后失败 | 在同一 Application 中展示最小错误界面；不得再次调用 `StartWithClassicDesktopLifetime` 启动另一个 App |
| Avalonia 尚未成功建立 | 保留可行的进程级诊断与已有错误兜底，不假设已经存在可用窗口 |
| 用户点击关闭或按 Alt+F4 | 接受一次取消请求，显示“正在停止启动”；停止进入后续步骤，按原所有权链收尾后退出，不继续弹出主窗口 |
| 取消遇到不可中断的同步调用 | 如实保留“正在停止”状态；取消是协作式请求，不承诺立刻中断插件构造、注册或原生代码 |
| 初始化超时或取消后仍有任务运行 | 沿用既有超时、取消宽限和资源保留规则；停止等待不等于任务已结束，不提前释放仍被使用的 Provider |
| 启动窗口关闭与成功完成发生竞争 | 由协调器提交唯一终态，关闭已被接受后不再交接主窗口，晚到进度不能反向改变结果 |
| V14 自动重启 | 助手仍无启动窗口；新 Host 普通启动显示羽毛窗口，失败不触发循环重启 |

当前生命周期默认初始化期限为 30 秒、关闭期限为 10 秒、取消宽限为 2 秒；这些事实来自现有协调器，V15 展示层不另设更短的强制跳过期限。同步代码尚未返回 Task 时，现有异步等待期限不能自动中断它，实施验证必须覆盖这一限制。

启动回滚和正常退出继续使用同一 Runtime 所有权链。协调器负责追踪任务，不能和 Program 各执行一套释放。取消、异常、日志释放结果及 `ResourcesRetained`、`Failures` 仍参与最终退出判定；[V14 自动重启契约](../reference/host-restart.md)中的清理成功和交接许可语义保持一致。

| V15-P3 窗口交接与收尾 | 完成主窗口接管、失败反馈、协作取消和唯一收尾 | 不发生双 App、误退出、晚到窗口或重复释放 |
| V15-P4 关联验证 | 验证插件开关、启动失败、正常退出、自动重启和外部插件线程兼容 | 自动化与实际桌面结果分别记录，问题可定位 |
| V15-P5 文档收口 | 更新当前架构、用户说明、专用验证和实施记录 | 方案与最终行为一致，开发完成与部署状态分别标注 |

实现采用简单的宿主内部类、不可变记录和窄端口，按职责注入；不引入通用事件总线或额外状态机框架。核心中文注释说明线程、终态提交、取消、回滚和资源所有权。

## 8. 验收标准

下表为验收目标；实际自动化映射及未执行的原生桌面范围见[专用开发验证](../maintenance/host-v15-startup-verification.md)。不得把自动化或源码支持等同于全部目标已人工验收。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| V15-A01 | 正常启动，使用可控慢插件 | 羽毛窗口先可见，再开始插件执行；等待期间 UI 可刷新 |
| V15-A02 | 多插件依次处理 | 当前插件、阶段和真实顺序一致；计数有定义且不把失败计为成功 |
| V15-A03 | 零插件、全部禁用、无生命周期项 | 正常进入工作台，无除零、虚构初始化或长期空白 |
| V15-A04 | 单插件可隔离失败 | 错误可见，其余项按现有策略处理，主界面能找到最终结果 |
| V15-A05 | 致命清单或宿主组合失败 | 同一应用显示失败信息，未显示半初始化主窗口，退出码和日志正确 |
| V15-A06 | 初始化超时及迟到完成 | 不误报成功、不访问已关闭 UI、不提前释放在用资源 |
| V15-A07 | 加载途中关闭，含成功竞争和重复关闭 | 取消只提交一次，不出现迟到主窗口，收尾不重复 |
| V15-A08 | 很快完成启动 | 不人为等待动画；窗口切换不触发应用退出或明显空白 |
| V15-A09 | 浅色/深色、125%/150%/200% DPI、长标识 | 羽毛清晰、文字和关闭入口可用；进度不单靠颜色表达 |
| V15-A10 | 动画减少/禁用 | 静态羽毛和文本仍完整表达当前阶段与结果 |
| V15-A11 | V14 旧 Host→助手→新 Host | 只有新 Host 显示启动窗口；普通退出不重启，启动失败不循环拉起 |
| V15-A12 | 外部插件、同步慢调用、原生/STA 依赖 | 明确线程兼容及取消限制，不以单纯 Task.Run 掩盖行为变化 |
| V15-A13 | 开发启动及已有单文件样本 | 记录进程启动到首屏、首屏到工作台时间；羽毛资源无需旁置文件 |

自动化重点覆盖进度规则、失败与取消竞争、所有权释放和窗口生命周期。原生桌面重点检查首帧可见、动画连续性、焦点、DPI 和重启体验；Headless 不能单独证明动画实际流畅。已有测试复用优先，新增测试围绕可观察行为，不为 SVG 路径坐标或文案镜像编写测试。
