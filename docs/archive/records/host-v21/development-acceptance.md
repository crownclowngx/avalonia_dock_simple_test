# V21 开发门禁与测试效能收敛开发记录

> 日期：2026-09-21。代码、专项与文档已落地；最终完整开发验收和源码身份以[非嵌入证据](development-evidence.json)为唯一状态来源。本记录不代表部署、发布或新增人工实机验收。

## 1. 实际改动

RestartHarness 的 Windows x64 测试副本从 260 个文件、约 597 MiB 收敛到 221 个文件、约 63.4 MiB。保留托管 PDB、apphost、deps/runtimeconfig 和当前平台 native 文件，去除其他平台运行文件、原生 PDB 及测试证据。增量构建删除已退出清单的旧文件；每例仍使用独立可写应用目录、Controls、数据根和故障注入。没有硬链接或共享可写模板。非 Windows 仍保留原运行资产，仅排除 native PDB 和证据，不宣称新增平台验证。

真实进程测试继续覆盖 15 个启动/重启场景，在原启动收据中增加实际加载的 Avalonia/Dock DLL 摘要，与当前测试输出核对。新增夹具测试检查必要文件、独立修改与字节收据。每例保存复制、场景、清理时间及清理残留状态；原有首帧/工作台就绪时间仍来自生产启动诊断。

UI 使用三个小方法表达 Dispatcher 排空、渲染推进和有界条件等待。控件模板/窗口布局等待明确就绪，异步关闭等待实际完成；动作只发送一次，不重试断言。帮助快速导航改用 reader 进入信号，20 轮关闭释放测试保留。工具中心两个工具的浮窗接线由每项三轮改为两轮，仍验证首次打开、关闭后再开、模型/View 身份与位置；第三轮未增加新状态。独立服务寿命测试仍保留八轮，二者保护的责任不同，不把八轮服务测试说成第三轮 Dock 操作的替代证明。

Gate 将空泛的执行图改为固定顺序计划，单仓快照直接传递；`host/all` 仍兼容完整本仓验证。开发顺序现在是补丁、还原、构建与必需 DLL 核对、契约/API、测试、打包、ZIP 验收。发布 profile 顺序和资格政策保持，源码消费路径不再过滤缺失 DLL。

TRX reader 读取一次字节快照，校验结构、必需非负计数、明细、唯一执行标识、运行结果和时间；Gate 单独判定完整通过及进程退出码。每轮 `tests/summary.json` 保存源码/run 关联、命令、过滤器、退出码、TRX 摘要、计数、耗时和慢用例。未执行、执行中、失败与通过明确区分。原 schema 2 汇总保持，附件进入本轮套件目录。

SDK 集中守护自己的旧类型和导出面；Host 保留自身旧类型及消费者构造依赖断言。活动项目扫描在进入目录前排除生成物、隐藏目录、链接和嵌套 Git 仓库，动态发现新增项目和模板。迁移详情见[测试去向](test-matrix.md)。

## 2. SOLID 与中文注释审查

- 夹具清单、复制、场景断言、UI 等待、阶段编排、TRX 解析与通过政策各自负责单一变化原因，未给业务代码添加测试入口。
- 使用具体类、不可变记录和普通委托；没有 DAG、策略注册、测试 DSL、第二容器或全局可变窗口缓存。
- 隔离、取消、窗口事件、范围确认、布局锁和子进程所有权保持。等待方法只推进必要框架时序，异常直接传播。
- 中文注释解释平台裁剪、旧文件清理、目录/进程归属、等待前提、计时口径及失败证据；不将机器秒数写进长期源码注释。
- 产品、程序集、SDK、NuGet、数据格式、补丁算法、API 分类及覆盖率阈值未改变。

## 4. 性能口径与限制

同机使用相同 SDK、Release、`--no-build --no-restore -m:1`、相同过滤器，实施前后分别取三次串行样本：真实进程 15 项与四组 UI 热点 88 项。全部原始值、中位数、计数和 DLL 摘要见非嵌入证据，不只报告最快一次，不反复完整 verify 充当微基准。

| 热点 | 实施前三次（秒） | 实施后三次（秒） | 中位数（前 → 后） |
| --- | --- | --- | --- |
| 真实进程 15 项 | 64.71 / 69.95 / 72.79 | 70.79 / 69.38 / 70.44 | 69.95 → 70.44 |
| UI 热点 88 项 | 53.70 / 51.94 / 68.69 | 40.68 / 42.61 / 43.56 | 53.70 → 42.61 |

UI 基线尚不识别通用附件变量，优化后热点采样撤去该变量，使两侧可选截图均关闭；完整 UI 专项与最终 Gate 另行验证附件开启路径。前后保持 Headless/Skia 配置、UI 串行和相同交互矩阵，只有已列明的重复轮次与等待改变。进程新版本增加身份核对与计时证据，比较的是实际方案整体成本。

复制量下降不等于同等比例的磁盘写入或启动提速；缓存、杀毒、后台负载和进程启动均影响墙钟。本轮没有控制系统后台负载，也未在旧实现加入逐次复制 Stopwatch，不能给出旧夹具复制时间的可靠中位数。优化后分项计时用于判断剩余成本，进程总耗时若没有改善则如实保留；不为追求百分比扩大到通用缓存或并行套件。历史完整 verify 仅作热点线索，不作为相同输入性能基线。
