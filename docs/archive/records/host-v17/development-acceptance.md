## 2. 实际文件与职责变化

原 `HostDiagnostics.cs` 分为 `HostDiagnosticContracts`、`HostDiagnosticCodes`、`HostDiagnosticRedactionPolicy`、`HostDiagnosticFailurePolicy`、`HostDiagnosticSession`、`HostSensitiveDiagnosticDebugOutput`、`PluginLoadExceptionMapper` 七份文件。契约中的枚举、记录及端口仍就近组织；会话继续拥有锁、记录与写入器，错误码到固定消息的映射表保持集中。

原 `WorkbenchCommandProjection.cs` 分为 `WorkbenchPresentationCommandStore`、`WorkbenchMenuProjection`、`WorkbenchKeyBindingProjection` 和 `WorkbenchCommandPresentation` 四份文件。菜单和快捷键的小契约跟随对应投影；Palette 与刷新调度器未迁移、未改造。创建与释放仍由既有组合对象负责。

`AddApplicationServices` 从 232 行变为 39 行（方法声明至结束，含空行/注释）。共享所有者仍在入口选定，十一组私有方法依次登记服务，WorkspaceCatalog 的简单合并工厂留在入口。注册语句、工厂与原来三个辅助入口保持；没有引入接口、模块容器、反射扫描或额外运行期状态。

文件变多和详细注释增加是本次可定位性的代价；不以总行数下降作为收益证明。类名能直接定位主要文件，注册入口能顺序阅读职责，具体服务仍在同一组合根文件内可查。

## 3. SOLID 与行为等价审查

| 原则 | 实际结果 |
| --- | --- |
| SRP | 显露既有策略、查询、缓存、组合与会话边界，没有迁移资源所有权 |
| OCP | 原显式贡献和精确工厂继续有效，无插件 ID 特判或新注册框架 |
| LSP | 原类型身份、接口、方法体、注册语句及顺序保留；运行期通过诊断、通知、身份与寿命测试核对 |
| ISP | 未新增单实现接口，未扩大 SDK、Dock 回调或展示契约 |
| DIP | DI 解析留在既有组合根，业务仍消费原窄端口，无第二容器或 Service Locator |

Roslyn 结构比对记录：P1 的十二个类型、P2 的十个类型在忽略注释、格式和 using 组织后，语法标记与原类型一致。P3 将新增私有调用展开后，89 条原顶层语句逐条内容与次序相同，未提取的既有成员也一致。结构比对不替代行为测试，也不承诺调试堆栈中的文件名或私有工厂名称不变。

新增中文注释解释了：诊断为何先脱敏再输出、共享命令适配器与观察者的释放顺序、可选诊断会话回退、工作台解析线程、同实例关闭端口，以及工厂为何必须成功交付前登记真实对象。未逐句翻译代码，也未为拆分新增设计模式。

覆盖率清单中的旧命令展示文件映射为四个新文件，各保留 `90.0`；其余条目和整体阈值保持。仅维护路径，没有采集覆盖率，不能据此宣称达到任何覆盖率数值。
