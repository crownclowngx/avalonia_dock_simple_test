## SOLID 与朴素设计

SRP：StartupCoordinator 只管理启动任务和终态；StartupWorker 只承担非 UI 调度；StartupDesktopShell 适配首帧和窗口；Splash 只展示并提交关闭意图；原 Runtime 保留组合和释放。OCP：加载流程向同一个进度端口报告，不为插件写特殊 UI。LSP：启用过滤、插件隔离、超时、原关闭和重启许可继续使用既有规则。ISP：进度端口只有 Report，不暴露容器或控件。DIP：组合根注入工厂和进度端口，UI 通过快照读取，不让插件加载器依赖 Avalonia。

采用 sealed 类、记录、少量窄接口、普通方法和任务，不引入事件总线、通用状态机、第二套 DI 或全局服务定位器。核心中文注释解释 STA 的兼容边界、UI 间接依赖、阶段计数、晚到消息、取消和所有权交回。SDK public API、产品版本和持久化格式未改变。

相较初稿的落地细节：窗口为 520 × 380 DIP，避免三行状态及错误摘要拥挤。羽毛用内嵌 Avalonia Path，SVG 保留为设计来源。UI 每 80 毫秒读取快照；动画仅操作羽毛变换。命令目录经 Host Handler 间接解析 Workspace，最终合并校验随工作台装配移至 UI 线程，仍早于主窗口展示。后台线程仅保证同步入口 STA，不能保证异步延续线程或替代 COM 消息泵。
