# V23 本地 ZIP 安装与恢复开发记录

> 日期：2026-09-24。实现、测试与文档已落地；最终本机开发门禁、源码身份及逐套件计数以[非嵌入证据](development-evidence.json)为准，不在嵌入文档中预填最终通过结论。没有执行安装目录部署、公开发布或新增人工桌面验收。

## 实施结果

Host 插件看板直接消费现有 `Controls/<PluginFolder>/` ZIP，先快照、受限检查和预览，再确认待办。可选外置发布清单按现有 schema 2 核对完整摘要；错误不会静默降级。支持新装、升级、明确选择的同版重装/降级、取消待办及恢复上一版本。现有 Build 1.1.3 / 3.4.1 协议保持，SDK public API 未增加安装接口。

活动会话不移动 DLL。下一次正常启动在发现前取得独占租约、复核候选和旧目录摘要、记录 Applying，再将完整旧目录移到备份、候选移到目标。成功启动交接后才确认；禁用插件只确认文件就位。加载/初始化失败或进程中断在下次独占启动恢复，不在当前已加载进程内回退，不循环自动重启。

文件步骤采用日志、前后摘要和旧登记进行恢复；对日志写入、两次目录移动、安装登记和最终提交分别注入实际 IO 故障。恢复重复进入仍保存旧目录事实。无法识别的磁盘内容、坏备份、坏日志或外部改动保留现场并拒绝覆盖。

运行租约由 Program 在插件发现前取得，转交 ProcessExit；关闭看板、Runtime Shutdown 或 Program 返回不提前释放。重启助手保持原进程交接职责。两个数据根共享同一插件根的租约；其他实例占用则保持旧版和 Staged，试启动期间只有 PID/启动时间对应的所有者可加载候选。

## SOLID、取舍与中文注释

- 检查、决策、存储、用例、应用恢复、租约和界面分开；纯版本决策不依赖 Avalonia/IO。看板仅通过安装和重启窄端口操作。
- `IPluginInstallFileCommit` 只抽象真实不可逆提交，测试仍操作真实临时目录。没有通用虚拟文件系统、安装框架、状态机库、来源策略中心或第二容器。
- 准入/排空复用既有实现；中文注释解释快照所有权、锁顺序、取消提交点、日志写成功但返回失败时保留暂存、目录恢复和真实进程退出。
- 备份路径收敛为 `backups/<operationId>`，旧身份与登记由日志拥有，不重复 PluginId 层。主动恢复也先复制受检备份并形成普通事务。
- 保守保留已完成 ZIP、旧备份及失败载荷，未自动清理历史备份。没有对插件业务数据库做迁移或回滚承诺。
- 安装元数据缺失与无权读取分开；无法可靠建立租约时不绕过保护。不能把同权限恶意进程的持续路径竞争称为已被操作系统隔离。

首次新增边界测试使用阻塞式异步断言，xUnit1031 在 `-warnaserror` 下使命令退出 1，尽管当轮 95 个测试断言通过，该轮不记为成功构建。已改为同步 `Assert.Throws`，随后同范围 95 项及零警告构建通过；两轮原 TRX 均保留。早期编译中修正了指纹属性名、命名空间与内部枚举的测试方法可访问性，不调低警告门槛。安装代码复核补上多份嵌套清单拒绝、不可读清单不降级、提交前 ZIP 快照复核与占用提示保持。

启动契约复核发现安装 IO 的 await 会让后续模块初始构造落到线程池 MTA。已改为仅在专属后台 STA 线程同步桥接安装准备，再调用原 Runtime 工厂；真实进程探针新增构造/Configure 的 STA 断言，避免用“功能启动了”掩盖线程契约变化。UI 不参与该同步等待。
