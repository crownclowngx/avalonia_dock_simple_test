## 1. 目标：让用户能够预测入口、结果与恢复方式

当前工作台已经具备功能中心、工具中心、命令面板、独立帮助与诊断窗口。V8 的目标是让这些能力形成一致的使用路径：用户不需要先理解插件架构，就能找到功能、开始工作、回到已有页面，并理解隐藏与关闭的后果。

本轮集中回答四个问题：

1. 我想做这件事，应该从哪里开始？
2. 我搜索到的结果，会打开一个新页面，还是回到已有页面？
3. 我把工具隐藏后，任务和页面分别发生了什么变化？
4. 操作失败或被中断后，我能否保留现场并继续？

减少窗口数量、按钮数量或点击次数都不是独立目标。入口与对象关系清晰、行为可预测、状态可恢复，才是验收依据。自动化测试证明实现遵守这些规则，真实任务观察检验规则是否容易理解，两类证据分别记录。

## 4. SOLID 是首要设计与审查约束

SOLID 用来约束职责、依赖和可替换性，不以接口数量或设计模式数量作为达标依据。以下规则同时约束实现和测试；发现冲突时先修正边界，再继续增加交互。

| 原则 | V8 落地要求 | 审查与验证依据 |
| --- | --- | --- |
| SRP 单一职责 | 目录读取、文字匹配、界面会话、实际执行、窗口所有权分别负责各自变化原因 | 查询不创建页面；匹配不读配置；ViewModel 不遍历 Dock 或解析 Provider |
| OCP 开闭原则 | 功能由既有贡献目录自动进入发现路径，新增业务插件不要求 Host 增加插件名分支 | 合成不同来源与多创建意图夹具，无业务插件硬编码 |
| LSP 里氏替换 | 各类结果遵守共同展示与可执行约定，但不假设每类都持有 CommandId；旧插件继续按已有契约工作 | 旧 SDK、不可持久化页面、无菜单 Command 的 Document 贡献均有用例 |
| ISP 接口隔离 | View 只接触展示字段和操作；查询不获得执行、关闭或容器解析权限 | 复用现有窄接口，只在确有替换边界时增加新接口 |
| DIP 依赖倒置 | 展示依赖 Host 用例与只读边界；基础设施在组合根注入 | 不通过 `App.Current`、静态 Provider、ServiceLocator 取业务服务；Dock 类型留在内部适配边界 |

### 4.1 朴素使用设计模式

- 继续使用现有 MVVM、构造器注入、只读投影和 Dock Adapter。
- 匹配逻辑优先使用一个无副作用的函数或小型具体类，返回有限匹配等级。
- 四类搜索结果是已知集合，可用少量封闭类型与明确分支；不为未来未知结果类型建立注册框架。
- 真正不同的操作保留小型适配器，分别进入现有创建、显隐、定位和命令执行路径。
- 新接口必须能解释“消费者需要什么”和“存在什么替换边界”；不能仅为每个类配置一个同名接口。
- 不为本轮引入 MediatR、CQRS 基础设施、规则引擎、状态机库或新的 DI 层。
- 修改文件按职责需要确定；不顺带重构与本轮无关的整个 Host。

### 4.2 中文注释要求

新增及实质修改的核心类型、跨层方法、状态转换和异常边界使用中文注释。注释应说明设计原因，尤其包含：

1. 当前对象拥有和不拥有的资源。
2. 输入身份、合法状态、结果与副作用。
3. 为什么执行前必须重查，为什么某个状态不能缓存。
4. 异步完成、取消、窗口关闭、退出与迟到回调的处理顺序。
5. 为什么保持原有兼容行为，以及为何没有采用更复杂的抽象。

接口和关键 internal 用例优先使用 XML 注释；有必要时使用 `remarks` 说明设计思路。普通赋值不逐行翻译，既有无关代码不为“统一中文”而批量改动。测试用例补充中文场景说明，解释它防止哪一种用户可见错误。

示例为注释内容示意，不规定新增类型名称：

```csharp
/// <summary>按运行期身份定位一个仍然打开的工作页面。</summary>
/// <remarks>
/// 搜索结果只保存页面身份和展示快照，不持有插件模型、View 或 Scope。
/// 用户按下 Enter 前页面可能已经关闭，因此执行时必须再次查询 Workspace。
/// 若目标已不存在，返回可展示的失败结果；不能按相同标题创建新页面，
/// 也不能切换到另一个同名实例，否则“继续原来的工作”会变成不同操作。
/// </remarks>
```

### 5.2 保留熟练用户的导航方式

原 Dock 插件分组菜单及平铺／树形偏好继续可用，可从工具中心恢复。不因欢迎页主入口调整而删除既有 Tool、修改稳定 ID 或重置布局。

旧目录与功能中心都读取同一份创建目录。窗口模态形式、创建成功后关闭、失败保留选择、忙碌时防重复等行为继续沿用已有功能中心流程。

欢迎页通过组合根注入的 Host 展示命令或窄回调进入同一用例；禁止在欢迎页再次实现创建窗口或插件页面的逻辑。欢迎页文字聚焦“选择功能并开始工作”，现有框架介绍可以降低显著程度，不要求本轮整体重做视觉动画。

## 6. 搜索：先覆盖，再保证排序与动作可预测

### 6.1 结果类型与身份

| 结果类型 | 数据来源 | 身份 | 对用户显示的动作 |
| --- | --- | --- | --- |
| 功能 | `DocumentCreationMenuQuery` 的有效创建入口 | 原有 DocumentTypeId 与可空 CreationIntentId 组合，保留真实 Owner | 打开新标签 |
| 已打开页面 | 当前 Workspace 的已发布页面只读快照 | 现有运行期页面身份，不是 DocumentTypeId 或标题 | 切换到页面 |
| 工具 | `ToolWorkspaceReadModel` | ToolTypeId | 显示／定位 |
| 命令 | 既有许可候选及 Command State | CommandId | 原有命令动作 |

身份在类型层区分，不能继续扩大“多个可空 ID 任意组合”的记录。用于 UI 选择保持的 key 可以序列化身份，但必须无歧义、区分结果种类，执行仍使用原始强类型身份。

一个 Document 类型的多个创建意图分别显示。无创建意图与有创建意图的入口不合并；不同插件同名功能不合并。图标解析继续携带原 Owner，不能因统一展示而丢失插件资源边界。

普通命令仍只来自既有发现许可，不把全部注册 Command 自动公开，不把仅限快捷键或局部使用的命令加入面板。新增“功能”结果来自已经面向用户公开的创建目录，不伪造插件菜单贡献或 CommandId。

### 6.2 已打开页面的有限范围

- 只列当前 Runtime 内已经发布、尚未最终关闭的页面；创建中的临时对象不进入列表。
- 使用 Host 最终展示标题、修改标记、功能名称和来源。不读取插件内部表单、文件内容或敏感路径来构造摘要。
- 同名页面仍是不同项，可补充当前运行内稳定的显示序号。序号只用于识别，不改写标签标题、文件标题或 SDK 状态，也不能因过滤而重新编号。
- 定位不重新 Initialize，不新建 Scope，不改变保存状态，不释放其他页面。
- 页面已关闭或正处于不可激活的关闭阶段时，重查并提示，不回退成新建，也不匹配另一个同名页面。
- 当前实现若缺少合适只读查询／定位入口，只在 Workspace 边界补充最小能力；窗口不能自行遍历 Dock 树。

### 6.3 匹配与排序规则

查询 Trim 后使用固定的不区分大小写比较，不增加文化环境相关的隐式排序规则。首版把完整查询作为普通文本匹配，不引入拼音、分词或模糊距离。

非空查询共享以下等级，取单项最好的匹配等级：

1. 名称精确匹配。
2. 名称前缀匹配。
3. 名称包含匹配。
4. 说明、分类、来源或稳定身份等辅助字段包含匹配。

展示前缀“功能”“工具”不加入名称分值；按原始业务名称匹配。各入口使用自己已有的合法字段，不为统一搜索凭空添加插件元数据。

命令面板在相同等级内按“已打开页面、功能、工具、命令”固定排序，再按名称及稳定身份排序。这一规则用于优先辨认已有现场，不允许把功能结果的动作自动改成定位。可执行状态变化不单独触发上下跳动的排序。

空查询保留适合各界面的顺序：功能中心保留原目录分类顺序；工具中心的常用与最近保留用户顺序；命令面板按上述类型顺序及稳定名称排序。不新增持久化使用频次或全局 MRU。

### 6.4 范围与选择保持

- 功能中心搜索继续跨分类，清空后回到此前分类；主动选择分类退出搜索。
- 工具中心搜索继续跨导航分组，保留显式来源约束。界面同时说明搜索范围和当前来源，提供清除来源的直接操作。
- 命令面板覆盖四类结果，不额外混入帮助正文、诊断事件或历史缺失文件。
- 查询文本变化可选择第一个匹配项；纯状态刷新优先保持同一稳定身份。目标消失后按明确规则选择首项或显示空态。
- 展示“打开新标签／切换到页面／显示／定位”等动作文字，不只依赖颜色或图标。

### 6.5 执行、异步与失败

功能中心和命令面板的功能结果都调用 `DocumentPersistenceCoordinator.CreateDocumentAsync`，参数来自同一创建入口；旧插件目录继续使用该用例。

| 操作 | 执行与反馈约定 |
| --- | --- |
| 打开功能 | 执行前复核入口与 Host 状态；忙碌时禁重复提交；成功后关闭面板并聚焦新页面，失败保留查询、选择与错误 |
| 切换已有页面 | 执行时复核运行期身份；成功后交还焦点，失败保留面板并刷新 |
| 工具显示／定位 | 进入既有 `ToolCenterActions`；保留显隐、自动收起、最近记录和最终重查规则 |
| 普通 Command | 继续使用既有 State Query、Executor、活动 Target 和关闭协议，不建立第二套命令执行器 |

新功能创建采用功能中心已有的忙碌关闭规则：初始化开始后，Esc 不假称取消初始化；界面清楚显示正在打开，Host 退出仍遵守原有文档操作排空机制。其他空闲场景的 Esc 正常关闭搜索。

新增异步路径必须真实观察 Task 和失败结果，不让 `async void` 或未观察异常逃逸。现有 `ICommand` 同步接缝可以调用内部已观察的异步方法，测试应能等待实际完成。仅在 UI 线程修改界面，迟到回调必须复核当前窗口会话，不得重新打开窗口或抢回焦点。

## 7. 工具中心：把使用与整理分出主次

### 7.1 默认界面

每行保留名称、简短用途、来源／分类、状态、星标、一个主按钮和更多操作。星标保留加入／移出常用；主按钮继续为显示或定位。

示例名称仅说明布局，不表示 Host 为外部插件新增业务规则。

- 默认仍为全部工具，避免首次打开进入空常用页；不自动跳到最近页。
- 分类浏览保留，不因收起编辑操作而删除有用导航。

- 整理入口承接现有分类管理区的展开，以及“隐藏所有工具”。分类管理仍使用已有窗口空间，不新增独立中心或整页管理模式。

- 无匹配结果提供更换关键词或清除来源提示；已有错误和偏好保存警告保持可读。

### 7.2 更多操作与刷新

更多操作绑定被打开菜单的 ToolTypeId，不能依赖随后变化的全局 SelectedItem。搜索或可用性刷新发生时，不得把操作施加到另一行。

键盘可以聚焦星标、主操作和更多按钮，打开菜单后可用方向键和 Enter 完成操作；Esc 先关闭当前菜单，再按现有窗口规则处理。不因加入弹出菜单而破坏原双击、行 Enter、首次搜索焦点与定位后的焦点交还。

所有修改仍通过现有 Actions 和 Preferences；不保存第二份显隐状态，不新增偏好格式。已有收藏顺序、最近记录、分类、缺失历史项以及错误备份继续恢复。
