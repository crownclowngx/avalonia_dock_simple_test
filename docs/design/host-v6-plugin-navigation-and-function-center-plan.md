# MyAvaloniaManagement V6 插件目录双模式与功能中心改造方案

> 状态：设计草案，待实施；本文不代表功能已经完成。
> 日期：2026-09-11。
> 代码核查基线：`6e558e8` 加当前未提交工作树；实施前重新记录实际基线，不覆盖同期其他改动。
> 范围：Host 内部实现、Host 测试及配套说明；本轮不修改外部业务插件。
> V6 表示本次 Host 改造的时间顺序，不自动对应产品版本、SDK/NuGet 版本或数据格式版本。
> 方案主题名称和界面模式名称允许以后自定义；稳定身份不使用显示名称，也不使用“V6”作为业务标识。
> 本次交付仅为本设计文档，尚未修改 Host 实现或执行功能验收。

## 1. 目标与本轮决策

保留现有“插件分组菜单”Tool，在同一个 Tool 内提供旧版和新版两种展示模式；新增由“文件 → 新建文档…”打开的功能中心。三个入口共享 Document 创建目录和既有创建用例。

| 项目 | V6 目标行为 |
| --- | --- |
| 原有 Tool | 保留原 Tool 身份、默认停靠位置和现有关闭策略 |
| 旧版模式 | 按完整分类字符串平铺分组，组内直接显示创建入口，保持当前逻辑 |
| 新版模式 | 将分类字符串解释为多级路径，显示可展开的分类树和创建入口 |
| 模式切换 | 在插件分组菜单 Tool 顶部选择；不要求切换布局或重新启动 |
| 初始模式 | 没有有效偏好时使用旧版，用户主动切换后记住选择 |
| 功能中心 | 独立的“新建文档”选择弹窗，提供分类树、搜索、功能说明和创建操作 |
| 图标 | Host 统一提供矢量图标，插件可通过现有 `IconPath` 指定名称；缺省或无法识别时使用公共默认图标 |
| 外部插件 | 无需同步改造；现有平面分类和空图标继续正常使用 |
| 命名 | V6 作为改造序号保留；方案副标题、旧版和新版的显示名称可以另外命名 |

本轮采用 `/` 作为分类路径分隔符。这个选择是根据讨论确定的设计默认值：已有“大唐-会计”使用 `-` 作为名称内容，因此保留 `-` 的字面含义，避免旧插件被自动重新分类。

本轮不包含插件市场、插件安装、外部插件分类批量迁移、收藏、最近使用、运行时重命名编辑器或通用图标包引入。功能中心列出当前可以创建的文档入口，不承担插件状态管理和安装管理职责。

## 3. 同一个 Tool 内保留新旧两种模式

### 3.1 Tool 身份和操作位置

继续使用现有 `HostExtensionIds.PluginMenu`，默认标题仍为“插件分组菜单”。新增工具栏：

```text
插件分组菜单
显示方式：[旧版（平铺） ▾]
--------------------------------
下方按所选模式展示插件创建入口
```

选择项默认是“旧版（平铺）”和“新版（树形）”。选择发生在插件目录 Tool 内，“工具管理”仍然负责工具的显示状态，不承载业务目录的显示模式配置。

切换只替换内容展示：保留 Tool 的停靠、浮动、自动隐藏和尺寸状态，不重新注册 Tool，不创建 Document，也不改变已经打开的文档。

### 3.2 旧版模式的保留边界

- 使用完整原始分类字符串分组，不拆分 `/`、`-` 或其他字符。
- 保留现有分类顺序、入口顺序、直接入口数量、展开/收起和单击创建行为。
- 保留当前统一四宫格图标；本轮共享业务图标首先用于新版树和功能中心。
- 新插件声明 `闲才业务工具/文本检测` 时，旧版仍将这整段文字显示为一个分类。
- 当前顺序来源保持不变：目录按分类、Document 显示名、Document 类型 ID 排序，再按声明顺序投影创建意图。

为加入选择器而调整外层布局是允许的；旧版内容不顺带改为卡片、不增加树层级，也不重新定义点击行为。

### 3.3 新版模式

```text
插件分组菜单
显示方式：[新版（树形） ▾]
--------------------------------
▾ 闲才业务工具                     4
  ▾ 文本检测                       3
      Excel 批量审核
      审核结果分析
      文本智能审核
    业务首页
▸ 大唐-会计                        2
```

- 分类节点只展开/收起；叶子节点单击创建对应 Document。
- 同一个分类可以同时包含子分类和直属创建入口。
- 分类数字统计所有后代创建入口，包含直属叶子；不统计子分类个数、插件包个数或已打开的文档数。
- 子分类按节点名称使用 `StringComparer.Ordinal` 排序，分类先于直属叶子；同一分类内叶子保留目录顺序。
- 同名分类只在同一个父路径下合并。不同业务的“文本检测”互不合并。
- 长名称省略显示，悬停可查看完整名称/路径；树支持多级，使用指南建议业务层级控制在两三层。
- 使用支持递归层级和键盘导航的树控件/模板；不要通过固定嵌套三层 `ItemsControl` 假定最大业务深度。

旧版、新版和功能中心分别保存自己的展开及选中状态，不共用可变 UI 节点。当前运行期间来回切换应恢复对应模式的展开状态；第一版不要求跨启动恢复每个分类的展开情况。

### 3.4 模式记忆与自定义名称

内部模式使用稳定值 `legacy` 和 `tree`。显示文字不参与分支判断、偏好保存、分类身份、Tool ID 或 Document ID。

拟新增 Host 用户偏好文件 `plugin-navigation-v1.json`，放在 `HostDataRootPolicy` 解析的用户数据目录内。这里的 `v1` 是该偏好文件的格式版本，与本轮 V6 改造序号无关。

```json
{
  "schemaVersion": 1,
  "pluginMenuMode": "legacy",
  "modeDisplayNames": {
    "legacy": "旧版（平铺）",
    "tree": "新版（树形）"
  }
}
```

`modeDisplayNames` 为可选项，允许以后自行修改为“经典目录”“业务树”等名称。启动时读取，空白名称回退到默认名称；保存模式时保留有效的自定义名称。本轮不新增名称编辑界面，改名可通过该配置完成并在重启后生效。

没有配置、模式未知或配置损坏时使用 `legacy`。读取/保存失败不阻止菜单使用；记录简短诊断并采用内存偏好。文件写入沿用现有 Host 设置的临时文件与原子替换方式，损坏文件保留后再恢复默认值，不将用户偏好写入仓库或插件包。

## 4. 分类字符串的解析规则

保留 SDK 的 `MenuCategory` 字符串，仅在 Host 的新版投影中将它解释为路径。不得把路径用于动态解析服务、加载文件或查找 Document 类型。

| 输入示例 | 新版树 / 功能中心 | 旧版 |
| --- | --- | --- |
| `图像分析` | 一级分类“图像分析” | 原样分组 |
| `闲才业务工具/文本检测` | 闲才业务工具 → 文本检测 | 完整字符串作为一组 |
| `闲才业务工具/文本检测/批量处理` | 三级分类 | 完整字符串作为一组 |
| `大唐-会计` | 一级分类“大唐-会计” | 原样分组 |
| `闲才业务工具 / 文本检测` | 对各段执行 Trim 后合并到对应路径 | 原始完整字符串分组 |
| `闲才业务工具//文本检测` | 非法空段，整串回退为一个分类并记录诊断 | 原样分组 |
| `/闲才业务工具` 或 `闲才业务工具/` | 前后空段，整串回退为一个分类并记录诊断 | 原样分组 |

规则补充：

1. `/` 是新版的保留分隔符，第一版不设计转义语法，也不同时支持多个分隔符。
2. 解析不修改注册描述和原始字符串；原始值继续服务旧版及诊断。
3. 使用规范化后的完整路径标识分类，按 `Ordinal` 比较，保留大小写差异。
4. 非法路径不丢弃入口、不隔离插件、不静默删掉空段；整串回退保证功能仍可发现。
5. 同一原始路径的诊断在同一目录版本中去重，避免刷新时重复输出。
6. SDK 现有的非空分类校验继续有效，本轮不另行改变 SDK 输入校验规则。

实施前审计已有 `MenuCategory`，特别记录本来含 `/` 的字面名称。新版会对这些值产生新的层级含义；旧版始终保留完整字符串展示，说明文档必须明确这种展示差异。

## 5. 新建文档功能中心

### 5.1 入口与窗口形式

新增“文件 → 新建文档…”，显示在现有“打开…”之前。它通过 Host 命令目录、菜单贡献和 Handler 接入，不由 XAML 另外拼装一套命令执行链。

功能中心是以主窗口为 Owner 的单个模态选择窗口，不注册为新的插件 Tool 或可保存 Document。重复请求只激活当前选择窗口。分类切换、搜索、查看说明均在同一个弹窗内完成。

本轮以文件菜单入口为必做项；新增快捷键不是完成条件。若后续选择增加 `Ctrl+N`，须通过现有快捷键声明和冲突治理接入，不在窗口中额外监听一套热键。

```text
新建文档
[ 搜索功能名称、说明、分类路径……                       ]

业务分类                    功能列表
全部功能                    闲才业务工具 / 文本检测
▾ 闲才业务工具
  文本检测                  [图标] Excel 批量审核
  图片检测                         选择模型逐行审核……
▸ 图像分析
▸ 视频工具                  [图标] 审核结果分析
▸ 文件工具                         多模型结果对比……

                            [图标] 文本智能审核
                                   使用选定模型审核文本……

                                              [取消] [创建]
```

### 5.2 浏览、筛选和搜索

- 左侧“全部功能”默认选中；其他节点来自与新版 Tool 相同的分类路径投影，但拥有独立选择/展开状态。
- 选择分类后，右侧显示该分类和所有子分类中的创建入口。
- 非空搜索默认检索全部可用入口，匹配显示名称、说明和规范分类路径，使用不区分大小写的文本包含匹配。
- 搜索时明确显示“全部分类中的搜索结果”，避免用户误以为只搜索当前分类。清空搜索恢复先前分类选择；点击分类则清空搜索并进入该分类。
- 卡片显示图标、名称、简短说明和所属分类路径，完整说明可在选中详情或提示中查看。
- 搜索和分类浏览使用确定性目录顺序；第一版不引入模糊检索引擎、拼音索引或相关度评分。
- 没有匹配结果时显示空状态；没有选中可用入口时禁用“创建”。
- 第一版只读取当前可用目录，不展示未安装功能，也不在此处增加启停插件的操作。

### 5.3 创建行为

1. 单击卡片选中；点击“创建”或双击卡片提交一次创建请求。
2. 创建期间设置本窗口的忙碌状态，屏蔽重复提交和改变创建目标；显示创建进度提示。
3. 传递原有 `DocumentTypeId` 和可选 `CreationIntentId`，调用 `DocumentPersistenceCoordinator.CreateDocumentAsync`。
4. 以本次调用结果判断成败，继续更新共享 `DocumentOperationState`。当前创建调用成功返回 `ClearError`，失败返回 `Failure`；不得只检查可能包含旧错误的全局提示状态。
5. 成功后关闭选择窗口，并将焦点交给已创建的主工作区 Document。
6. 失败时保留选择、搜索和窗口，在弹窗内展示本次错误；解除忙碌状态后允许重试。
7. 未开始创建时，取消/Esc 关闭弹窗，不创建任何文档。创建已经开始后，关闭按钮和 Esc 不得伪装为“已取消创建”；等待当前事务返回后再允许正常关闭。

用户浏览目录、搜索、切换模式、加载图标时，均不实例化插件 Document/View，不调用插件工厂，不新建 Document Scope。只有实际提交创建操作才进入既有激活、发布及失败回滚链。

### 5.4 窗口及在途操作所有权

窗口服务由当前 HostRuntime 拥有，通过桌面 Shell 绑定主窗口。构造服务时不创建窗口，不使用进程静态窗口或全局 Provider。关闭后清理窗口引用、事件订阅及图标控件。

“打开功能中心”的 Host Handler 只负责在 UI 线程显示或激活窗口，观察展示异常后结束本次打开动作。不要在工作台命令执行器中把整个选窗生命周期当作一个持续命令等待，以免与 Host 退出时等待命令结束形成循环等待。

实际创建仍由既有文档操作链管理。Host 退出时停止接受新选择请求，关闭空闲选择窗口；若创建已经在途，必须服从当前文档操作与 Runtime 关闭协议，不能仅因弹窗关闭就提前释放其依赖。该场景列入验收，不新增独立的插件生命周期管理器。

## 6. Host 共享矢量图标

### 6.1 图标契约

沿用可选字符串 `IconPath`，定义 Host 对 `builtin:` 前缀的解释；本轮不改 SDK 构造签名、不新增插件必须实现的图标接口。

以下为本轮拟提供的名称，实施后才成为可用约定：

| 名称 | 用途 |
| --- | --- |
| `builtin:module` | 所有未提供/无法识别图标的公共默认图标 |
| `builtin:folder` | 分类节点 |
| `builtin:table` | 表格及批量数据处理 |
| `builtin:chart` | 分析、报表、统计 |
| `builtin:text-check` | 文本检测、审核 |
| `builtin:image` | 图片功能 |
| `builtin:video` | 视频功能 |
| `builtin:download` | 下载功能 |

后续插件可这样声明，示例不意味着本轮修改闲才插件：

```csharp
new DocumentDescriptor(
    documentTypeId,
    "Excel 批量审核",
    "选择模型逐行审核文本并查看结果",
    menuCategory: "闲才业务工具/文本检测",
    iconPath: "builtin:table");
```

显示优先级沿用现有元数据投影：创建意图非空图标优先，否则使用 Document 图标；最终选中的字符串为空、未知或不受支持时，使用 `builtin:module`。一个非空但错误的入口图标回退到公共默认图标，不额外回查并猜测其他资源。

未知图标只影响外观，不导致插件注册失败、卡片消失或文档无法创建。图标名称精确匹配已登记项，不解释为文件路径、网络地址、任意 Avalonia 资源键或 CLR 类型名。

### 6.2 图标实现和资源复用

- 由 Host 维护图标名称到矢量几何资源的固定映射，优先复用已有四宫格、文件夹等图形，按需补齐其余条目。
- 使用当前 `PathIcon`/`StreamGeometry` 绘制方式，不要求插件携带 PNG，也不要求插件引入额外 UI 包。
- 新版树和功能中心共用同一目录及解析逻辑，分别设置适合的尺寸，通过 Host 主题资源控制颜色。
- 旧版模式保持既有四宫格展示，确保选择旧版时外观行为稳定。
- 可以复用只读图形数据；每个显示位置创建自己的控件，不能把同一个 `PathIcon` 实例挂到多个父级。
- 不为图标显示加载插件 View、执行插件回调或从插件安装目录猜测资源位置。
- 第一版不引入完整图标库。需要扩充时由 Host 集中接入，插件继续使用稳定的 `builtin:` 名称。

共享矢量资源仍然占用包体和绘制资源；设计收益是集中复用、缩放清晰、统一主题和减少插件资源维护，不承诺“零资源占用”或一定小于任意 PNG 方案。

## 7. 数据与展示的组织方式

```text
HostWorkspaceCatalog + PluginRegistry + 当前可用性
                      ↓
           WorkspaceCatalog 创建入口
                      ↓
         Host 创建目录的只读查询/投影
          ├─ 完整分类分组 → 旧版 Tool
          ├─ 分类路径树   → 新版 Tool
          └─ 路径树和入口 → 功能中心分类、搜索、卡片

三处创建操作 → DocumentPersistenceCoordinator → 既有 Workspace 激活/发布
新版树/卡片图标 → Host 固定矢量图标目录
```

具体组织原则：

1. 继续使用 `WorkspaceCatalog`/`WorkspaceSession` 提供的当前可用创建入口，不从磁盘重新扫描插件，也不从显示名称反推类型。
2. 保留旧版 `GetCreationEntriesByCategory()` 的完整字符串分组语义；另设路径解析和树形投影，避免一次修改意外改变旧版结果。
3. 分类路径、创建入口和图标描述保持只读。Tool 模式、展开、选中、搜索、忙碌属于各自的展示状态。
4. 对同一目录快照，两种 Tool 模式与功能中心的叶子集合应一致；只改变组织形式。
5. 可用性变化后在 UI 线程刷新投影，保留仍存在的分类展开/选择，移除不可用条目；实际创建时仍由现有链再次检查可用性。
6. 切换模式和打开功能中心时读取最新目录；需要订阅可用性事件的对象必须在窗口关闭或 Runtime 释放时退订。
7. 内部协作者优先使用具体类型。不要为这次改造新增通用菜单框架、全局事件总线、图标服务定位器或重复的文档创建管理器。

## 10. 验收标准

### 10.1 分类与模式

- 无分隔符、二级、多级、共同前缀、同名不同父级、分组与叶子共存均展示正确。
- `大唐-会计` 在新版中仍是一个一级分类；`A//B` 等非法路径保留入口并按规则回退。
- 同一 Document 的多个创建意图分别显示、分别计数，并传递各自 `CreationIntentId`。
- 旧版继续按原始字符串分组，名称、排序、数量及单击创建行为与改造前一致。
- 默认旧版；切换不改变 Tool ID、停靠位置和现有 Document，也不会触发插件初始化。
- 有效模式可跨启动恢复；未知/损坏偏好回退旧版，保存失败时仍可继续使用。
- 将显示名改为“经典目录/业务树”后，选择、保存、重启恢复仍正常；旧布局仍能找到同一个 Tool。

### 10.2 图标

- `builtin:` 已登记图标在新版树和功能中心中一致；空、未知、不支持的值都显示公共默认图标。
- 创建意图图标缺省时继承 Document 图标；非空但无效的最终值回退默认。
- 图标在浅色、深色以及不同缩放下清晰可辨；缺失图标不影响功能创建。
- 多处同时显示同一个图标不会出现控件父级冲突。
- 测试使用已核实存在的图形资源，不以“字段非空”代替实际显示验证。

### 10.3 功能中心

- 文件菜单“新建文档…”打开一个具有主窗口 Owner 的选择弹窗，重复请求不产生多个窗口。
- 分类筛选覆盖后代；搜索覆盖名称、说明和分类路径，搜索范围提示、清空恢复及空结果行为符合约定。
- 浏览和搜索不创建任何插件 Document/View/Scope。
- 选中并创建成功后只出现一个目标 Document，关闭弹窗并激活文档。
- 连续双击、点击创建和 Enter 等重复输入不能让同一次提交创建多份文档；创建失败可原地重试。
- 使用本次调用结果判断成功，不受其他操作遗留的全局错误提示影响。
- 取消选择不创建文档；创建中不能通过关闭弹窗宣称事务已取消。
- 从旧版、新版和功能中心打开同一入口，Document 类型、创建意图及失败回滚语义一致。

### 10.4 集成与验证方式

- 保留并运行现有插件菜单、Host 命令投影、Document 创建及布局相关测试，按新行为补充有实际意义的测试。
- 用 Headless UI 检查模板、绑定、主题、选择、重复提交和窗口生命周期；用实际桌面截图检查窄面板、长中文名称和弹窗布局。
- 覆盖窗口关闭再打开、模式反复切换、插件变为不可用、Host 退出时创建在途的场景，确认没有重复订阅、悬挂窗口或提前释放。
- 在不修改外部插件元数据的情况下验证旧插件可以显示并正常创建；使用 Host 测试注册验证新增路径和图标能力。
- 执行实施时仓库要求的 Gate CLI 检查，命令和结果写入实施记录，不沿用历史 V4/V5 的测试数字或已退役命令。

以上项目目前均为待实施验收项；本次写文档没有运行或声称通过这些功能测试。
