# 插件状态独立窗口：设计与本地验收

日期：2026-09-11。范围：Host 内部、相关测试与文档。插件 SDK、产品版本及磁盘 schema 不变。

## 决策与交互

插件状态用于按需检查兼容性和排查故障，原 Dock Tool 的空间和布局身份不再合适。
改为“工具 → 插件状态…”及命令面板中的同一个 Host 命令：
`myavalonia.host.command.plugin-status.open`。

窗口是主窗口拥有的非模态单实例 Window，默认 1040 × 720，尺寸限制依据屏幕工作区缩小。
它不注册为 Tool 或 Document。重复打开恢复最小化状态并激活；Esc 关闭；主窗口取消关闭时继续可用，
真正关闭或 Runtime 释放时解除事件并清空 DataContext。未绑定 Owner、工作区尚未就绪或正在退出时禁止打开。

布局采用顶部概览、搜索筛选、左侧虚拟化插件选择、右侧可滚动详情。右侧分基本信息、贡献信息和诊断记录，
不再把完整诊断堆在窄 Tool 中。深浅主题沿用宿主资源；图标与文字共同表示状态，长字段可换行、选择复制。

## SOLID 与职责

| 组件 | 单一职责及依赖边界 |
| --- | --- |
| `IPluginStatusQuery` / `PluginStatusQuery` | 读取并组合 Registry、Availability 和诊断快照；不读取插件实例、调用工厂或扫描磁盘 |
| `PluginStatusPresentation` | 集中映射已有生命周期和诊断阶段的中文文案 |
| `PluginStatusItem` 等记录 | 只保存展示数据和稳定选择键；不持有容器、插件实例或控件 |
| `PluginStatusWindowViewModel` | 通过窄查询接口取得快照，管理搜索、筛选、选择、概览、刷新错误与复制摘要 |
| `PluginStatusWindow` | 绑定界面，只适配焦点、Esc 和平台剪贴板 |
| `PluginStatusWindowService` | 当前 Runtime 的窗口所有权、重复激活、Owner 关闭与资源清理 |
| `HostOpenPluginStatusCommandHandler` | 进入 UI 线程打开窗口后完成命令，不等待整个窗口存续期 |
| `RetiredHostToolIds` | 布局与偏好共用的退役身份白名单，不重新赋予旧项运行身份 |

采用普通查询对象、MVVM 和窗口服务，没有通用窗口框架、反射路由或额外运行状态存储。
只为窗口真正需要替换的查询依赖提供接口；事实写入和生命周期执行继续属于原来的组件。

## 数据与刷新

1. 已提交插件以真实 Plugin ID 为身份。生命周期状态与可用性分别读取，避免无生命周期插件在退出后仍被标为可用。
2. 加载、模块发现、服务注册、容器构建和扩展组合阶段的失败候选由诊断补足。
3. 早期只有目录的记录，在该目录明确对应唯一 Plugin ID 时与后续记录合并；无身份候选保留目录键。
4. 每条诊断来自 `HostDiagnosticSession.Snapshot` 的已脱敏字段，按 Sequence 排列，不读取原始 Exception 正文。
5. 查看声明不创建贡献；文档、工具、命令、工作流动作均只读描述符。插件可用不等价于具体命令在当前上下文可执行。
6. 异常/警告优先。可用数与异常数可能重叠；等待初始化、正常停止不会被误判为初始化失败。

打开、激活和手动刷新都会重新查询。列表刷新通过稳定 Key 保持仍存在的选择，保留搜索和筛选；
查询失败保留上一份成功快照及其时间。没有后台定时器或窗口关闭后遗留的订阅。
复制使用同一份展示快照，异步完成时检查原选择和 DataContext，防止把成功提示写到另一详情或已关闭窗口。

## 兼容迁移

`myavalonia.host.tool.plugin-status` 与 `myavalonia.host.tool.management` 仅保留在退役白名单。
布局先通过已有结构校验，再定向移除退役项及活动引用，重新连续编号，保留其他项的相对顺序与属性。
迁移幂等，允许仅含退役项的布局变为空；其他未知 Tool 仍按原严格恢复规则处理。
首次覆盖原布局前备份为 `.pre-tool-retirement.bak`，备份失败拒绝写回。

`tool-center-v1.json` 读入、编辑及写回使用同一归一化规则，清理退役项的收藏、最近、分类分配和历史名称。
读入只修改内存，下一次正常偏好保存以原子方式固化；未知版本、损坏文件和写入失败继续遵循既有处理。
其他缺失插件的偏好与用户分类保留，不形成错误的退役项历史占位。

## 测试与本地开发门禁

- 查询测试：零插件、全部生命周期阶段、无生命周期插件的退出门控、失败候选合并、无身份候选、后期启动失败、诊断脱敏，以及查看声明不执行工厂。
- 窗口模型测试：搜索与筛选组合、异常统计、保留选择、刷新失败恢复、空结果和复制摘要。
- 迁移测试：隐藏、停靠、自动收起、活动引用、只有退役项、未知项保留、原始字节备份、重复迁移及所有偏好字段清理。
- Headless UI 测试：菜单/命令面板同一入口、无文档或所有工具隐藏仍可打开、非模态单实例、最小化恢复、Esc、取消关闭、Runtime 隔离、命令取消、真实剪贴板、100 项虚拟化及长诊断布局。
- 旧 Dock 测试改用保留的插件分组菜单，继续覆盖自动收起、四向恢复和唯一 PreparedView 回收。

运行 `dotnet test` 的 Host 单元和 Headless UI 套件，并使用仓库 `Gate verify` 执行本地开发门禁。
`verify` 包含锁定还原、构建、五个测试套件、架构/契约检查和本地包消费验收；它不运行 Windows Smoke，
不具备发布资格。遵循本轮要求，不使用 AIFLOW、Windows CI 或 `Gate seal`/发布门禁。
