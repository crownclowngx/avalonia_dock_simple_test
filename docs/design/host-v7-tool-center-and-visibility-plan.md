## 1. 目标与已确定的决策

当前工具入口主要依靠 Dock 边缘自动隐藏标签和工具区域底部标签。工具增多后，长中文名称难以扫读，局部标签宽度不足，低频工具也持续占用入口空间。V7 将全量工具的发现与管理放进独立窗口，工作区只承载用户主动显示的工具。

| 项目 | V7 目标行为 |
| --- | --- |
| 工具中心入口 | 主菜单“工具 → 工具中心…”；即使全部 Tool 隐藏，入口仍可使用 |
| 窗口形式 | 主窗口拥有的非模态、可调整大小、单实例窗口；重复请求激活已有窗口 |
| 旧工具管理 | 移除 `myavalonia.host.tool.management` 的 Tool 注册与展示，不保留侧边兼容壳 |
| Tool 隐藏规则 | 文件系统浏览器、插件分组菜单、插件状态及所有插件 Tool 均允许隐藏 |
| 管理例外 | 工具中心不是 Tool，不需要“某个 Tool 禁止隐藏”的例外 |
| 中心能力 | 全部、常用、最近使用、已显示、已隐藏、用途分类、来源筛选、搜索、显示、定位和隐藏 |
| 收藏位置 | 首版放在工具中心内部，不新增常驻侧边常用栏 |
| 新工具 | 新安装插件贡献的 Tool 默认隐藏，不自动收藏、不自动展开 |
| 老用户布局 | 保留仍有效的旧位置与显隐状态，只定向移除已退役的管理 Tool |
| 业务生命周期 | 隐藏 Tool、关闭工具中心都不停止后台任务，不释放插件级模型 |
| 键盘入口 | 命令面板可搜索工具中心及 Tool 打开入口，沿用现有键盘资源治理 |

早期讨论中“保留不可隐藏的工具管理 Tool”“在侧边固定全部工具入口”“先做常用工具栏”的方案，已由本节独立窗口方案替代，不作为 V7 并行模式实现。

### 1.1 两个中心的职责

| 中心 | 入口 | 操作对象 | 提交后的行为 |
| --- | --- | --- | --- |
| V6 新建文档功能中心 | 文件 → 新建文档… | Document 类型与创建意图 | 创建 Document；保持现有成功后关闭的选择流程 |
| V7 工具中心 | 工具 → 工具中心… | 已登记的 Tool 类型 | 显示、定位或隐藏已有工具；窗口保持打开，便于连续整理 |

两者可以复用样式、图标和纯数据查询方法，窗口状态、操作协议与生命周期分别拥有。V7 不改变 V6 功能中心的模态选择语义，也不将 Tool 列入 Document 创建目录。

### 1.2 本轮边界

本轮包括工具中心、显隐规则、分类与偏好、命令入口、默认布局及旧管理项迁移。保留现有四向 Dock、拖动、尺寸调整和自动隐藏能力。

下列内容留作后续独立改造：Dock 标签模板整体重写、面板标题栏替代标签的切换器、外部常用栏、场景布局预设、Bilibili 摘要 Tool 与完整任务 Document 拆分、插件安装或启停管理、热加载、多级用途分类、拼音或模糊检索引擎、工具模型懒创建。

工具中心提供充足的分类和管理空间，但不承诺消除用户主动同时显示大量 Tool 后的全部 Dock 标签拥挤问题。

## 3. 入口与窗口交互

### 3.1 统一入口

新增 Host 命令，建议稳定 ID 为 `myavalonia.host.command.tool-center.open`，展示名为“工具中心…”。命令名是本方案拟新增值，不是当前已有 API。

- 在“工具”菜单中提供固定入口，不受活动 Document、Tool 数量或插件生命周期影响。
- 命令面板搜索“工具中心”可触发相同命令。
- 欢迎页原“工具管理”按钮改为“工具中心”，调用同一 Host 入口。
- Host 正在退出或 Owner 尚未就绪时拒绝打开；不把缺少活动文档当作不可用条件。
- 首版不占用新的固定快捷键。现有 `Ctrl+Shift+P` 仍由当前命令面板机制管理。

### 3.2 窗口约定

工具中心是宿主内部 Window，不注册到 `PluginRegistry`，不产生 Tool/Document 身份，也不进入 Dock 布局快照。

1. 当前 HostRuntime 同一时刻只有一个工具中心窗口，两个 Runtime 的窗口和偏好服务引用互不共享。
2. 初次显示以主窗口为 Owner，允许缩放，初始尺寸根据 Owner 与可用屏幕区域限制，避免长列表挤入侧栏。
3. 使用非模态显示。窗口打开后主工作区继续响应，可直接观察显隐变化。
4. 重复打开恢复最小化窗口并激活；不重复创建 ViewModel 或订阅。
5. “显示”和“隐藏”后窗口保留当前位置与搜索条件，便于连续操作；“定位”显式激活主窗口中的目标工具。
6. 不设置全局置顶。定位工具后，中心保持存在但不抢回焦点。
7. 关闭按钮或 Esc 关闭中心；不撤销已经完成的显隐或偏好修改。
8. 主窗口关闭时停止接受新操作并清理中心窗口、事件订阅和 UI 资源；主窗口关闭被取消时仍能正常使用。

“打开工具中心”的 Command Handler 只负责显示或激活窗口并观察展示异常，不能在命令执行器中等待整个窗口存续期。否则容易与 Host 退出排空形成相互等待。

## 4. 工具目录、状态与操作语义

### 4.1 目录与运行状态分离

列表身份使用 `ToolTypeId`。查询合并 Host 已登记工具、成功提交的插件工具声明、当前可用性、运行时激活结果和用户偏好，不重新扫描插件目录、不解析服务容器。

拟投影以下纯数据：

| 数据 | 来源与含义 |
| --- | --- |
| Tool ID、名称、说明、图标引用 | 不可变 Tool 描述符 |
| 来源种类、插件 ID 与显示名称 | Host/真实插件登记来源；Host 不伪造 PluginId |
| 用途分类、收藏顺序、最近访问 | Host 工具中心偏好 |
| 可用性、不可用原因 | 既有插件可用性事实及 Host 的工具激活结果 |
| 布局状态、活动状态 | Workspace 拥有的只读运行事实 |
| 可显示、可定位、可隐藏 | 根据可用性、实例、布局和退出状态计算，不由 UI 自行猜测 |

已提交声明但运行不可用的工具仍显示在目录中。加载阶段未成功提交任何声明的插件，不凭空生成 Tool；有历史收藏但当前已缺失的工具只在收藏/最近视图中显示不可用占位，不计入当前已登记工具总数。

打开中心、搜索、筛选和渲染图标均不得触发额外的 Tool 模型、插件 View、Document 或 Scope 创建。当前启动流程已创建工具模型；V7 不同时改成模型懒创建，也不将“默认隐藏”描述为启动内存优化。

### 4.2 状态定义

可用性、布局状态、是否活动与是否收藏是不同事实：

| 维度 | 值 | 说明 |
| --- | --- | --- |
| 布局状态 | 隐藏 | 不在可访问的停靠/自动隐藏区域，能从中心恢复 |
| 布局状态 | 已停靠 | 已加入普通 ToolDock；未成为该区域活动页也属于已显示 |
| 布局状态 | 自动收起 | 已加入 Dock 自动隐藏区域，不能误报为已隐藏 |
| 活动状态 | 活动 / 非活动 | 当前区域正在展示或聚焦哪个工具 |
| 可用性 | 可用 / 暂不可用 / 激活失败 / 历史项缺失 | 决定是否能执行操作，独立于最后一次布局状态 |
| 收藏 | 是 / 否及顺序 | 快捷访问偏好，与显隐无关 |

“已显示”筛选包含已停靠和自动收起。不可用项显示原因；没有运行实例时不伪造“已隐藏”。不以 Dock 的 `IsPinned` 表示收藏；该字段在当前布局中描述自动隐藏状态。

### 4.3 单工具操作

| 操作 | 成功行为 | 不应产生的副作用 |
| --- | --- | --- |
| 显示 | 隐藏工具恢复到仍有效的原位置，否则使用声明默认方向；成为所在区域活动工具 | 不创建重复模型，不自动收藏 |
| 定位 | 展开必要的自动隐藏区域并将焦点交给主窗口目标 | 不移动工具，不改变保存的自动隐藏模式 |
| 隐藏 | 从停靠或自动隐藏区域进入隐藏状态，移除相应 Dock 入口 | 不移出常用，不停止下载，不释放插件模型 |
| 加入常用 | 保存稳定 ID 与收藏顺序 | 不显示工具，不改变停靠位置 |
| 移出常用 | 删除收藏关联 | 不隐藏正在显示的工具 |
| 设置分类 | 修改该工具的 Host 分类关联 | 不改变插件声明、Tool ID 或默认方向 |

显示/隐藏使用明确目标状态，重复提交视为已达到目标，不使用容易受刷新影响的 UI 本地取反。每次执行前由 Workspace 复核实际状态、插件可用性与退出门控；目录刷新不能代替执行检查。

显隐完成后读取真实布局状态再更新列表。失败保留原筛选和选择，在对应项附近展示本次错误，继续使用既有诊断通道。不能把现有方法返回的所有 `false` 都显示为失败，需区分“已是目标状态”“不可用”“未知工具”和实际操作错误。

当前 `ShowTool` 对自动隐藏工具的激活不等于已经验证了视觉展开和键盘焦点；实施时必须验证 Dock 的实际行为，并由 Adapter/Coordinator 补齐定位动作。

激活失败项可以查看既有诊断，首版不新增绕过当前所有权协议的“重建模型”按钮。单项不可用不应阻止其他工具操作；已有但不可用的实例在所有权允许时仍可隐藏。

### 4.4 隐藏所有工具

- 操作范围是整个工作区的所有 Tool，按钮文案使用“隐藏所有工具”，不受当前列表筛选影响。
- 不隐藏 Document，不关闭工具中心，不停止业务任务，不清空常用与最近使用。
- 在 UI 线程捕获目标集合，经 Workspace 执行，避免列表逐行调用导致重入和部分 UI 假状态。
- 完成后统一刷新；部分失败保留已经成功的结果，说明失败数量及对应项，不宣称全量成功。
- 每个退出或失败分支仍发布与实际提交相符的最终状态，不留下错误的已勾选项。
- 全部隐藏后仍能通过主菜单恢复任意可用工具，工作区不应残留空白工具条占位。

## 5. 分类、搜索与常用工具

### 5.1 用途分类与来源筛选

当前 Tool SDK 没有 `MenuCategory`。V7 首版将用途分类作为 Host 用户偏好，避免为这次窗口改造要求所有外部插件升级。

1. 首版提供一级用途分类，不建立固定多层树。预置“资源导航”“系统诊断”和“其他工具”。
2. 内置文件系统浏览器、插件分组菜单可初始归入资源导航，插件状态归入系统诊断；依据精确内置 ID 映射。
3. 外部工具没有用户关联时归入其他工具。用户可创建“下载任务”“工作流”等分类并移动工具。
4. 一个工具只有一个用途分类；常用、最近、已显示是过滤视图，同一工具不会被复制注册。
5. 支持新建、重命名和删除用户分类，以及设置工具所属分类；稳定分类 ID 与名称分离。
6. 删除分类后其工具回到其他工具，不隐藏或删除工具。“其他工具”作为兜底分类不能删除。
7. 分类名称 Trim 后非空，同名检测采用固定的不区分大小写比较；重命名不改变关联 ID。
8. 来源筛选单独使用真实插件 ID；相同显示名的不同插件不能混为一个来源。Host 显示为“内置”。

不从某个插件的 Document 分类推导其 Tool 分类，也不依靠标题关键词推断业务含义。以后增加插件可选推荐分类时，应独立设计兼容契约，保持用户已设置的分类优先。

### 5.2 搜索与排序

- 搜索名称、说明、用途分类、插件显示名及稳定 ID；采用不区分大小写的包含匹配，首版不增加索引服务。
- 输入非空搜索时检索全部已登记工具，界面明确显示“全部工具中的搜索结果”，允许继续使用显式来源筛选。
- 进入搜索前记录导航选择；清空搜索恢复原选择。主动选择分类或导航项时清空搜索，避免隐含双重筛选。
- 默认列表按显示名、Tool ID 确定性排序；收藏页按用户顺序，最近使用页按成功访问顺序。
- 单击列表行只选中；显示、定位、隐藏由明确按钮或菜单执行，双击/Enter 可执行该项主操作。
- 使用适合长列表的虚拟化控件；不为每个条目同时创建隐藏的插件业务页面。
- 长名称和说明省略后可读取完整内容；提供键盘焦点、可访问名称和可识别的图标按钮提示。
- 无匹配结果、无工具、无收藏和插件不可用分别提供明确空状态。

分类数字统计当前登记的工具，不统计插件包、Document 创建意图或历史缺失占位。查询刷新后保留仍存在的选择，不因状态更新自动重排收藏。

### 5.3 常用与最近使用

收藏只保存工具稳定 ID 及用户顺序。用户可通过拖动或上移/下移调整顺序；加入常用不自动打开，隐藏不取消收藏。首版不自动猜测常用工具，也不将新安装的工具自动加入常用。

最近使用仅在工具“显示/定位”成功后更新，最多保留 20 个去重 ID。浏览中心、搜索、收藏、布局自动恢复和后台任务进度刷新不刷新最近使用顺序。

同名工具、改名工具以 ID 识别。缺失收藏项显示上次名称与“插件缺失”，可移出收藏；重新安装相同身份的插件后恢复关联，不自动执行工具。

## 6. 隐藏政策与 SDK 兼容

### 6.1 Host 统一负责显隐

V7 最终工作区中所有 Tool 都允许用户隐藏，包括文件系统浏览器、插件分组菜单、插件状态及外部插件 Tool。关闭按钮、Dock 上下文菜单、中心操作、批量隐藏和测试入口遵循同一政策。

实现时同步清理下列政策来源：

- 内置工具注册中的 `Prevent` 使用。
- `ManagedToolDockable.CanClose` 从插件描述符获得否决权的逻辑。
- `ToolWorkspaceReadModel` 和 `ToolManagementViewModel` 的禁用判断。
- Workspace 显隐命令中与旧规则耦合的分支。
- 布局恢复与关闭钩子对隐藏/释放的区分。

不为只有一个固定规则的政策机械增加服务接口。优先通过 Host Adapter 与 Workspace 已有职责保持单一事实，查询层直接投影该事实。

### 6.2 公开契约处理

V7 采用“Host 行为更新，旧 SDK 二进制表面保留”的路线：

| 项目 | V7 处理 |
| --- | --- |
| `ToolDescriptor` 构造签名 | 保持，避免旧插件链接失败 |
| `ToolCloseBehavior` 枚举与属性 | 保留以兼容已有插件；旧 `Prevent` 不再阻止 V7 Host 隐藏工具 |
| 插件编译要求 | 现有二进制无需为显示/隐藏能力重编；必须验证真实旧包 |
| 文档说明 | 明确“源码/二进制兼容，禁止隐藏行为有意改变”，不能写成所有语义完全不变 |
| 将来删除字段 | 另行进行 SDK 破坏性版本与消费方迁移，不在本轮静默删除 |

V7 保留 SDK 公共签名、历史 Shipped API 和包版本；使用说明明确当前 Host 不再承诺插件可阻止隐藏。不为 V7 改造序号直接升到 SDK 7。

## 7. 默认布局、旧管理项迁移与偏好保存

### 7.1 新旧用户的默认行为

| 情况 | 行为 |
| --- | --- |
| 首次启动、没有有效布局 | 普通 Tool 默认隐藏，保留欢迎 Document 与工具中心菜单入口 |
| 有有效旧布局 | 迁移退役管理项后恢复其他工具的显隐、顺序、方向与比例 |
| 旧布局未记录的新工具 | 保持隐藏，进入工具中心待用户主动选择 |
| 用户主动隐藏全部 | 保存该状态；重启后不能自动展开默认工具 |
| 快照损坏或普通插件引用不可用 | 沿用既有严格拒绝与回退诊断，回退布局采用 V7 默认隐藏政策 |

构建默认工具实例和恢复布局应作为启动内部过程完成，在主工作区首次展示前提交最终状态，避免所有工具先展开再依次消失。默认隐藏不重写描述符的停靠方向；用户第一次显示时仍能取得声明位置。

### 7.2 退役工具的定向迁移

退役稳定 ID 固定为：`myavalonia.host.tool.management`。它只能作为历史布局迁移常量保留，不再是可创建的活动 Tool 注册。

建议恢复顺序：

```text
严格读取 layout-v2.json 并验证原结构
  → 复制快照，定向移除退役管理项
  → 清理活动引用与规范化剩余顺序
  → 再验证迁移后结构
  → 验证其他贡献、可用性和运行实例
  → 补建需要的稳定 Pane
  → 恢复布局并提交
```

迁移规则：

1. 只删除工具数组中精确匹配该 ID 的项，不放宽任意未知 Tool 的验证。
2. `ActiveToolId` 指向退役项时清空；否则保留。受影响区域中剩余项保持相对顺序，并满足既有顺序校验。
3. 保留其他工具的位置、显隐、自动隐藏状态及 Pane 比例。空 Pane 由既有折叠机制处理，不重命名稳定 Dock ID。
4. 迁移函数只处理数据，不操作 Dock，不创建模型，不在校验前修改运行布局。
5. 同一快照重复迁移结果一致；没有旧管理项时保持语义不变。
6. 仅因这个已知退役项发生的迁移不能将整份旧布局标记为坏文件。
7. 其他未知工具、插件不可用或结构错误继续使用当前拒绝策略。本轮不扩大成任意缺失插件的局部容错恢复。
8. 初次将迁移后的布局写回前保留旧文件的迁移备份，采用既有原子写入机制；备份失败时保留原文件并记录保存失败，不影响本次内存布局继续使用。
9. 保持 `layout-v2.json` 与 schema 2；正常保存不再包含退役项。

新版布局不再携带管理 Tool，旧 Host 可能重新显示该工具；保留原备份用于软件回滚。不能把格式版本相同解释为往返升级后所有 UI 行为必然一致。

### 7.3 独立工具中心偏好

拟新增 `tool-center-v1.json`，放在 `HostDataRootPolicy` 解析的用户数据目录，与 `plugin-navigation-v1.json`、`layout-v2.json` 分开。

```json
{
  "schemaVersion": 1,
  "favoriteToolIds": ["myavalonia.host.tool.file-system-tree"],
  "recentToolIds": ["myavalonia.host.tool.plugin-status"],
  "categories": [
    { "id": "user:downloads", "displayName": "下载任务" }
  ],
  "toolCategoryAssignments": {},
  "lastKnownToolNames": {
    "myavalonia.host.tool.file-system-tree": "文件系统浏览器"
  }
}
```

示例自定义分类 ID 仅示意。实际新建时由 Host 生成稳定且唯一的 ID，不从显示名称派生；预置分类使用保留 ID，不允许用户覆盖“其他工具”的兜底身份。

- 收藏数组顺序是用户顺序；最近数组按最近成功访问顺序保存，不需要持久化业务时间线。
- 缺失或错误分类关联回退到其他工具；重复工具 ID 去重并保留首个有效顺序。
- 缺失插件的有效收藏/分类关联可保留，不自动执行。历史名称仅保存必要关联，不存插件对象、业务输入或图标几何缓存。
- 偏好读取失败回退空收藏、空最近及预置分类；不连带丢弃有效 Dock 布局。
- 保存失败保留内存操作，提示跨启动记忆未保存并写简短诊断；不撤销已完成的显隐。
- 沿用 Host 原子写入与损坏文件保留方式。格式版本未知时不静默覆盖原文件。
- 窗口当次搜索、选择、滚动位置在窗口存续期保持；首版不要求跨启动恢复这些临时状态。

## 8. 架构职责、所有权与图标复用

### 8.1 职责划分

下列新增名称为建议，实施时可按实际职责调整；不要求为每一行新增接口。

| 协作者 | 职责 | 边界 |
| --- | --- | --- |
| `WorkspaceCatalog` 的工具查询 | 输出已登记工具、真实来源与可用性 | 不创建插件模型，不持有 Window |
| `ToolWorkspaceReadModel` | 将 Workspace 布局事实投影为纯数据状态 | 不写 Dock，不保存偏好 |
| 拟新增 `ToolCenterQuery` | 组合目录、状态、分类与偏好，产生确定性列表 | 不执行显隐，不暴露 Provider 或 Dock 类型 |
| 拟新增 `ToolCenterPreferencesStore` | 偏好读取、校验、原子保存 | 不修改插件清单和布局快照 |
| 拟新增 `ToolCenterViewModel` | 搜索、筛选、选择、反馈及命令意图 | 不遍历 Dock 树，不查全局容器 |
| `WorkspaceSession` / `ToolDockCoordinator` | 执行显示、定位、隐藏与批量提交 | 单一工作区状态所有者 |
| 拟新增 `ToolCenterWindowService` | Owner、非模态单窗口、激活、关闭与退订 | Runtime 拥有，不使用进程静态窗口 |
| 拟新增退役工具快照迁移函数/类型 | 对合法旧快照执行定向、幂等数据转换 | 不放宽普通未知贡献校验 |
| 既有 `HostIconCatalog` / Renderer / View | 解析和绘制 V6.1 图标 | 维持插件 Owner 校验与主题回退 |

### 8.2 SOLID 与复杂度控制

| 原则 | 本方案落实 |
| --- | --- |
| SRP | 目录、运行布局、用户偏好、窗口寿命和图标绘制各自按变化原因组织 |
| OCP | 新 Tool 通过已有登记进入中心，新增用户分类通过数据完成，不为每个业务插件加分支 |
| LSP | 旧二进制仍可登记和使用；对 `Prevent` 的有意行为变化明确记录并测试，不伪称保持原语义 |
| ISP | 不扩大插件必须实现的接口；UI 只消费需要的只读记录和窄命令入口 |
| DIP | 插件继续依赖 SDK；Host 通过现有组合根连接协作者，不引入服务定位器 |

目录项与运行状态以 ID 合并，一次刷新尽量只捕获一次 Dock 状态，避免每一行反复完整遍历。纯数据逻辑可以复用，V6 与 V7 不共用可变树节点、选择状态或业务 ViewModel。

### 8.3 刷新与释放

- 工具中心打开时获取最新快照，随后订阅布局和插件可用性变化，在 UI 线程合并刷新。
- Dock 内的关闭、拖动和自动隐藏变化都必须使列表状态及时更新；不以中心按钮的操作记录代替布局事实。
- 窗口关闭后解除所有订阅，释放窗口级 ViewModel 和图标控件；不释放 Tool 模型。
- Runtime 开始退出后拒绝新工具操作。已经提交的同步布局事务按原工作区边界完成，随后关闭中心。
- 状态回调不得在窗口关闭或 Runtime 释放后重新激活窗口；双 Runtime 测试覆盖引用泄漏。
- 操作错误使用本次调用结果展示，观察者刷新失败不能把成功的业务/布局提交伪装成从未发生。

### 8.4 图标和视觉

使用 Tool 的 `IconPath` 与真实来源构造现有图标请求。公共键、插件专属键、空图标和无效引用均遵守 V6.1 的解析、Owner 检查与默认回退，不重新建立另一份图标字典。

列表使用统一主题资源，状态同时以文字表达，不只依靠颜色。中心可以容纳说明和分类，但默认只突出搜索、主操作、收藏与状态；分类维护和低频动作放在明确的二级入口。

同一图形可以复用只读定义，各展示位置各自拥有控件。工具中心不预览或嵌入插件 Tool 的真实 View，避免重复父级与生命周期干扰。

## 9. 命令面板与显隐入口统一

“工具中心…”作为 Host 菜单命令自然进入既有命令发现链。按工具名称直接搜索需要额外的 Host 内部工具入口投影：当前命令面板只搜索菜单声明的 Command，不能假定所有 Tool 已经可搜。

建议在面板展示模型中显式区分“工作台命令”和“显示/定位 Tool”两类入口。Tool 项携带 `ToolTypeId`，执行时进入 Workspace 的同一打开用例；不要为每个工具伪造插件 Command 注册或放宽现有命令的发现许可。

- Tool 搜索结果标明类型和来源，避免与同名 Document 创建命令混淆。
- 工具中心、欢迎页、命令面板均复用宿主入口；显示/定位操作最终落到相同 Workspace 边界。
- 普通 Command 继续采用当前菜单发现、上下文路由与权限/可用性规则。
- 选中 Tool 后若插件已变为不可用，执行时拒绝并刷新；搜索快照不是执行授权。
- 面板打开 Tool 成功后按既有交互关闭，并聚焦目标；成功访问可更新同一最近使用记录。
