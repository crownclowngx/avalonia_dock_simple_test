# 让生成发生在明确的规则之内

## 要解决的问题

生成代码的速度提高以后，如何避免边界混乱、语义冲突和验证成本同步放大？

## 核心观点

通过领域模型、可执行原型和真实反馈理解问题，把重要约束固化为接口、检查和验收，再扩大并行工作范围。Host 与插件的边界是这一方法的工程载体之一。

## 关键公式

原文中的概念关系式可排版为：

\[Q\approx\frac{P\times N\times A}{H}\]

| 变量 | 演示含义 | 取值约束 |
|---|---|---|
| $P$ | 单个执行者的相对生产能力 | 大于 0 |
| $N$ | 安全并行的执行者数量 | 正整数 |
| $A$ | 自动验收比例 | 0 到 1 |
| $H$ | 相对人类注意力需求 | 大于 0 |
| $Q$ | 无量纲的示例生产能力指数 | 用于比较参数变化 |

这是一条**研究假说中的粗略关系式**，不是经过校准的吞吐量预测公式。并行增加后可能同时改变 $A$ 和 $H$，不能据此推导实际收益会无限增长。

## 交互演示

沿“领域模型 → 可执行原型 → 现实反馈 → 规则形式化 → 平台固化 → 扩展”查看每阶段产物，再调整模型参数，观察约束之间的相互关系。

## 适用边界

理论原文讨论的是方法论与工作假说。示例曲线和指数不代表当前项目已经取得对应生产率；测试通过也不能自动证明领域模型正确。完整正文保留失败模式、证据需求和可检验指标。
