# 看清边界，理解协作

Host 是运行环境和工作区的所有者。Plugin SDK 表达双方约定，插件提供具体业务能力。理解架构的关键是：**谁声明、谁创建、谁持有、谁释放。**

## 从外到内的五层结构

| 部分 | 主要职责 | 不应承担的职责 |
|---|---|---|
| 桌面展示层 | 主窗口、菜单、主题、帮助与用户交互 | 插件私有业务规则 |
| 工作台命令 | 命令目录、状态判断、执行与快捷键投影 | 另建一套业务运行时 |
| 工作区与文档 | 创建会话、管理资源、保存与关闭 | 插件发现和程序集加载 |
| 插件运行基础 | 清单校验、独立 Provider、声明式贡献与生命周期 | 任意跨插件服务解析 |
| SDK 契约 | Document、Tool、服务端口和扩展声明 | Host 内部实现与 Dock 类型 |

## 所有权如何流动

插件从独立的服务集合配置私有依赖，声明 Document、Tool 等贡献。Host 完成注册校验后冻结目录，通过明确的激活入口创建对象。

- **Document**：一个实例拥有模型、View 和独立 DI Scope，关闭时按所有权回收。
- **Tool**：View 由工作区管理；单例模型由所属 Provider 管理。
- **WorkspaceSession**：拥有工作区状态与退出释放；`HostDockFactory` 适配 Dock 框架。
- **文件保存**：捕获修订快照，原子写入成功后确认对应修订，避免并发编辑被误标为已保存。
- **帮助中心**：Host 内建的阅读功能，由桌面层管理独立窗口；不参与 Document 和 Dock 布局持久化。

## 用户命令与后台工作

菜单、快捷键和命令面板共用 Workbench Command 的目录与执行路径。Workflow Action 则表达可编排的业务能力，拥有自身授权和运行资源规则。两者服务不同的调用场景。
