# Host 设计方法与取舍

> 用途：指导当前 Host 内部维护。状态：当前；核对日期：2026-09-16。事实源：[内部架构](architecture.md)、[兼容约束](../reference/compatibility-contracts.md)及对应实现。

## 从行为约束开始

先区分内部重构、外部契约变更和新功能。内部类名、文件组织和协作者可以调整；稳定身份、public API、严格 JSON、取消与释放、工具显隐和诊断边界必须由测试保护。

当前只支持严格 manifest、显式贡献和独立插件 Provider。Document 采用独立 Scope、互斥激活与修订保存；Layout 生产读写 schema 3，首次升级时只读转换 V2，并只对明确退役的内置 Tool 做定向清理。Document V1、Layout V1 与旧策略发现不回流到生产路径。

## 按变化原因分配职责

| 边界 | 选择与理由 |
| --- | --- |
| HostRuntime / 启动关闭协作者 | 唯一组合根及资源所有权；失败回滚只处理实际创建对象，不提供全局服务定位器 |
| Plugin Registry / 生命周期状态 | 声明冻结后不可变；可用性和运行状态另有所有者，避免登记事实被运行期副作用污染 |
| 私有 Provider / Host Port | 每插件从空服务集合建立容器；只通过窄端口共享能力，用所有权替代覆盖 Host 描述符再回滚 |
| WorkspaceSession / HostDockFactory | Session 拥有工作区与实例；Factory 只适配 Dock 的协议与回调 |
| Document / Tool Adapter | Document 拥有独立 Scope Lease；Tool 只是 singleton 的投影，隐藏不释放业务模型 |
| Coordinator / Serializer / Store | 用例顺序、严格格式和文件事务分别维护；失败不发布半成品状态 |
| Catalog / Context / State / Executor | Command 展示和执行共用一条路径，避免菜单、快捷键、面板分别维护业务规则 |
| Query / ViewModel / Window Service | 查询只投影元数据，ViewModel 管交互状态，窗口服务管 Owner、复用与退订 |

接口放在真实替换、测试或跨模块边界；内部纯函数和稳定协作者可以是具体类型。不会因追求接口数量建立通用仓储、事件总线、策略管线或窗口框架。

## 原子发布与显式寿命

Document 先创建 Scope、初始化模型、构造并绑定 View，再一次发布到 Workspace。失败时由持有者汇入同一个释放入口，避免留下可见但未完成的标签。只有主文件原子提交后才能接受保存修订；后续确认或备份失败应报告“已保存但有警告”。

取消请求不等于工作已经结束。关闭先拒绝新工作并排空在途操作；只有实际任务、取消通知及所需 Shutdown 达到安全终态才释放依赖。超时保留对象图是保守故障政策，不能通过后台迟到成功自动改变已作出的保留决定。

单文件事务采用同目录临时写入与原子替换，不扩展为跨文件事务框架。坏文件恢复保留原件，用户拒绝恢复不改变磁盘；磁盘 schema、插件内容 schema 与发布版本分开管理。

## 展示与搜索

文件系统路径先规范化与分类，再检查存在性，最后提交展示状态；因此语法测试不需访问真实磁盘，UNC 测试不需访问网络。

功能中心、工具中心和命令面板读取同一份冻结贡献与可用性事实；搜索不创建插件 View 或调用业务。活动页面使用稳定实例身份，不能按标题路由。图标元数据与几何绘制分离，各展示位置拥有自己的控件。

理论中的注意力、活动分解和分类轴用于解释设计；新增元数据或产品能力必须有独立需求依据，不能因为理论提到就认定已经实现。

## 修改前的判断

1. 行为是否对插件、文件或用户可见？如是，先更新契约和受影响的验收范围。
2. 谁拥有对象、状态、取消与最终释放？失败时是否仍有唯一所有者？
3. 是否泄漏 Control、Dock、Provider 或插件私有 DTO？是否增加了第二个事实源？
4. 初始化、并发、保存、关闭和启动失败是否会发布半成品？
5. 需要单元、Headless、真实窗口还是外部业务验证？各自不能证明什么？

日常入口为[主仓 verify](../../../../docs/maintenance/verification.md)。覆盖率及真实窗口按实际任务和发布前提执行，结果记录到有日期的历史验收；当前指南不预填“全部通过”。未完成工作集中在[待办](../../../../docs/roadmap/README.md)。


## V11 窗口与布局取舍

SOLID 优先：Session 保持唯一业务所有权，Factory 适配框架，窗口协作者只管交互与展示；格式校验、树投影、文件存储、写入顺序和屏幕计算分别独立测试。使用具体协作者、短期关闭许可和一次转移检查点，不新增通用事件总线、全局服务定位器或插件 API。

原生 Float/FloatAll 与 HostWindow 保留框架协议；实际核查后补上原生取消保护和同模型窗口复用。布局只记工具，不承担文档会话恢复；缺插件的记录保留，业务 View/Scope 在移动和重置时复用。最终保存队列不捕获 Dispatcher，干净窗口可同步排空，其余关闭仍异步准备；这一调整保留既有原生关闭语义，日常保存仍后台执行。

接口只用于已有替换边界，新增具体类不为形式拆出单实现接口。详细协议集中在 [Layout V3](../../../../docs/reference/dock-layout-snapshot-v3.md)，实际开发证据与真实桌面待办分别记录。

### V11-P1：分割完成事实与停靠策略

`HostDockFactory.SplitToDock` 保存本次目标引用，保留基类通知和初始化顺序，仅在有效分割挂接后通过内部 `OnDockSplitCompleted` 交给 Session。通用 Docked 通知不拥有目标信息，不能用它推测全宽策略。Session 以主树对象引用确认窗口归属，Coordinator 仅处理主文档区和稳定全局目标；局部工具与浮窗沿用 Dock 结果。

这维持了 SRP 的框架、策略、所有权和保存分离，以及 DIP 的内部回调端口。目标按类型和拓扑分类，满足 OCP，不添加插件 ID 分支；ISP 不扩展窗口/插件 API；LSP 保留异常、取消、关闭及原实例协议。仅使用现有具体协作者，不增加事务框架。

临时容器必须仍挂在父列表且只剩一个有效子节点。先保存比例和 Active/Default 引用，再取出子节点、重查锚点、插入子节点，最后移除旧容器。原因是 Dock 的 `RemoveDockable(collapse:false)` 仍清理孤立分隔条；提前移除容器会使缓存索引和邻接结构失效。框架同方向分割漏初始化的新分隔条由 Factory 补 Owner，不在 Coordinator 重建整个树。中文代码注释与 [P1 记录](../../../../docs/archive/records/host-v11/p1-tool-split-fix.md) 说明边界及验证。

### V11-P2：一次按钮动作与可取消关闭

窗口适配层处理 ToolChrome 的 Click/Command 联动，Factory 按当前窗口内容识别最后一个 Tool，将关闭和隐藏接入原生窗口协议。能力和框架取消事件必须在窗口仍可保留时执行；短期许可避免 Closed 阶段重复询问，正常消费、拒绝、异常或移除后清除。真正隐藏及 DockableClosed 仍由基类完成，不能先移除窗口模型再尝试关闭。

这维持 SRP 的事件适配、工作区所有权、关闭范围保护与文件保存分离；OCP 按类型/拓扑而非业务 ID 分类；LSP 保留能力约束、取消及基类事件；ISP/DIP 继续使用原内部回调，不增加插件 API。只增加当前关闭所需的有限许可，不引入通用事务或第二份业务实例目录。窗口获准前保留位置，CloseWindow 批量清理后提交最终状态；详情见 [P2 记录](../../../../docs/archive/records/host-v11/p2-tool-window-close-fix.md)。
