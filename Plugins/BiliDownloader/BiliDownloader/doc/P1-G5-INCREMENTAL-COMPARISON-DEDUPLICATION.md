# P1-G5 增量检查与跨来源去重实现记录

> 完成日期：2026-08-07  
> 适用范围：BiliDownloader 可解析重复来源、Document V3 轻量基线、SQLite 任务身份与提交边界  
> 非目标：后台轮询、自动提交、自动删除、课程下载以及 G7 的实际编码/容器执行

## 1. 设计目标与职责边界

增量检查是一个由用户主动触发的只读预览命令。打开 Document、恢复来源和应用启动均不会调用 Provider；检查过程中不会写入 `download_tasks`，也不会启动 Coordinator。用户选择新增项后仍须经过统一预检、确认和 Coordinator 命令锁内复检。

职责拆分如下：

- `IContentSourceScanService`：分页、层级递归、游标防循环、快照一致性、解析和部分失败语义。
- `IContentComparisonPolicy`：只根据任务与成品事实产生 Downloaded、InProgress 或 New。
- `IIncrementalComparisonService`：组合远端快照、筛选、基线、SQLite 和文件事实；支持用内存快照重新分类而不联网。
- Document：保存来源、筛选、输出意图和最多 100 个边界键，不保存完整页面或任务历史。
- SQLite：保存跨 Document 的任务事实与输出身份。
- Coordinator：提交、最终去重、任务写入和启动的唯一命令入口。

## 2. 稳定身份

`MediaUnitKey` 使用 `mu1:{Aid}:{Cid}`。它不包含来源类型，因此同一媒体同时出现在收藏夹、UP 投稿、历史和订阅合集中时会聚合为一项。

`RenditionFingerprint` 使用 `rf1:{SHA-256}`，规范输入固定包含：

1. MediaUnitKey；
2. 视频质量 ID；
3. 音频质量 ID；
4. 编码偏好；
5. 输出容器；
6. 输出模式。

DocumentId、来源、标题、命名、目录和附加资源不进入指纹。同一媒体的不同画质或输出配置可以共存；同一输出版本不能因来源不同重复提交。

旧任务在 Aid/Cid 合法时只补齐媒体键。由于旧行缺少可信编码和容器，`rendition_fingerprint` 保持空值；它只作为“身份不完整候选”提示，并要求用户确认，不能静默阻止新任务。

## 3. 扫描与基线状态流

~~~text
用户点击检查更新
  -> 从保存的根来源递归枚举所有可访问容器
  -> 每个层级验证 token、页数、快照或首屏摘要
  -> 本地应用完整筛选规则并解析有效叶子
  -> 按 MediaUnitKey 聚合来源证据
  -> 查询 SQLite 与成品文件事实
  -> 生成五类预览（零任务写入）
  -> 完整成功：更新 Document 内存基线并标记已修改
  -> 取消/部分失败：保留部分预览，不判基线缺失 Invalid，不更新基线
~~~

Provider 的临时快照 token 只用于当前扫描一致性，不直接写入 Document。基线保存客户端生成的 `scan1:` 摘要、完成时间和确定性遍历中的前 100 个叶子键。层级来源检查整个根来源，不持久化当前面包屑；课程和直接链接不开放增量检查。

## 4. 分类语义

主状态优先级固定为：`Invalid > RuleExcluded > Downloaded > InProgress > New`。

| 状态 | 判定 |
| --- | --- |
| Invalid | 完整扫描确认边界项目消失、失效或无权访问 |
| RuleExcluded | 远端存在，但不满足筛选或当前媒体规则 |
| Downloaded | 同指纹完成任务的最终文件存在 |
| InProgress | 同指纹任务处于排队、等待登录、下载、暂停、中断或可恢复失败 |
| New | 没有可信同指纹占用；成品丢失的完成任务也回到 New 并提示 |

取消任务和不可恢复失败不占用输出身份。旧身份候选保持 New，并产生必须确认的警告。

## 5. 竞态关闭与迁移

预检先合并同批重复指纹，并把普通提交中已存在的可信同指纹项目标为跳过。增量提交携带检查时为 New 的指纹集合；若另一 Document 在检查后抢先提交，预检/Coordinator 返回 `StaleComparison`，整批零写入，Document 使用内存扫描快照重新读取 SQLite 并刷新分类。

SQLite 以可重入 `ALTER TABLE` 增加 `media_unit_key` 和 `rendition_fingerprint`，并建立两个非唯一索引。索引刻意不设唯一约束：旧数据可能不完整，成品丢失后也允许重新下载；真正的活动任务去重由单例 Coordinator 命令锁内复检保证。

G5 已冻结编码、容器和输出模式在指纹中的位置，但这些输出的实际执行属于 G7。当前预检明确阻止非兼容 MP4 音视频组合，避免任务快照与真实文件不一致。

## 6. 自动化与安全证据

- 身份格式、字段敏感性和无关字段排除。
- 平面/层级扫描、重复游标、取消、部分结果、跨来源聚合和边界基线。
- 五类状态、活动状态集合、成品缺失、旧任务候选与来源优先级。
- SQLite 新库、旧表迁移、索引、身份往返和定向查询。
- 同批去重、不同画质共存、StaleComparison 与零部分写入。
- ViewModel 默认仅选择 New、课程禁用、完整扫描写回基线和无网络重新分类。
- 检查更新不调用任务插入、Coordinator 或下载执行器；Document、SQLite 和日志不保存游标、Cookie 或签名 URL。
