# BiliDownloader 代码结构与设计导读

这组文档面向第一次阅读 `BiliDownloader` 插件代码的人。它不逐行解释实现，而是回答以下问题：

- 插件怎样被宿主发现、装配、初始化和关闭？
- 一条 URL 怎样变成可选择的视频集合？
- 点击“下载”以后，为什么还要经过预检、复检和路径预留？
- DASH 地址如何选择，音视频如何下载、校验、合并并安全发布？
- 暂停、续传、失败、重启和异常退出分别怎样处理？
- 字幕、弹幕、封面、登录凭据和文档保存如何接入主链路？
- 代码使用了哪些设计模式，如何体现 SOLID，又有哪些现实取舍？
- 全局与单任务限速怎样在不破坏断点和并发控制的前提下组合？

> 文档基于当前仓库代码编写。类名、职责和流程均以 `BiliDownloader` 项目内的实现为准；图中的方法名用于定位职责，不代表完整 API 清单。

## 先记住四个边界

| 边界 | 入口 | 输出 | 不负责 |
|---|---|---|---|
| 内容解析边界 | URL 或内容源描述符 | `BiliVideoCollection` / `VideoParseResult` | 创建下载任务 |
| 提交边界 | `DownloadSubmission` | 预检报告、持久化任务 | 下载媒体字节 |
| 调度边界 | SQLite 中的 `Ready` 任务 | 状态迁移与执行授权 | DASH/文件的具体实现 |
| 执行边界 | `DownloadTaskRecord` | 已发布媒体与附加资源摘要 | UI 状态和文档保存 |
| 带宽边界 | 主媒体读取量子与 taskId | 异步读取许可 | HTTP/文件流、API 与附加资源 |

这四条边界是理解插件的捷径：解析只生产“可选内容”，提交只生产“任务事实”，调度只决定“何时执行”，执行器才真正访问网络和文件系统。

## 术语

| 术语 | 含义 |
|---|---|
| Document | 一个独立的下载计划编辑页；多个 Document 可共享同一个调度器和任务库。 |
| Tool | 全局调度工具，展示和控制持久化任务。 |
| Provider | 某一种内容来源的策略，例如直接链接、收藏夹、稍后再看。 |
| Descriptor | 已规范化的来源身份，不包含 Cookie、签名 URL 或临时游标。 |
| Media unit | 用 `aid + cid` 表示的实际媒体单元。 |
| Rendition | 媒体单元与画质、编码、容器、输出模式等组合后的具体输出版本。 |
| Preflight | 创建任务前的登录、依赖、媒体、目录、空间和冲突检查。 |
| Staging | 与最终输出同目录的暂存文件；验证成功后再移动成正式文件。 |
| Extras | 主媒体之外的字幕、弹幕和封面。 |
| Bandwidth limit | 主媒体网络读取前的许可；0 不限速，全局额度由任务公平共享。 |
