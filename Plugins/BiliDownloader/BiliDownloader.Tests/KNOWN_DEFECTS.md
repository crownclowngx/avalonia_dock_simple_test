# 测试过程中确认的缺陷修复记录

以下缺陷已于 2026-07-30 修复。对应回归测试属于默认 `BiliDownloader.Tests` 测试集，不访问真实 Bilibili 网络或真实 ffmpeg。

## 1. 活动队列期间新 Ready 任务不会立即进入调度：已修复

- 队列处理循环现在同时等待活动任务完成与有界唤醒通道。
- 提交、恢复、手动启动和并发数变化都会唤醒循环；活动任务按 `TaskId` 去重。
- 调度器按当前并发上限填充空闲槽，不再在运行期间替换 `SemaphoreSlim`。
- 回归覆盖“阻塞任务 + 恢复任务立即占用第二槽”。

## 2. 新增完整性字段没有在 InsertBatchAsync 中写入：已修复

- 新建表、旧表迁移和批量插入已统一覆盖任务模型全部字段。
- 完整性、完成结果和失败事实使用针对性的原子更新语句。
- 所有任务变更同步更新 `last_updated_at`；无法推断的历史事实保持默认/未知值。
- 回归覆盖全字段往返、替换写入、完整性、完成和失败事实更新。

## 3. 分块下载未验证 Content-Range 与实际块长度：已修复

- 每个 `206` 响应校验区间起止、总长度、声明长度和实际读取长度。
- 错误尝试回滚到请求前长度，备用 CDN 不会继承未验证数据。
- 合并前验证所有 chunk，并通过临时文件验证总长度后原子替换最终文件。
- 回归覆盖错误起点、短响应、总长度变化、合法续传和不生成最终文件。

## 4. 静态 ffmpeg 与直接 HttpClient 限制主链路隔离：已修复

- `FfmpegService` 已实现实例级 `IFfmpegService`，进程创建、HTTP 客户端和下载运行时均可注入。
- 封面处理器与媒体下载器不再直接创建 `HttpClient`。
- 回归覆盖 ffmpeg 参数、取消终止与输出清理、HTTPS 封面，以及下载到合并的完整离线主链路。
