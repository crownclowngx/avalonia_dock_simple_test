## 1. 文档目的

本文用于回答以下问题：

- MySmallTools 的视频加密、解密、播放器和媒体库接下来按照什么顺序建设。
- 当前代码已经具备哪些能力，哪些能力仍只能视为技术基线。
- 各功能组之间有什么依赖关系，以及何时才能进入下一阶段。
- P0、P1、P2 分别交付什么，并通过什么标准判定完成。
- 在冻结 SECVID03 格式、密码不落盘和 Document 独立生命周期的前提下，如何继续扩展产品能力。

本文描述总体路线、阶段边界和验收口径，不替代每个功能组开发前的详细设计。涉及格式、状态机、存储结构、平台接口或 UI 交互的功能组，在进入开发前仍需单独形成可评审的实施计划。

## 2. 当前项目基线

### 2.1 已经具备的能力

当前安全视频子系统不是从零开始，已经形成四条可操作链路：

- **单文件加密**：将普通视频流式写为 SECVID03，显示进度，使用同目录 `.partial-*` 临时文件并在完整刷新后提交正式文件。
- **批量解密**：检查多个 SECVID03 文件，顺序导出明文，隔离单项失败，净化输出文件名并避免静默覆盖。
- **单文件播放**：通过可随机定位的按需解密流向 LibVLC 提供原视频视图，不生成完整明文临时视频。
- **文件夹媒体库播放**：扫描当前目录的 `.secvid` 文件，读取公开标题和描述，支持搜索、选择和同页切换播放。

已有关键技术能力包括：

- SECVID03 使用 PBKDF2-SHA256 派生 256 位密钥，以 AES-256-GCM 认证固定头和 1 MiB 视频块。
- 固定头、原视频前缀和视频块受到密码学完整性保护；公开标题、描述和原始文件名明确视为不可信公开信息。
- `SeekableEncryptedVideoStream` 支持顺序读取与随机 Seek，并使用有限 LRU 明文块缓存控制内存占用。
- 加密和解密都采用事务式文件提交；失败、取消和关闭 Document 时进入半成品清理路径。
- 每个 Dock Document 使用独立 DI Scope，不共享任务状态、密码、播放位置或原生播放器实例。
- `LibVlcRuntime` 从插件私有 Windows x64 目录初始化 LibVLC，不回退到工作目录、`PATH` 或系统 VLC。
- Dock 销毁并重建原生视频表面后，现有恢复策略能够恢复播放位置以及播放或暂停状态。
- 解密队列模型、公开信息和日志不持久化密码。

### 2.2 当前工程状态

- `MySmallTools` 和 `MySmallTools.Tests` 以 .NET 9、Windows x64 为当前运行基线。
- `MySmallTools.Tests` 当前有 34 项测试，覆盖格式边界、加解密往返、篡改拒绝、资源释放、Document 取消、视频表面恢复和媒体库扫描。
- `MyAvaloniaManagement.PluginTests` 当前有 15 项测试，覆盖插件模块接入、Document Scope 隔离和原生目录扫描约束。
- 2026-07-23 基线验证中，两组测试全部通过；宿主插件测试构建时存在其他插件的历史警告，但本路线图不得新增 MySmallTools 警告。
- 当前自动化测试主要使用合成字节验证容器和流行为，尚未形成真实 MP4/WebM、真实 LibVLC 解码和真实 Dock 高频切换的集成回归基线。

### 2.3 需要优先解决的问题

1. 缺少真实媒体文件的加密、解密、解析、播放和跨块 Seek 集成测试。
2. SECVID03 已有较完整实现，但缺少独立威胁模型、固定测试向量、畸形结构测试和系统化安全评审记录。
3. 加密仍以单文件为主；解密虽支持队列，但加解密的预检、失败分类、取消、重试和磁盘错误表达尚未统一。
4. 播放器目前只有播放、暂停、停止、进度和音量等基础控制，缺少全屏、倍速、快捷键、音轨、字幕轨和连续播放。
5. 媒体库只扫描当前目录，没有递归、排序、增量刷新、目录监听、播放历史和千文件规模验收。
6. Windows x64 和 HWND 约束仍直接出现在运行时与视频表面实现中，业务层缺少清晰的平台能力边界。
7. LibVLC 缺失、原生目录不完整、媒体解析失败和加密内容认证失败仍需要更统一、可行动的诊断信息。
8. 代码和文档仍残留 SECVID02 提示以及旧 AES-CTR/Header 辅助实现；当前没有任何 SECVID02 存量文件，不再为其保留兼容或迁移能力。
9. `GetDetailedMetadata()` 等未实现入口和未使用的媒体元数据辅助代码会模糊真实产品边界，需要在扩展功能前清理或正式接入。

## 3. 总体实施原则

后续开发必须遵守以下顺序和边界：

1. **先验证安全与可靠性，再扩展功能**：P0 不增加大范围播放器功能，先把真实媒体、错误路径、资源释放和部署诊断变成可回归事实。
2. **SECVID03 格式冻结**：现有磁盘布局、KDF、分块、nonce 和 AAD 规则不在普通迭代中修改。若发现必须破坏兼容的安全问题，另行设计新魔数和专项计划。
3. **不支持 SECVID02**：不实现直接播放、批量迁移或兼容读取；P0 清理相关提示、旧格式辅助代码和迁移描述。
4. **密码永不落盘**：密码只存在于当前 Document 和同步调用链中，不进入任务模型、播放历史、设置、日志、诊断包或导出结果。
5. **Document 拥有任务生命周期**：不引入全局加解密 Coordinator 或持久化任务中心。关闭加密或解密 Document 时必须取消活动任务并清理当前半成品。
6. **任务提交必须是事务式的**：所有输出先写唯一 partial，验证、刷新和关闭成功后才以不覆盖方式提交正式文件。
7. **公开信息始终不可信**：公开标题、描述和原始文件名只用于展示与命名建议；路径生成、日志和 UI 都不能把它们当作经过认证的数据。
8. **播放不得生成完整明文副本**：倍速、全屏、连续播放、历史恢复等功能不得绕过按需认证解密流。
9. **用户操作优先于自动行为**：历史位置只用于加载后定位，不自动播放；Dock 自动恢复不得覆盖用户刚执行的播放、暂停、停止或 Seek。
10. **平台能力显式化**：P0/P1 继续支持 Windows x64；P2 只建立可替换接口和 Windows 实现，不把“已抽象”等同于“已支持 Linux”。
11. **完成后再宣称支持**：只有同时通过代码、异常路径、自动化测试、手工验收和文档更新的能力，才能从“规划”改为“已实现”。

## 5. P0：可靠与安全基线

P0 不追求更多播放功能，重点是把已有四条链路变成稳定、安全、可测试、可排障的产品基线。

### G0：基线、真实素材与遗留清理

**时间：W1，2026-07-27～2026-08-02**

主要工作：

- 建立版权清晰、体积可控的真实 MP4 和 WebM 测试素材，覆盖有声、无声、短时长和跨多个 SECVID03 块的样本。
- 记录素材来源、编码信息、SHA-256 和预期时长；自动化测试不能依赖开发机私人视频。
- 保留现有 34 项 MySmallTools 测试和 15 项宿主插件测试作为回归基线。
- 删除 SECVID02 产品提示、兼容分支和迁移描述，不提供直接播放或迁移工具。
- 删除不再被 SECVID03 链路使用的 AES-CTR、旧 Header 辅助实现；清理或正式接入返回空值的媒体元数据入口。
- 建立“代码能力—测试—文档”对应表，避免 README 将规划能力描述为已实现。

退出条件：

- 测试仓库中有可复现的真实媒体资产说明和完整性校验。
- SECVID02、旧 AES-CTR 和旧内存解密方案不再出现在运行入口与用户文档中。
- 清理后现有容器、解密、媒体库、Document 生命周期和插件测试全部通过。
- MySmallTools 构建不新增警告。

### G1：SECVID03 格式与安全验证

**时间：W2～W3，2026-08-03～2026-08-16**

主要工作：

- 编写 SECVID03 威胁模型，明确保护内容、攻击者能力、公开信息边界、密码内存边界和不抵御的场景。
- 生成固定测试向量，记录输入字节、公开信息、密码、固定头字段、块边界和预期认证结果。
- 覆盖空文件、短文件、整块、尾块、跨块读取、最大合法长度、物理文件截断、保留字段非零和整数溢出。
- 覆盖错误密码、固定头、原视频前缀、密文和 Tag 的独立篡改，以及公开区 CRC 损坏和合法重写。
- 验证结构检查早于高成本 KDF，畸形长度不会导致超大分配、越界 Seek 或路径写入。
- 基准记录 600,000 次 PBKDF2 的打开时延和 1 MiB 分块读取开销，不在 SECVID03 内静默更改参数。

退出条件：

- 格式文档、实现常量和测试向量一致。
- 任何受认证区域的单字节篡改都会被拒绝，公开区修改不会被错误宣称为密码学认证。
- 畸形、截断和溢出输入只产生受控错误，不提交输出、不泄漏文件句柄。
- 安全评审没有遗留必须破坏 SECVID03 兼容的未决问题；若存在，则停止后续功能并另立格式升级计划。

### G2：加解密预检、错误与资源闭环

**时间：W4～W5，2026-08-17～2026-08-30**

主要工作：

- 为加密侧增加与现有解密服务对称的可替换接口，使预检、执行、进度和失败路径可在不写真实大文件时测试。
- 统一加密和解密的任务状态、进度、预检结果与失败代码，至少区分密码/认证、格式、输入、输出冲突、权限、磁盘、取消和未知错误。
- 在开始前检查输入存在、输入输出不同、输出目录可写、目标冲突和可用磁盘空间；警告与阻止项分别展示。
- 统一 current-item 取消、Document 关闭取消、失败重试和 partial 清理顺序。
- 输出路径始终由可信目录与净化名称组成，并在最终提交时再次使用不覆盖语义防止竞争。
- 验证密码不进入队列项目、异常文本、日志、公开信息或诊断对象。

退出条件：

- 权限不足、磁盘不足、输出竞争、输入截断、内容篡改和主动取消都有稳定失败代码与可行动提示。
- 错误密码在创建明文 partial 前失败；中途失败只删除当前半成品，不回滚之前已经成功的文件。
- 关闭任一加密或解密 Document 不影响其他 Document，但会有序取消自身任务并释放句柄。
- 输出文件不存在静默覆盖和目录穿越。

### G3：真实媒体播放与 Dock 稳定性

**时间：W6～W7，2026-08-31～2026-09-13**

主要工作：

- 使用真实 MP4/WebM 完成“加密—加载—解析—播放—Seek—解密还原”的集成回归。
- 覆盖播放、暂停、停止、拖动进度、跨块 Seek、接近结尾 Seek、媒体结束和解码错误。
- 覆盖重复打开与关闭、快速切换两个媒体、连续创建和关闭 Document，以及文件删除/改名后的错误路径。
- 高频切换 Dock 标签页并验证 HWND 重建、旧 vout 退出、位置恢复、播放/暂停恢复和过期请求拒绝。
- 把 `MediaInput.LastError` 中的认证或读取错误转为可行动的播放器错误，不用 LibVLC 通用错误掩盖根因。
- 验证播放器全过程不创建完整明文临时文件，缓存和派生密钥在释放时按当前设计清理。

退出条件：

- 真实视频能够稳定解析、播放和随机 Seek，解密后的字节与原文件一致。
- 连续 100 次打开、读取、切换和释放后没有残留文件锁、失控后台回调或持续增长的缓存。
- 快速 Dock 切换不会弹出独立视频窗口，不会让旧恢复覆盖用户新操作。
- 播放中遇到被篡改块时立即停止，并显示认证失败而不是普通“无法播放”。

### G4：P0 部署、验收与发布基线

**时间：W8，2026-09-14～2026-09-20**

主要工作：

- 增加 Windows x64、托管桥接程序集、`libvlc.dll`、`libvlccore.dll` 和插件目录的启动前自检。
- 对缺少运行时、架构不匹配、插件目录不完整和媒体解析失败提供实际检查路径与下一步操作。
- 验证插件扫描和依赖解析不会进入 `native`、`runtimes` 或 `libvlc` 原生目录。
- 执行大文件流式加密、解密和随机读取内存验证，确认内存不随文件总大小线性增长。
- 更新 README、格式文档、架构设计和接入排障文档，使产品宣称与实际代码一致。

P0 统一退出条件：

- 篡改或错误密码不能提交正式输出。
- 取消、失败和关闭 Document 后没有遗留 partial 或被占用文件。
- 真实媒体播放、跨块 Seek、Dock 恢复和重复资源释放验收通过。
- MySmallTools 相关自动化测试全部通过，构建不新增 MySmallTools 警告。
- Windows x64 部署失败时，用户能够看到明确原因和处理入口。

## 6. P1：批量、媒体库与播放器体验

P1 在不改变 SECVID03 格式和密码边界的前提下，均衡推进批量处理与播放器日常体验。

### G5：批量加密与统一队列交互

**时间：W9～W11，2026-09-21～2026-10-11**

主要工作：

- 加密器支持一次添加多个普通视频，默认严格顺序执行，避免多个大文件同时争用磁盘和 KDF/加密资源。
- 每个项目独立保存输入、建议输出、公开标题、公开描述、状态、进度和非敏感错误，不保存密码。
- 支持取消当前项、取消全部、失败后重试、移除等待项、跳过已成功项和清空已完成项。
- 批次开始前汇总可执行、冲突、警告和阻止数量；任何覆盖都必须由明确策略决定，默认不覆盖。
- 解密器与加密器统一队列状态和交互语义，但各自保持独立 Document 与服务。
- 队列和密码不持久化；关闭 Document 时取消活动项并放弃等待项，已经成功提交的成品保留。

退出条件：

- 100 个小文件的批次可以顺序执行、取消和重试，单项失败不阻断后续项目。
- 队列变更不会让旧进度更新到新任务或已关闭 Document。
- 批次内与磁盘上的重名都不会导致静默覆盖。
- 内存中的密码只由当前 Document 在调用时提供，不复制到项目模型。

### G6：播放器日常控制

**时间：W12～W14，2026-10-12～2026-11-01**

主要工作：

- 增加窗口内全屏进入/退出，保留 Esc 退出和 Dock 恢复语义，不创建未受控的独立 LibVLC 视频窗口。
- 增加 0.5、0.75、1.0、1.25、1.5 和 2.0 倍速，并在媒体切换时按非敏感设置恢复。
- 增加空格播放/暂停、左右方向键 Seek、上下方向键音量、Esc 退出全屏等快捷键，并避免与文本输入冲突。
- 展示并允许选择可用音轨和字幕轨；无轨道或切换失败时保持当前可播放状态。
- 为媒体库增加上一项、下一项和可关闭的连续播放；单文件播放器不虚构播放列表能力。
- 建立播放能力模型，由播放服务统一暴露倍速、全屏、轨道和连续播放状态，ViewModel 不直接操作平台句柄。

退出条件：

- 高级控制不绕过 `SeekableEncryptedVideoStream`，不创建明文副本。
- 全屏、倍速、轨道切换和连续播放与 Dock 切换恢复兼容。
- 用户主动操作会取消尚未完成的自动恢复，不发生状态反跳。
- 快捷键只在播放器作用域生效，不破坏密码、搜索和公开信息编辑。

### G7：媒体库、增量刷新与播放历史

**时间：W15～W18，2026-11-02～2026-11-29**

主要工作：

- 增加“仅当前目录/递归子目录”扫描选项，默认保持仅当前目录。
- 增加按文件名、公开标题、修改时间和上次播放时间排序，以及搜索和基础状态筛选。
- 使用目录变更监听和可取消的增量刷新处理新增、删除、改名和公开信息修改；事件风暴回退为节流后的完整重扫。
- 优化列表增量更新和虚拟化，建立 1,000 个 SECVID03 条目的扫描、搜索、排序和滚动验收。
- 增加本地播放历史/设置存储接口，保存最近目录、递归选项、排序、音量、倍速、侧栏状态和每个文件的播放位置。
- 文件再次加载后定位到历史位置但不自动播放；接近结尾的记录视为已看完并从头加载。
- 提供清除单项历史和清除全部历史入口；历史存储不包含密码、密钥、明文块、认证上下文或公开描述全文。
- 路径和位置允许以明文保存在当前用户数据目录，文档明确其隐私边界。

退出条件：

- 扫描可取消，旧目录的迟到结果不会写入新目录列表。
- 目录监听不会因临时文件、重复事件或快速重命名造成重复项目和 UI 风暴。
- 1,000 个条目时列表仍可搜索、排序、滚动和切换播放。
- 历史恢复只定位不自动播放；删除历史后不会从其他缓存重新出现。
- 对历史和设置文件进行敏感信息扫描时，不存在密码或派生密钥。

### G8：P1 集成验收

**时间：W19～W20，2026-11-30～2026-12-13**

主要工作：

- 执行百文件加密/解密队列、失败隔离、取消、重试和输出冲突测试。
- 执行千文件递归媒体库、目录监听、连续播放、历史位置和设置恢复测试。
- 同时打开多个加密器、解密器、单文件播放器和媒体库 Document，验证 Scope、密码、任务与播放器实例完全隔离。
- 执行全屏、倍速、轨道、快捷键与 Dock 高频切换的组合验收。
- 扫描设置、历史、日志和诊断对象中的敏感信息，并同步更新产品文档。

P1 统一退出条件：

- 批量任务单项失败不阻断后续任务，不存在未确认覆盖。
- 关闭 Document 会安全取消其任务，不影响其他 Document 或已提交成品。
- 媒体库扫描可取消，过期结果被拒绝，千文件规模仍可操作。
- 播放器高级控制与 Dock 视频表面恢复兼容。
- 播放历史和设置中不存在密码、派生密钥或明文视频内容。

### G9：平台能力与原生表面抽象

**时间：W21～W22，2026-12-14～2026-12-27**

- 抽象视频表面创建、绑定、丢失、重建和销毁，业务 ViewModel 不直接读写 Windows HWND。

- 将插件部署路径和运行时检查规则集中到平台实现，避免散落在播放器、View 和项目文件之外的业务代码中。
- 保留 Windows x64 作为唯一生产实现，测试使用假平台和假视频表面验证时序。

- 不支持的平台会在创建播放器前得到明确能力结果，而不是原生加载崩溃。

### G10：性能基线与脱敏诊断

**时间：W23～W24，2026-12-28～2027-01-10**

主要工作：

- 建立大文件流式加密、解密吞吐，随机 Seek 延迟，四块 LRU 缓存命中和内存峰值基线。
- 建立 100/1,000 文件媒体库扫描、搜索、排序、增量刷新和目录事件风暴基线。
- 建立重复播放器创建、媒体切换、Dock 重建和释放的句柄、后台任务和内存趋势检查。
- 提供脱敏诊断摘要：平台能力、托管与原生版本、实际运行时路径、容器结构摘要、最后播放错误和资源状态。
- 诊断输出默认移除密码、密钥、公开描述、用户目录细节和完整文件名；路径只保留必要的脱敏定位信息。

退出条件：

- 性能基线可重复运行并记录环境、素材、参数和结果。
- 大文件处理的内存占用不随视频总长度线性增长。
- 诊断信息能够区分平台、部署、格式、认证、I/O 和解码问题。
- 敏感信息扫描确认诊断输出不包含密码、密钥或明文视频数据。

- 按真实完成情况更新本路线图状态；未通过验收的能力继续标记为规划或部分完成。
- 重新评估是否进入独立 Linux 适配项目；不得仅凭接口存在就宣称支持 Linux。

P2 统一退出条件：

- 平台相关职责可以由接口替换，Windows 实现通过全部回归。
- 业务层不再直接依赖 Windows HWND 和固定原生部署细节。
- 性能与资源释放基线稳定，诊断输出可用于实际排障且默认脱敏。

## 8. 计划中的接口与数据边界

### 8.1 加解密任务接口

- 加密侧增加与 `IVideoDecryptionService` 对称的可测试服务接口。
- 加密和解密共用一致的任务状态、进度、预检严重级别和失败类别，但不强制合并为同一个执行服务。
- SECVID03 密钥派生、固定头认证和块认证继续保持内部实现，不作为插件公共扩展 API。
- 队列项目只保存路径、公开信息、状态、进度、输出和非敏感错误；密码由 Document 在执行调用时提供。
- 不新增全局 Coordinator、后台常驻队列或任务数据库。

### 8.2 播放能力接口

- 播放服务统一暴露播放状态、Seek、音量、倍速、全屏、音轨、字幕轨和媒体结束事件。
- ViewModel 只消费播放能力与平台能力，不直接操作 LibVLC 原生句柄。
- 单文件播放器与媒体库共用基础播放能力；上一项、下一项和连续播放只由拥有列表上下文的媒体库协调。

### 8.3 历史与设置接口

- 存储最近目录、递归选项、排序、侧栏状态、音量、倍速和播放位置。
- 文件身份至少结合规范化路径和可检测的文件变化信息，避免把同路径替换后的新文件直接当成旧媒体。
- 密码、密钥、明文块、认证上下文、公开描述全文和任务队列禁止写入历史。
- 支持删除单项、清空全部和处理损坏设置文件；损坏时回退默认值，不阻止播放器启动。

### 8.4 平台接口

- P2 增加 LibVLC 运行时定位与验证、视频表面适配和平台能力接口。
- Windows x64 是唯一生产实现；测试提供假运行时和假视频表面。
- Linux 原生视频表面、原生包部署和发行流程不属于本路线图交付范围。

## 13. 默认假设

- 仓库和插件名称以实际代码中的 `MySmallTools` 为准。
- SECVID03 是唯一容器格式并保持冻结；当前没有 SECVID02 存量数据，不提供兼容、迁移或直接播放。
- P0/P1 只面向 Windows x64；P2 只完成平台抽象和 Windows 实现，不交付 Linux 版本。
- 密码永不落盘，关闭加密或解密 Document 时安全取消自身任务。
- 播放历史允许以明文保存在当前用户数据目录，必须提供清除入口并明确隐私边界。
- 批量加密和解密默认顺序执行，不在本路线图中实现断点恢复、崩溃后任务恢复或后台常驻队列。
- 时间估算以一名全职开发者为基准，不包含法定假期、LibVLC/Avalonia 上游重大变化和路线图外插入需求。
- P0 结束后根据真实开发速度重新估算 P1/P2，产品安全边界和用户确认要求不随工期压缩而降低。
